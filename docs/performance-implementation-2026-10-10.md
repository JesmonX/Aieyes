# 性能优化实现与验收（2026-10-10）

本次实施覆盖 Tauri 桌面前端、macOS 原生前端和共享 Rust 核心。菜单栏动画保持不变；前台/后台服务器、历史和账户限额仍遵循用户设置的刷新间隔。列表继续滚动浏览，不引入分页。没有安装或替换正在运行的应用，也没有修改个人配置。

## 已实现的行为

- **服务器采样与界面**：`hosts.sample` 保留旧数组协议，并支持 `stream: true` 返回批次与逐台进度；使用会话标识和版本去重。同一采样的进度广播与 RPC 返回只应用一次。SSH 指标查询最多并发 3 台，按完成顺序显示，慢主机不再阻挡已完成主机。移除/暂停的主机不保留核心速率计算状态。
- **桌面渲染**：保留服务器卡片 DOM，更新数值；折叠时不创建设备明细，大于 80 项的设备列表按可视区加缓冲区复用节点。支持可变行高、连续滚动、设备过滤、键盘焦点和展开状态恢复；隐藏窗口推迟渲染。失败保留旧读数并显示本次错误。
- **macOS 渲染**：服务器页使用 `LazyVStack`、值比较卡片和按需展开的指标内容；分面板/详情记住主机与指标展开状态。没有修改菜单栏的脉冲/循环动画。
- **历史查询**：每日聚合按 provider/account/source 及共享 Codex home 来源范围缓存，模型与日期范围复用同一日数据。数据库触发器在事件、来源归属变化和价格重算后修订受影响日期；历史账户选择项由精确来源/账户计数维护，避免命中缓存后仍遍历全部历史。`dashboard.summary` 只组装今日摘要及实时限额/采样信息。
- **资源边界**：每个 Store 的序列化内存缓存最多 16 MiB，SQLite 日缓存 payload 总量最多 64 MiB，近似 LRU 淘汰。它们不是整个进程 RSS 或数据库文件体积上限。缓存写入不等待其他写事务，并恢复连接原有超时；缓存不可用时回退原始统计。价格重算在同一事务中每批读取 512 个事件，避免一次装载全部 payload。
- **查询调度**：统计使用独立核心通道；筛选变化合并 120ms，任一时刻只有一个概览查询执行，待查条件仅保留最新值。旧结果不会覆盖新筛选，失败保留此前成功快照。手动刷新立即入队。
- **远程历史**：协议 v2 通过 stdin 发送脚本和游标，远程无需安装服务。JSONL 按 offset、设备/inode、前缀及检查点指纹续传，保留未完成尾行；文件替换、截断和可检测重写触发重读。解析累计 Token 所需状态与事件、游标在一个事务中提交。传输中断保留已提交批次，下次恢复；同一来源跨进程互斥，远程来源最多并发 2 个。改绑主机使原游标失效，传输开始后的损坏帧明确报错。自动扫描跳过暂停的主机；手动指定来源或采样边界同步仍明确报错，不能把跳过当作同步成功。
- **传输上限**：NDJSON 每帧至多 1 MiB、接收队列 4 帧；统计投影约 768 KiB 分批，无统计内容的日志每约 8 MiB 推进检查点。单原始行超过 64 MiB、单统计记录过大或游标清单超过 16 MiB 时明确失败，保留已提交位置。只传统计字段。
- **Antigravity**：DB/WAL 指纹未变时跳过；变化后重新读取一致快照并去重，不对 SQLite 使用字节偏移。记录错误、传输失败或读取期间变化不提交成功指纹；`invalidRecords` 独立计数，不能因错误列表截断而放过无效采样边界。
- **定时与生命周期**：两端移除固定 500ms 任务扫描，按最近到期时间设置单次定时器。`quotas.schedule` 根据各账户最后尝试时间和独立间隔计算下次到期；窗口状态、设置、任务完成、唤醒/恢复会重新计算。保留可见读数老化和 5 秒会话读取/30 秒目录发现语义。更新等待新增查询通道；原生退出集中取消任务并关闭所有客户端。独立 Unix 核心及 Tauri 退出清理登记的 SSH/CLI 查询进程组；已安装唤醒服务和 OS 打开页面不登记为短期查询。

## 实测结果

环境：Intel i7-9700、32GB、macOS 26.7.1。核心为 release 构建；网页为 Chromium 151 合成 IPC；原生视图为 Swift debug 构建。测量期间系统存在其他负载，结果用于比较和定位，不是跨设备承诺。

### 历史查询

固定合成数据覆盖 365 天、8 个模型。10 万条分布于 10 个来源/账户，100 万条分布于 30 个来源/账户。完整 JSON-RPC 响应计时，每项 5 次，热缓存列为后 4 次中位数。后续日期范围已复用首次查询建立的日缓存。

| 场景 | 10 万条 | 100 万条 |
| --- | ---: | ---: |
| 今日首次建缓存 | 295ms | 4,586ms |
| 今日热缓存 | 14.3ms | 12.1ms |
| 30 天热缓存 | 16.8ms | 13.4ms |
| 365 天热缓存，含较大响应序列化 | 61.0ms | 50.6ms |
| 今日轻量摘要 | 1.94ms | 2.42ms |
| 指定来源 30 天热缓存 | 6.16ms | 5.60ms |

首次建缓存和首次新来源范围查询仍有明显耗时：100 万条的新来源范围约 4.7 秒。查询在独立通道执行，界面保留上一快照和进行中状态。表中不含旧数据库首次升级时的来源/账户计数回填，也不含首次原始日志解析；缓存不会消除这些成本。

另外用同一固定合成数据库调用保留的原始聚合函数与缓存函数，逐字段比较汇总、日序列、热力图、模型选项及定价缺口，结果相同。原始审计的私人统计副本已清空，未将空数据库测量当作原始 50,304/105,465 条记录的复测。

### 服务器界面

复用审计中的网页场景及相同重复渲染计时：

| 主机 × CPU 设备 | 原节点数 | 当前节点数 | 原重复渲染中位数 | 当前中位数 |
| --- | ---: | ---: | ---: | ---: |
| 3 × 16，折叠 | 1,004 | 622 | 14.3ms | 0.30ms |
| 10 × 64，折叠 | 5,364 | 1,679 | 47.4ms | 0.35ms |
| 30 × 256，折叠 | 44,564 | 4,699 | 205.4ms | 0.70ms |

当前重复调用主要复用已有节点，这个表不代表冷启动建卡耗时。独立测试验证 256 项 CPU 展开后仅挂载可视区域，滚动时回收节点；广播与返回重复时不重建卡片、不丢焦点，主机/明细展开状态跨页面保留。

原生合成服务器视图分别运行 10×64、30×256；每场景连续更新单台主机 30 次。更新到完成显示的中位数为 18.0ms / 16.9ms，包含每次主动等待约 16ms；最大值 77.5ms / 33.8ms。原生到期调度还验证了后台 10 秒、前台 2 秒切换，更新/价格重算期间暂停、恢复后只追赶一次，以及无账户时不轮询空限额。桌面端验证限额查询、配置保存结束后重新安排历史刷新。三次相同批次仅发布一次，后续 30 次不同版本各发布一次。保存并检查了真实 `NSHostingView` 内容截图，不是整个桌面合成性能或长期 GPU 测量。

### 远程历史

同一 42,139,017 字节合成 JSONL、10,002 条统计记录，本机直接执行生产 Python 投影脚本：

| 文件无变化的第二次读取 | 全量协议 | 增量协议 |
| --- | ---: | ---: |
| 耗时，含 Python 启动 | 630ms | 96ms |
| 返回字节 | 1,469,195 | 116 |
| 返回统计记录 | 10,002 | 0 |
| 日志正文读取字节 | 全量 | 0 |

增量协议仍有启动、目录遍历、stat 和少量指纹读取；`readBytes=0` 表示没有读取新增日志正文，不表示零文件系统 I/O。未进行真实远程网络性能测试。

### 60 分钟日缓存持续测试

100 万条合成库实际运行 3,600.0 秒，共 1,763 轮、3,526 次概览/摘要查询正常返回；每 2 秒轮换 1/30/365 天范围，每约 30 秒从外部连接修改一个事件，触发日缓存失效。累计记录 118 个资源采样点，进程正常退出。

| 指标 | 结果 |
| --- | ---: |
| 首次 / 末次采样 RSS | 31.1 / 61.7 MiB |
| 第 5–10 分钟 RSS 中位数 | 51.5 MiB |
| 第 20–30 分钟 RSS 中位数 | 57.9 MiB |
| 最后 20 分钟 RSS 范围 / 中位数 | 57.6–61.8 / 59.6 MiB |
| 最后 20 分钟 RSS 线性拟合斜率 | +0.124 MiB/分钟 |
| 采样到的核心子进程数 | 始终为 0 |
| 磁盘日缓存 payload | 1,000,319–1,000,339 字节 |

RSS 预热后增长放缓，但末段仍有小幅上行，不能宣称内存已经完全稳定或排除长期增长。序列化缓存容量上限不限制整个进程 RSS。原始结果为 `synthetic.json`，统计摘要为 `soak-summary.json`。

该运行在最终同步/调度边界修正前启动，验收对象是共享核心的日缓存组件；最终代码另外完成了上面的功能回归。它不是完整原生/Tauri 应用或 SSH 链路连续运行一小时的测试，不能据此推断全应用 CPU/GPU、耗电或跨平台稳定性。

- `TZ=America/Sao_Paulo cargo test -p aieyes-core --lib usage_cache`：午夜 DST 缺失场景及日缓存与原始聚合一致。
- `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml`：21 项通过，覆盖独立通道和共享事件、更新逻辑。
- `npm --prefix apps/desktop run test:ui`：15 个脚本全部通过，覆盖桌面和浮窗的交互回归及新增 `test-performance-ui.cjs`。
- `sh scripts/test-native.sh`、SwiftPM 构建：通过原生模型、查询隔离、错误恢复、配置和生命周期回归；主通道阻塞 20 秒时，配置与概览查询仍在 500ms 内返回。
