# 三端 UI 与控件评审及优化方案 · 2026-10-26

评审基线 `cef8541`（main，v0.1.60 之后）。范围是 Windows、Linux 的 Tauri 界面与原生外壳，以及 macOS 的 SwiftUI/AppKit 界面，重点看控件、视觉细节、平台惯例和三端一致性。官网、核心统计口径与 RPC 不在范围内。

**结论**：信息架构、令牌生成链路（`docs/ui-design-tokens.json` → CSS/Swift）和无障碍降级（强制颜色、减少动效与透明度、增强对比度）已经比较成熟，三端面板的内容和顺序基本一致。问题集中在五处：

1. **控件没有统一规格。** 总览页可见按钮有 9 种高度，页头三个相邻按钮分别高 28、32、24px；主次按钮区分弱；折叠指示有 4 种画法，菜单有 5 种实现，弹层有 4 种。
2. **平台惯例没有落到原生层。** Windows/Linux 没有单实例保护；Windows 托盘打不开紧凑面板；Windows 标题栏按钮不符合系统规格，也没有 Snap Layouts；macOS 菜单栏没有配置，"设置…"会打开空白窗口；Linux 的"跟随系统"主题会把 GTK 的深色偏好重置为关闭（可见效果待实机确认）。
3. **i18n 把显示文案当状态键。** 英文界面下服务器状态颜色全部变成警告色；运行时切换语言后会话阶段仍是中文；计数和金额没有本地化（"1 hosts"、"$128571.75"）。
4. **三端视觉规则不一致。** Linux 浅色卡片比窗口还暗，分类染色卡片上的次要文字只有 3.8:1；资源条阈值颜色在 Web 与 macOS 上规则不同；导航图标、单位、全局操作位置各不相同。
5. **样式层维护成本在上升。** CSS 靠追加覆盖，`style.css` 有 44 个选择器重复定义，存在失效选择器和未定义变量；38 个浏览器测试全部只跑 Chromium，Linux 实际使用的 WebKit 没有自动化覆盖。

建议分五个阶段推进：阶段 0 修复缺陷（2–3 天），阶段 1 统一控件规格并收敛组件（约 1.5 周），阶段 2 对齐平台惯例（约 2 周，三端可并行），阶段 3 治理设计系统与工程（约 1 周，之后持续），阶段 4 建立验证体系（与前三个阶段并行）。详见[第 6 节](#6-分阶段优化方案)。

## 1. 值得保留的设计

- **令牌单一来源。** `docs/ui-design-tokens.json` 同时生成 `tokens.css` 与 `DesignTokens.swift`，CI 会检查两者是否同步；图表色板与阶段色也走同样的生成流程。
- **无障碍降级完整。** Web 处理了 `forced-colors`、`prefers-reduced-motion/transparency/contrast`；macOS 在减少透明度和增强对比度下改用不透明底并加粗边框。截图中高对比度模式的边框与选中态都清晰。
- **面板三端对齐。** 450 宽面板的分段、筛选、额度卡、底栏顺序在三端一致（见 `web/win-panel-*.png` 与 `macos/workspace-panel-*.png`）。
- **原生层稳健。** 材质只在系统调用成功后才启用半透明；Windows 桌宠不抢焦点、不进任务栏，透明像素可点穿；托盘丢失时回退桌宠；Linux 激活窗口时使用 X 服务器时间戳。
- **交互防护细致。** 后台刷新在菜单或对话框打开时延后；草稿有丢弃确认；重复提交有防护；Windows 自绘单选框保留原生 `<select>` 作为数据源，并支持类型选择和键盘提交。
- **图表有替代形式。** 趋势图配有逐日表格，环形图配有图例列表，热力图支持漫游焦点并提供完整数据表，资源条暴露为进度条。

## 2. 优先处理的问题（P1）

级别定义：**P1** 指功能不可用、显示错误信息、无障碍阻断或严重违反平台惯例；**P2** 指明显的可用性或一致性问题；**P3** 指打磨项。

| ID | 平台 | 问题 | 位置 | 置信度 |
| --- | --- | --- | --- | --- |
| P1-01 | Win/Linux | 没有单实例保护 | `src-tauri/src/main.rs:364-367` | 核实 |
| P1-02 | Windows | 托盘打不开紧凑面板，键盘也无法进入面板 | `desktop.rs:1104-1121`、`:1757-1776`；`context_menu.rs:17-43` | 核实 |
| P1-03 | macOS | 菜单栏未配置，"设置…"打开空白窗口 | `AieyesApp.swift:7`、`:107-114` | 核实 |
| P1-04 | Win/Linux | 英文界面下服务器状态颜色错误 | `app.js:1024-1038`；`style.css:216-218,498,621` | 核实 + 截图 |
| P1-05 | Win/Linux | 面板中的"切换账户"操作无效 | `account-targets.js:42-46`；`floating.html` 脚本列表 | 核实 |
| P1-06 | Win/Linux | 提示气泡永久删除 `title`，收起的导航按钮失去可访问名称 | `tooltip.js:63-72`；`style.css:579` | 核实 |
| P1-07 | Win/Linux | 侧栏导航图标两两重复 | `index.html:11,13,15,16` | 核实 + 截图 |
| P1-08 | macOS | 设置页服务器行的开关与按钮重叠 | `SettingsView.swift:144-148,186-196` | 核实 + 截图 |

**P1-01 没有单实例保护。** Tauri 构建器只注册了 dialog、notification、updater 三个插件，没有互斥锁或单实例插件；数据库为 WAL 模式，第二个进程也能正常打开。用户关闭主窗口后，常会从开始菜单或启动器再次打开应用，这会启动一个完整的第二进程：两个桌宠叠在同一位置，两个托盘图标，提示音响两次，SSH 和额度轮询翻倍，同时并发写 `desktop.json`。
**建议**：最先注册 `tauri-plugin-single-instance`（保留 `session_hooks::run_if_requested()` 在它之前），回调里执行 `desktop::action(app, "open")`，把已有窗口带到前台。

**P1-02 Windows 托盘打不开紧凑面板。** 托盘设置了 `.show_menu_on_left_click(true)`，左键和右键弹出同一个菜单，只有双击才打开详情；而第二次点击会被用来关闭菜单，双击并不可靠。"打开面板"菜单项写在 `#[cfg(target_os = "linux")]` 块中，而外层函数本身是 `#[cfg(not(target_os = "linux"))]`，所以这项永远不会编译。托盘模式下桌宠隐藏，与 macOS 菜单栏弹出面板对应的紧凑面板因此无法打开。面板始终以 `SW_SHOWNOACTIVATE` 显示，键盘用户无法进入；在用户点击面板之前，Esc 和 Alt+F4 都不起作用。
**建议**：左键单击（抬起时）在托盘矩形旁切换面板，右键保留菜单；Windows 托盘菜单增加"打开面板"；从托盘或菜单打开时激活面板，失去激活时关闭，与系统浮出面板的行为一致。

**P1-03 macOS 菜单栏未配置。** 唯一的场景是 `SwiftUI.Settings { EmptyView() }`，没有 `.commands`。打开窗口后应用切换为常规应用，菜单栏随之出现：
- 用鼠标点"设置…"会打开一个空白的设置窗口；事件监视器只拦截了 ⌘, 快捷键。
- 没有"文件"菜单，⌘W 在主窗口和辅助窗口中都无效。
- "Aieyes 帮助"没有对应的帮助内容；"显示"菜单为空，⌘1–3 只存在于事件监视器中，菜单里看不到。

**建议**：用 `CommandGroup(replacing: .appSettings)` 调用 `model.openSettings`；增加"文件 ▸ 关闭窗口 ⌘W"和"显示"菜单（总览 ⌘1、用量分析 ⌘2、服务器 ⌘3、刷新 ⌘R）；把"配置向导"放进帮助菜单。

**P1-04 英文界面下服务器状态颜色错误。** `hostStatus()` 返回译文，`updateHostStatuses()` 把译文写进 `data-status`，而 CSS 只匹配中文值。英文下所有状态点都回落为琥珀警告色：健康主机看起来像警告，连接失败不显示红色；"数据已延迟"的描边消失，已暂停卡片也不再变灰（见 `web/win-light-en-servers.png`）。`app.js:202` 的统计用 `=== AieyesI18n.t('正常')` 比较，同样依赖译文。
**建议**：`data-status` 只写状态码（`ok|paused|failed|waiting|stale|partial`），文案单独翻译；CSS 和统计逻辑一律比较状态码。

**P1-05 面板中的"切换账户"无效。** 面板加载了 `account-targets.js`，展开的 Codex 额度卡会显示"切换账户"；但弹窗内各行按钮调用的 `window.AieyesCodexAuth.open(...)` 定义在 `codex-auth.js`，`floating.html` 没有加载该文件，点击时抛出 TypeError，没有任何反应。"重新扫描"依赖的 `account-scan.js` 在面板中同样没有加载。
**建议**：面板内的账户切换改为跳转主窗口的对应设置（与 `openSettings` 的做法一致），或者在面板中隐藏这一行。只检查"有处理函数"抓不到这个缺陷：按钮本身绑定了 `onclick`，异常发生在函数内部。测试应在面板中实际点击，断言主窗口打开并定位到目标账户，全程没有脚本异常。

**P1-06 提示气泡删除 `title` 后不再恢复。** `tooltip.js` 在第一次悬停或聚焦时把 `title` 移到 `data-hint` 并删除原属性，之后不再恢复。侧栏收起后，导航按钮的文字以 `display:none` 隐藏，`title` 是唯一的可访问名称；一旦被悬停或用 Tab 经过一次，这些按钮就变成没有名称的按钮。另外，切换语言时 `applyStatic` 只更新仍等于旧值的属性，已经被气泡接管的提示会一直停留在中文。展开的侧栏里，气泡内容与可见标签相同，屏幕阅读器会把名称和描述各读一遍，在截图中气泡还遮住了相邻的导航项。
**建议**：收起状态用视觉隐藏文本或 `aria-label` 提供名称；不再删除 `title`，改为在显示气泡时临时抑制原生提示；气泡文本与可见文字相同时不显示；焦点触发只响应 `:focus-visible`。

**P1-07 侧栏导航图标重复。** "总览"与"接入与账户"都用 `sources` 图标，"服务器"与"机器与采集"都用 `hosts` 图标。窗口宽度降到 640 时侧栏自动收起，只剩图标，这两组入口无法区分（见 `web/win-collapsed-overview.png`）。macOS 的七个入口使用了各不相同的 SF Symbols（`MainWindowView.swift:19-20`）。
**建议**：按 macOS 的语义补齐图标——总览用网格（`square.grid.2x2`），接入与账户用人像（`person.crop.circle`），服务器用机柜（`server.rack`），机器与采集用电脑（`desktopcomputer`）。图标名在 `icons.js` 中与 SF Symbols 对照，统一管理。

**P1-08 macOS 服务器行开关与按钮重叠。** 两列开关固定宽 112pt，内部的标签用 `fixedSize`，编辑按钮固定宽 78pt。中文截图中"Agent 采集"的开关已经贴住"监控设置"（`macos/full-multi/settings-servers-light.png`）；英文"Agent collection"会被压到按钮下面，鼠标点开关会点中按钮。
**建议**：去掉固定宽度，改用 `Grid` 按列对齐，或使用带标签的 `Toggle`；宽度不足时换到第二行。

## 4. 根因归纳

1. **以 macOS 几何为唯一参照。** 令牌按 macOS 的逻辑尺寸设定（24px 控件、浅灰卡片、`[取消] … [保存]`），Windows 与 Linux 直接沿用，于是 Windows 控件偏小、按钮顺序相反，Linux 表面不像 GNOME。macOS 一侧反过来又用自定义样式模仿 Web（14pt 按钮、四种固定强调色、底栏的语言和主题按钮），也偏离了原生习惯。三端应该共享的是语义（层级、颜色角色、间距比例），而不是像素。
2. **组件没有沉淀成单一实现。** 菜单、弹层、折叠、对话框外壳、提示和提示条都是逐个页面写的，键盘、焦点和关闭行为自然不一致；一处修复不会传到其他地方。
3. **i18n 在显示层兜底。** 源文案即中文键，再加上反向翻译和片段匹配，适合快速覆盖，但会把状态判断、复数、语序和格式化问题都推到运行时。
4. **验证只覆盖 Chromium 与像素矩阵。** 现有测试擅长发现布局回退，但看不到 WebKit 差异、可访问名称、播报频率和原生层的入口可达性。

### 5.2 按钮层级与对话框

| 层级 | 外观 | 规则 |
| --- | --- | --- |
| `primary` | 实心强调色，白字 | 每个对话框或视图最多一个；Enter 触发 |
| `secondary` | 现有默认按钮 | 一般操作 |
| `tinted` | 现有 `.primary` 的淡强调色 | 次要但需要突出的操作（如"添加账户"） |
| `subtle` | 透明，悬停出底 | 工具栏和行内操作 |

| `link` | 文字链接 | 跳转（"查看分析 ›"） |

对话框统一外壳：标题加关闭 ×；正文可滚动；底栏按钮右对齐，Windows 为 `[主按钮][取消]`，macOS/Linux 为 `[取消][主按钮]`。表单打开时聚焦第一个字段，破坏性确认聚焦"取消"。Esc 等同取消，有未保存改动时先确认。macOS 每个 sheet 都设置 `.cancelAction` 和 `.defaultAction`。

### 5.4 颜色语义

- **类别色只表示身份**（Provider、资源种类），用于卡片左侧色条、色点和图标，不用于大面积文字背景。
- **状态色只表示状态**（ok/warn/danger），用于数值文字、图标和描边。阈值不再改变条形颜色；存储类别色移离琥珀色相（例如改为棕灰或青灰）。
- **染色上限**：文字所在的表面染色不超过 8%；染色表面上的次要文字、强调文字和徽标都要达到 ≥4.5:1，由自动化检查保证。
- **阶段色**：在明度和色相上都拉开距离，并且总是配图形或文字。
- **macOS 强调色**：默认跟随系统。

### 5.5 文字、数字与长文本

- 最小字号 12px/pt，用于说明和图表刻度；10–11px 一律取消。
- 数字：Token 用紧凑格式（K/M/B，中文可以考虑"万/亿"作为可选项）；精确值和金额使用 `Intl.NumberFormat` / `FormatStyle`，带千分位。
- 单位：字节统一用 IEC（KiB、MiB、GiB、KiB/s）。
- 时间：语言决定文字，系统决定 12/24 小时；相对时间用 `Intl.RelativeTimeFormat`。
- 长文本：账户名、模型名、主机名限制 2 行，完整内容放在提示和可访问名称中；按钮文字不换行，宽度不足时截断并给出提示。

### 5.6 i18n 规则

1. 状态、筛选、比较一律使用代码值；译文只出现在渲染输出中。
2. 所有可见文字在渲染时调用 `t()`，模块级不缓存译文。
3. 不拼接句子片段，计数统一写成 `t("{0} 台主机", n)`；中期引入 `Intl.PluralRules`，词条支持 `one/other`。
4. 词条键按上下文区分，不复用"日""读取"这类短片段。
5. CI 检查：英文模式下扫描 DOM 中残留的汉字（排除用户数据）；静态扫描上述反模式。

### 5.7 CSS 架构

```css
@layer tokens, base, layout, components, platform, overrides;
```

- `tokens`：生成区和 Web 专用表面；`base`：元素重置；`components`：按 5.3 的组件拆分文件；`layout`：页面网格；`platform`：Windows/Linux 差异；`overrides`：辅助功能降级（强制颜色、减少动效等）。
- 每个选择器只在一处定义；平台差异只写在 `platform` 层。
- stylelint：`no-duplicate-selectors`、`declaration-block-no-duplicate-properties`；自定义规则检查字号和圆角是否来自令牌、引用的变量是否已定义。
