# Aieyes desktop / mac 全面 UI 复核与美化改革方案

评审日期：2026-10-06。基线：`26823c9`，desktop 配置版本 `0.1.12`。本报告对应当前源码，独立于同日较早的 [UI 改革方案](ui-reform-2026-10-06.md) 和 [实施记录](ui-reform-2026-10-06-implementation.md)。

**总体判断：产品已具备完整功能与基础视觉系统，下一轮应优先调整信息层级、保存语义、数字可读性与操作连续性。** 两端已有统一强调色、中性卡片、错误重试、筛选清除和刷新菜单。当前主要问题是：面板像缩小的详情页，复杂配置缺少明确的提交边界，局部状态容易被理解成全局状态，小尺寸下通过挤压数字维持布局。

本次只交付审计与改革方案，没有修改应用业务代码。

## 0. 范围、证据与结论使用方法

### 0.3 已解决项，不重复立项

当前代码已具备以下能力，应保留并回归：两端四项刷新菜单；结构化失败列表与逐项重试；筛选 chips 和清除全部；初始空态隐藏零值卡；mac 数据源 / 主机删除影响确认；mac 菜单栏 Token 独立于详情筛选；中性卡片与主题调色；desktop 按压反馈、键盘提示即时显示、热力图色块图例、设置快捷键；Windows 胶囊高对比主题分支；mac 主设置关闭 / 退出时的草稿保护。此前方案中“上述能力缺失”的描述不适用于当前版本。

## 1. 二者共有问题

### C01 · P1 · 面板和详情首屏没有稳定的信息优先级

- **证据：实测 + 视觉 + 源码。** desktop `app.js` 的 `renderAgentPanel/renderAgent`、mac `Views.swift` 的 `agentContent`，均先铺开会话、筛选、限额，再呈现今日概览。账户数、采样状态、异常条数共同决定核心指标位置。
- **影响：** 用户打开面板想判断“今天用了多少、当前账户还能用多久”，却经常先滚过多张限额卡。mac 旧有双账户采样截图中，720px 面板也未露出今日概览；desktop 五账户测量见上表。
- **改革：** 面板固定展示“会话摘要 → 当前 / 置顶账户两周期限额 → 今日两个主指标 → 缓存摘要”。其余账户以“查看全部 N 个账户”进入展开层。采样收为单行状态入口，只有需要用户处理时展开。详情页允许所有账户，但今日概要应位于限额长列表之前或同一首屏。
- **验收：** 450×540、5 个账户、存在后台采样时，无滚动可读今日 Token、API 等价成本和当前账户 5h/7d；其余账户仍可一步访问。

### C02 · P2 · 中性卡片已经统一，但边框仍抢占内容层级

- **证据：视觉 + 源码。** `tokens.css` 的 `--card-border`、`style.css` 末尾 `.card,.stat`，以及 `NeutralCard` 的无透明度 `strokeBorder(Palette.cardBorder)`，使普通卡、统计卡、会话卡都具有较显眼轮廓。
- **影响：** 首屏像由多个等权盒子组成；深色下长限额卡、统计卡和次级信息之间缺少主次，浅色中尤其容易看到“卡片框”而非数字。
- **改革：** 普通卡用低对比中性分隔；主要依靠间距、背景层次分组。只有可交互控件、键盘焦点、错误边界维持必要对比。去掉普通卡多余投影，面板 / 菜单 / 对话框保留层级阴影。
- **验收：** 正常主题下第一视觉焦点是数值和状态；增强对比主题仍保留强边框。降低装饰边框不应同时降低输入框与焦点对比。

### C03 · P1 · “数据时间 · 正常”仍可能让旧数据看起来是新的

- **证据：源码。** 两端 footer 均读取 `dashboard.generatedAt`；`crates/core/src/store.rs:562` 在每次查询 dashboard 时赋值 `now()`。切换筛选可更新生成时间，并不代表重新读取日志。服务器总状态使用各主机采样时间的最大值。
- **影响：** 一个刚完成的查询或一台刚更新的服务器，不能说明所有来源都新鲜。“正常”主要代表已记录的操作没有失败，也不包含全部会话、限额、过期状态。
- **改革：** 常驻摘要显示“记录同步于 … / N 个来源有延迟”；查询时间放诊断详情。服务器显示“N/N 台已更新”并保留每台时间。综合正常、部分失败、过期、未接入必须区分。
- **验收：** 停止同步后反复切筛选，最后同步时间不前进；一台服务器长期没有更新，另一台成功刷新后全局不能显示无条件正常。

### C04 · P1 · 一个筛选区域覆盖了不同数据口径，作用域不够直观

- **证据：源码。** 日期控制改变概览与趋势；今日概览的趋势仍为近 7 天；热力图始终为过去 365 天。限额属于当前账户状态，不随历史日期或模型变成“那一段历史限额”。来源过滤还可能仅影响账户资格，而非限额数值。
- **影响：** 用户选择“最近 30 天 / 某模型”后，容易把附近账户剩余百分比理解为相同范围的指标。
- **改革：** 视觉上分为“当前账户状态”和“用量分析”。账户、Agent 用于共同上下文；历史区明确显示日期、来源、模型的作用范围。今日＋近 7 天趋势可保留，但必须就地标注。
- **验收：** 切日期时限额旁仍明确显示“实时账户限额”；筛选模型后不暗示模型拥有独立的账户总额度。

### C05 · P2 · 空态没有充分区分“未接入、未同步、无匹配、确实为零”

- **证据：实测 + 源码。** 两端用当期、趋势、热力图任一存在记录来决定是否渲染统计区。完全无数据时隐藏时间范围入口。无匹配和有来源但尚未导入时使用接近的文案；限额专用来源也容易进入用量空态。
- **影响：** 用户不知道该扩大日期、清筛选、修连接，还是等待首次导入。已有历史但今天为零时，其实应正常显示今日零值，不能一律隐藏。
- **改革：** 定义四种状态模板，保留用于恢复的筛选和日期入口；无匹配提供“清除筛选 / 扩大时间范围”，未同步提供“同步记录”，未接入提供具体添加方式。仅限额来源显示其适用的限额能力。
- **验收：** 四个场景各有对应动作，错误状态不能伪装成空记录；正常零用量不会触发首次引导。

### C06 · P2 · “缓存数量（百分比）”把两个不同口径挤成一个值

- **证据：源码。** 两端缓存数量为 `cacheRead + cacheWrite`，百分比为缓存读取 / 总输入；UI 均直接放在“缓存”标签下。
- **影响：** 用户会自然认为括号是前方缓存总量的占比；有缓存写入时，这个理解不成立。
- **改革：** 常态显示“缓存读取”“缓存写入”，或“缓存 Token 30K”并另起一项“读取命中率 31.3%”。输入量明确使用“普通输入”或解释已归一化口径；完整公式放 tooltip / 说明，不占主卡。
- **验收：** 同时含读取和写入的样本能够从 UI 复核命中率；缓存写入为零时也不改变标签语义。

### C07 · P2 · 限额折叠只减少部分内容，且面板与详情共用折叠偏好

- **证据：源码。** desktop localStorage 与 mac `@AppStorage` 均使用 `quota.expanded.<account>`；折叠后仍展示多组条形、credits、已存在估值。agy 账户可能有多个模型组。
- **影响：** 用户在详情展开账户后，面板也可能变长；“折叠”不能保障面板稳定密度。
- **改革：** 共用账户顺序，分别存储 `panel` / `detail` 折叠状态。面板摘要只保留余额或主限额两行；估值结果变为小徽标，更多周期 / 模型组进入展开区。
- **验收：** 详情展开全部账户不会改变面板高度；账户排序仍跨窗口保持一致。

### C08 · P2 · 重置时间偏重绝对时间，缺少易读倒计时

- **证据：源码。** 两端限额主要显示格式化日期，以及到期后的“等待同步”；mac 的 TimelineView 也没有显示“还剩 X 小时”。折叠后时间隐藏。
- **影响：** 用户需要心算；折叠状态下难以判断何时恢复可用。
- **改革：** 主显示“2 小时 18 分后重置”，次级显示“明日 08:00”；折叠摘要保留最近重置时间。到零转“确认重置中”，向来源请求确认，禁止直接把额度画满。
- **验收：** 跨日、已过期、未知时间、系统时区切换均有明确文案；读数必须等来源确认后改变。

### C09 · P2 · 图表可看趋势，但难以完成比较与精确读数

- **证据：源码。** 模型颜色来自名称哈希，两端仅保证稳定色相，没有相邻色冲突处理；圆环图图例主要列绝对值；native 趋势没有选择 / 高亮 / 注释交互。desktop 有鼠标 title 读数，但没有统一选择模型的交互。
- **影响：** 多模型时颜色接近、图例很长；成本模式下难以找出主要贡献项。
- **改革：** 圆环改为“前 5 模型＋其他”可展开列表，显示绝对值与占比；按当前指标排序。趋势支持悬停 / 键盘定位日期、点击图例高亮或隐藏模型。保留表格等价数据入口。
- **验收：** 12 个模型、长模型名、Token / 成本切换时，模型身份稳定，排名和数值对应当前指标；不靠颜色单独传递信息。

### C10 · P2 · 热力图的时间定位与键盘读数不足

- **证据：实测 + 源码。** desktop 主要是带 title 的 span 网格，缺少可聚焦日期；mac 提供 `.help` 与 accessibilityLabel，但成本模式的 accessibilityLabel 仍使用 compact 数字，没有 USD 单位。两端没有清晰月份刻度；desktop 也缺星期刻度。
- **影响：** 一年数据无法快速定位“哪一月、哪一天”；鼠标提示不能替代键盘、读屏访问。
- **改革：** 增加月份及星期标尺；日期支持方向键移动、Enter 查看当天详情； tooltip 同时给日期、单位、数值。提供可读表格替代，避免让 365 个格子全部加入 Tab 顺序。
- **验收：** 无鼠标也能定位任意一天；成本与 Token 模式读屏单位准确；零用量格与最低非零等级可区分。

### C11 · P1 · 主设置与编辑器的未保存保护不完整

- **证据：实测 + 源码。** desktop 直接重绘设置；mac 主设置有 dirty guard，但 `SourceEditor/AccountEditor/HostEditor/PriceEditor/WakeEditor` 的取消或 Escape 可直接 dismiss，编辑中的本地值尚未进入主草稿。
- **影响：** “主设置有保存保护”不能保障用户在 sheet / 对话框内已经输入的内容。一次 Escape 可能丢掉路径、模型映射或长命令。
- **改革：** 为编辑器维护初始快照与本地草稿；切页优先保留草稿，仅在真正丢弃 / 关闭时提供“继续编辑 / 放弃”；空白或未变更编辑器仍直接关闭。保存失败保留值并定位问题字段。
- **验收：** 输入长前置命令后误按 Escape 可恢复；无改动时无需额外确认；主配置保存与局部草稿的边界可见。

### C12 · P2 · 账户管理被埋在来源编辑器中，共享影响难发现

- **证据：源码。** 两端数据源列表主要显示来源名和账户名；只有未关联 / 归档账户在独立列表里，正常关联账户的名称、限额开关、查询来源通过来源编辑器修改。
- **影响：** 用户想管理账户时，需先知道应编辑哪一个来源；一个账户关联多处设备时，修改影响不够直观。
- **改革：** 数据源页保留统一入口，但用“账户分组 → 来源子行”。账户行管理名称、额度查询及排序；来源行管理路径、主机和同步。关联已有账户时展示“共用 N 个来源”及影响摘要。
- **验收：** 从限额卡进入编辑账户不必猜来源；一个账户的设置修改不会看起来只对某条来源生效。

### C13 · P2 · 配置页的初始复杂度偏高

- **证据：视觉 + 源码。** 新建来源较早展示账户属性、CLI 路径、连接方式；SSH 页面同时承担认证、设备发现、采集组、细分项；价格页同时包含映射、缺价修复、价格目录。
- **影响：** 首次接入用户需要理解大量可选术语，熟练用户又要滚动寻找关键项。
- **改革：** 按任务渐进展开：来源先选服务和位置、再检测路径、最后可选账户；SSH 先连接成功，再选择监控指标；价格先显示待修复项，再进入完整目录。高级选项显示当前摘要而非全量展开。
- **验收：** 默认 Codex 本机接入只需确认来源与路径；默认 SSH 连接只需目标和认证，仍能完整访问原有高级能力。

### C14 · P2 · 估值结果和采样流程的主次关系不清

- **证据：视觉 + 源码。** 结果同时显示 5h 价值、7d 同期换算、7d 倍率估算、容量倍率、样本数、计算说明；“结束采样并计算”在已有实时估值时容易让人以为尚未计算。
- **影响：** 用户难以辨别直接测量与推算值，也难判断何时样本足够。
- **改革：** 主结果突出“本段 5h API 等价值”；两项 7d 推算降为次级且分别标明依据。增加“正在积累样本 / 可输出估值 / 需要确认 / 已结束”状态；结束按钮说明“结束并保存本段结果”。计算明细按需展开。
- **验收：** 用户能区分 5h 与 7d，也能知道关闭窗口后仍采样；样本不足时给剩余条件，不只显示横杠。

### C15 · P2 · 服务器页缺少适合多主机的比较模式

- **证据：视觉 + 源码。** 每台主机采用大卡＋圆环＋多级细项；GPU 多卡、多核 CPU 会继续扩展高度。实时百分比没有历史曲线。
- **影响：** 三台以上服务器时难以同时比较 CPU、内存、GPU；一台主机的细节挤掉其它主机。
- **改革：** 主列表统一一行主机摘要：状态、CPU、内存、GPU、最新采样时间；展开后再给圆环和设备细节。提供“全部 / 异常 / 已暂停”筛选，已暂停状态弱化旧读数。若新增短时曲线，必须先明确采样存储和时间范围。
- **验收：** 5 台服务器在一屏可比较主要指标；任意一台失败不移动其它主机排序或滚动位置。

### C16 · P2 · 定时唤醒的核心状态需要主动展开才能看到

- **证据：源码。** 下一次运行和历史结果在显式查询 `wakeups.status` 后才呈现。时间输入为逗号分隔字符串，时区主要通过说明文字传达。
- **影响：** 任务已部署并不等于“用户确认了下一次会在什么时间执行”；“保存草稿、更新部署、立即运行”并排时容易混淆。
- **改革：** 列表默认读状态，突出下一次执行、目标机器时区和最近结果。编辑器用可增删的时间行，显示目标时间及本地换算；主操作随状态变化为“部署 / 更新部署 / 查看运行结果”，其它动作放更多菜单。
- **验收：** 打开列表即可识别下次执行及未部署更改；编辑草稿不暗示已改变系统任务，立即运行成功后自动跟进结果。

### C17 · P2 · 全局反馈、业务异常与网络测试结果没有充分分层

- **证据：源码。** 全局 message、刷新失败列表、限额错误、会话 Attention、网络延迟标签来自不同状态源；网络测试成功只代表测试站点可达，不等同于所有账户可用。
- **影响：** 同一错误可能多处出现；“正常”与“会话状态待确认”同时出现时需要用户自己解释。用户还可能把“系统 73ms”当成服务器延迟。
- **改革：** 全局只显示综合健康摘要；账户 / 主机失败就地展示；可展开“连接诊断”说明测试对象、方式及测试时间。成功反馈短暂显示，持续错误保留明确关闭和恢复入口。
- **验收：** 每个错误有唯一主要处理位置；网络标签明确表示应用出站连接测试，和 SSH 采样状态区分。

### C18 · P2 · 字号、点击区域、读屏名称仍需按组件验收

- **证据：源码。** 两端主体已接近 15 / 14 的字号体系，但图表、底栏、徽标仍含 12–13px / pt；小图标按钮的实际点击区并非都统一。部分数据行只保留视觉结构。
- **改革：** 重要数字不以连续缩小字号换取塞入；默认鼠标图标按钮建议 32×32，紧凑按钮至少明确验证命中区和相邻间隔；所有“编辑 / 删除 / 重试”附具体对象名。Web 以 WCAG 2.2 AA 为验收参考，原生另走辅助技术检查。
- **验收：** 200% 内容缩放、长中文名、键盘遍历、读屏操作均可完成主流程；高对比、减少动态效果、减少透明度分支继续保留。24×24 CSS px 是 Web 目标尺寸基线且有例外，不把该数值直接当作所有原生控件的强制尺寸。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

### C19 · P1 · 设备发现结果没有和发起时的主机配置绑定

- **证据：源码。** mac `SettingsView.swift:HostEditor.discover` 复制 testingHost 后等待返回；desktop `app.js:bindHostSelectors` 复制 host 后发起请求。期间目标地址、端口、认证字段仍可编辑。desktop 校验编辑器是否仍打开，二者都没有比较返回时的主机配置是否仍匹配请求快照。
- **影响：** 请求 A 时把目标改成 B，A 的设备可能显示在 B 的表单下。
- **改革：** 设备发现绑定配置摘要与 requestID；目标、用户名、端口、认证方式变动立即让旧结果失效。只接收与当前快照匹配的结果，成功显示“从 B 读取，时间 …”。
- **验收：** 延迟请求 A、改为 B、等待 A 返回，界面不得把 A 的设备列成 B 的发现结果。该异步交互结论来自代码链路，未连接真实 SSH 主机复现。

## 2. desktop 专项问题（Windows / Linux）

### D01 · P1 · 统计卡响应式规则被后续样式覆盖

**位置：** `style.css:375` 的两列断点，随后被 `style.css:497` 的四列 `.stats` 规则覆盖；`.cache-card` 跨两列。**实测：** 840px 宽度仍四列，成本标题换行，缓存标签与数值拥挤；卡内溢出不会被“页面 scrollWidth 不超过窗口”检测发现。

**优化：** 把最终网格规则集中到同一组件；依据内容区域宽度，宽屏 `1:1:2`，中等宽度两个主指标并排＋整行缓存，窄屏单列。缓存使用明确垂直标签，不继承普通明细的横向 flex。**验收：** 840/1000/1120 下每个数字均完整，无异常逐字换行；逐元素检查溢出。参见[840px 实际截图](../.local/ui-audit-2026-10-06/desktop-stats-840.png)。

### D02 · P1 · 通用配置切换标签即丢失，更新检查的脏表单机制未覆盖普通导航

**位置：** `app.js:renderSettings`、导航 click；`updates.js:unsavedForms` 只保护安装更新。**实测：** 输入 987 后切换标签返回为 300。

**优化：** 用独立 draft 对象保留表单状态，按区显示“未保存”；成功保存后才替换基线。正常切页不弹确认，保留草稿；真正关闭或放弃才保护。**验收：** 标签切换、主导航切换、后台数据更新、窗口关闭、更新重启五条路径分别验证。

### D03 · P1 · “保存并重算”没有保存当前输入中的映射

**位置：** `app.js:renderSettings` 中 `mapping-form` 与 `#reprice`。前者提交 FormData，后者仅提交 `state.settings`。

**实测：** 填写 `unsaved-alias → provider/model`，不按“添加映射”而直接点“保存并重算”，结果 mapping 为 null，输入清空并报告成功。

**优化：** 将待添加映射纳入草稿；“保存并重算”先校验并提交全部价格页草稿，再重算。若产品决定要求先添加，则按钮改为“按已保存价格重算”，有待添加输入时明确阻止或引导。**验收：** 不能出现“成功提示＋用户可见输入未保存”；空半行、重复键覆盖、重算失败均保留编辑内容。

### D04 · P1 · 移除自动唤醒 / 删除草稿没有确认，且和普通操作同权

**位置：** `wakeups.js:html/action/bind`。**实测：** 点击“移除自动任务”直接调用 `wakeups.remove`；mac 同操作已有 `DangerConfirmation`。

**优化：** 危险动作移入更多菜单，确认展示任务名、目标机器和“后续自动唤醒停止，历史保留”；默认焦点取消。删除草稿可以撤销时优先提供撤销。**验收：** 取消不发 RPC，确认仅发一次；失败保留任务及原状态，成功原地反馈。

### D05 · P2 · 本机路径全靠手填

**位置：** `app.js:editItem` 的数据目录 / 密钥路径均为普通 field，没有原生选择入口；mac 本机来源已有 NSOpenPanel。

**优化：** 本机目录、文件增加“选择…”和路径存在性检测；远程路径保留文本并显示所在主机。CLI 路径与代理等高级字段默认折叠。**验收：** 首次添加来源无需手打隐藏目录；Windows 盘符、空格路径、远程路径不混淆。

### D06 · P2 · 左侧栏的面积与导航内容不成比例

**位置：** `style.css` `.shell/aside`；默认侧栏 214px，三项导航；700px 以下才切图标栏，而主窗最小宽度已为 840。

**影响：** 常用支持尺寸下很少获得紧凑模式，统计区被固定侧栏压缩。**优化：** 保留左侧导航，但支持用户收起至约 64–72px，较窄内容宽度自动建议紧凑；设置归到下部，版本与诊断可收起。**验收：** 840px 仍有清楚的图标名称提示，用户能主动展开；不靠降低字体容纳内容。

### D07 · P2 · 标题行操作分散，账户排序按钮落在中间

**位置：** `quotaSection` 直接在 `.section-head` 放标题、排序、刷新三个子元素，通用 `justify-content:space-between` 使它们分占左、中、右。

**优化：** 标题与数量一组，排序＋刷新放右侧 action group；列表页均沿用相同语法。**验收：** 450/840/1120 下操作组不分裂，排序不会像主内容的独立按钮。参见[概览截图](../.local/ui-audit-2026-10-06/desktop-overview-light.png)。

### D08 · P1 · 筛选请求失败时，控件与旧数据可能形成不一致状态

**位置：** `app.js:renderAgent/renderAgentPanel` 的 onchange 先改 state，再 `await loadDashboard()`，缺少该入口自己的 pending / catch；`loadDashboard()` 只有请求序号淘汰旧响应。

**影响：** 查询失败时新筛选保持选中，旧统计仍留在页面，用户无法判断是否已按新筛选计算。**优化：** 区分 requestedFilters 与 appliedFilters；旧结果上显示“正在更新 / 更新失败，仍显示上一结果”，失败可重试或恢复筛选。空态始终保留日期入口和就地同步按钮。**验收：** 模拟慢请求、失败、快速连续切换，页面明确显示已应用的数据口径；不会产生未处理 Promise 错误。

### D09 · P2 · 每日明细的视觉表格没有对应语义，小尺寸还会隐藏成本列

**位置：** `dailyTable` 使用 div/details；700px 断点把最后一列 `display:none`；当前原生最小窗为 840px，该隐藏路径主要涉及更小预览或未来内容缩放。

**优化：** 使用有列标题关系的数据表格或合适语义；窄宽度改成日期主行＋可展开字段，不直接丢掉成本维度。支持复制完整模型名与精确数值。**验收：** 键盘及读屏能对应日期、模型、Token、缓存率、成本；窄布局仍能访问全部字段。

### D10 · P1 · 5h 估值入口的主数字与 mac 取值不同

**位置：** desktop `quotaCard` 用 `latest.weeklyValue`；mac `QuotaCard` 使用 `fiveHourValue ?? weeklyValue`。核心 `estimates.rs:614` 生成 fiveHourValue，`:617` 将 weeklyValue 赋为 weeklyDirectValue。

**影响：** 同一“5h / 7d 估值”入口，两端可能显示 7d 同期换算与 5h 价值两种不同金额，且入口数字旁没有明确周期。

**补充实测：** 向 desktop 注入 `fiveHourValue=20, weeklyValue=100` 的合成记录，入口显示“5h / 7d 估值 $100.00 USD”；mac 对应路径从源码确认优先取 20。

**优化：** 两端统一显示“5h ≈ $20”；展开后列 7d 两种估算。旧整周采样明确标“7d 整周”。**验收：** 用 `fiveHourValue=20, weeklyDirectValue=100, weeklyValue=100` 的同一真实结构验证，两端入口均显示 5h $20，结果区 7d $100 各归其位。

### D11 · P2 · 点击任意提示文字就关闭整条通知

**位置：** `app.js:734` 为 `#message` 整块绑定 `notify('')`；样式使用 `cursor:pointer`。

**影响：** 用户点击、选择或准备复制错误文字时可能把提示关闭；错误仍在刷新状态里，但可见诊断消失。**优化：** 提示文字保持可选择；只由明确的“关闭”按钮消隐。批量错误提供“折叠详情”，而非随意清空。**验收：** 点击文字、复制多行错误不会关闭，键盘可聚焦关闭按钮。

### D12 · P2 · 估值动作进行中会锁住整个模态窗口

**位置：** `quotaAction` 禁用包括关闭按钮在内的所有 button，并阻止 cancel；启动采样包含同步远端来源等潜在长耗时动作。

**优化：** 提交期间禁用重复提交，但可收起到后台任务条；若操作不可取消，明确显示“后台处理中”，保留重新打开入口。采样管理、错误和进度独立于 dialog 生命周期。**验收：** 模拟慢 SSH 时仍可返回看服务器或概览，完成后结果能恢复，不重复创建采样。

### D13 · P2 · 已部署唤醒任务仍可编辑运行位置，跨端约束不一致

**位置：** `wakeups.js:edit` 的来源 select 始终可编辑；mac `WakeEditor` 对已部署任务 `.disabled(deployed)` 并解释需先移除部署。

**优化：** 若后端要求先移除旧部署，desktop 同样就地锁定并提供原因；若未来支持迁移，做明确“迁移部署”流程，展示旧、新目标。**验收：** 不允许用户填写完整表单后才因位置不可变被拒；两端操作与后端约束一致。

## 3. mac 专项问题（原生 macOS）

### M01 · P2 · 详情三等宽统计卡不适合三列缓存明细

**位置：** `Views.swift:agentContent/CacheSummaryCard`。详情采用三个等宽 GridItem，第三张卡内部再三等分，数值 `.lineLimit(1).minimumScaleFactor(0.8)`。

**位置：** `Views.swift:agentContent` 以 HStack 放两图，模型分布固定 340pt；`ModelChart` 圆环固定 132pt，图例剩余空间随之缩小。

**影响：** 760pt 窗口、多模型、长名称时两图同时争夺空间；和 desktop 在 1100px 以下改为单列的行为不同。**优化：** 使用基于可用宽度的 ViewThatFits / Layout；窄宽度趋势全行，模型分布放下一行；模型名允许完整查看、复制。**验收：** 七天及一年数据均有可读轴标签，长图例不会只留下大量省略号。

### M03 · P1 · 多账户估值窗口共享“额度 / credits”模式

**位置：** `EngineClient.swift:184` 的 `@Published creditEstimateMode`；`QuotaTools.swift:QuotaEstimateView` 绑定该全局值；`AieyesApp.swift:openEstimate` 又为不同账户保留不同窗口。

**判断：源码状态依赖确认，未执行真实多窗口鼠标复现。** 打开账户 A 的额度估值，再打开账户 B 的 credits 估值，会修改同一个模式；观察该 model 的其它 Codex 窗口也会改读另一组 records。

**优化：** mode 归属于估值窗口上下文，例如 `(accountKey, kind)`；窗口初始模式通过参数传入。全局只共享采样数据和运行状态。**验收：** 两个 Codex 账户分别显示不同口径，任一窗口切换不改变另一窗口标题、结果、按钮或表单选择。

### M04 · P2 · 筛选 chips 每项独占一行，放大了面板高度

**位置：** `Views.swift:activeFilters` 使用 VStack；“清除全部”放在账户 / 日期与来源 / 模型之间。

**视觉证据：** [450×540 筛选面板](../.local/ui-audit-2026-10-06/native-single/filtered-panel-small.png) 仅来源和模型两个筛选，就把今日卡片推到首屏外。

**优化：** chips 采用流式换行，最多两行＋“另有 N 项”；“清除全部”固定尾部。面板常态可显示“已筛选 2 项”摘要，点开编辑筛选。**验收：** 长名称不挤掉关闭按钮；五项筛选仍保持摘要高度可控，详情完整展示。

### M05 · P2 · 草稿中的启用开关与实际运行状态并置，缺少逐行待提交提示

**位置：** `SettingsView.sources/servers` 的 Toggle 绑定 `settingsDraft`，错误状态读取当前 dashboard；实际采集仍使用已保存的 settings。顶部只给整个窗口一个未保存提示。

**影响：** 用户把来源 / 主机开关关掉但未保存时，行上看起来已停用，后台采集仍按旧配置进行。这是草稿模型的正常行为，但当前逐行可见性不足。

**优化：** 修改过的行显示“待保存：停用”；实际状态独立标“当前仍运行”。保存成功后移除待提交标记。大范围修改可展开变更摘要。**验收：** 停用草稿、实际停止、保存失败三者可以直接区分；不要为了视觉一致擅自把草稿开关改为立即生效。

### M06 · P2 · mac 的两阶段保存已经有说明，但没有形成明确视觉层级

**位置：** `SettingsView` 顶部全局保存，编辑器“完成”，价格独立保存，WakeupsView 独立任务草稿；所有设置标签共用同一全局工具区。

**影响：** 用户可能对唤醒任务点完“保存草稿”后继续寻找顶部保存；对编辑器点“完成”后则可能误以为已生效。**优化：** 配置页顶部显示“应用配置 · 未保存 N 项”；sheet 按钮改成“应用到草稿”。价格、唤醒各自有作用域明确的保存栏，顶部不要暗示能保存这些独立事务。可提供“保存并验证”作为最后一步。

**验收：** 每个保存按钮都能从邻近文字判断保存对象和是否立即生效；有其它标签未保存内容时，仍有总草稿入口，不把它隐藏掉。

### M07 · P2 · Grouped Form 的字段值看起来像只读信息

**位置：** SourceEditor / HostEditor 的默认 TextField 与 grouped Form；[SSH 编辑器截图](../.local/ui-audit-2026-10-06/native-single/host-editor.png)、[远程来源截图](../.local/ui-audit-2026-10-06/native-single/remote-source.png)。

**影响：** 右对齐的 SSH 地址、名称、路径与静态说明形式接近；技术路径又缺少等宽文本、完整值查看和针对性校验。**优化：** 对路径、地址等使用有明确编辑边界的字段，焦点高亮；保留 Form 的标签对齐。较长路径采用中间省略＋选择 / 复制 / 展开编辑，不硬换成多行标签。

**验收：** 新用户能识别可编辑位置；鼠标与全键盘模式下，焦点、选中文字和错误字段均可辨。

### M08 · P2 · 原生设置标签和列表操作的辅助语义仍不完整

**位置：** SettingsView 标签是普通 Button 加 accessibilityValue；来源 / 主机启用开关都叫“启用”，移除按钮主要用 `.help`。

**影响：** 读屏时可能连续听到多个同名“启用 / 编辑”；普通按钮组也不自然表达“设置标签组”。这是需 VoiceOver 验收的语义风险，不能仅从截图判失败。

**优化：** 使用原生 TabView / 合适的选择器，或补选择状态和组语义；标签例：“启用训练服务器”“编辑个人 Codex 来源”“移除服务器 A”。使用系统焦点机制，并验证方向键切换和 Cmd+,。

**验收：** VoiceOver 不依赖视觉位置便能区分对象与当前标签；键盘可以完成新增、修改、保存、取消。

### M09 · P2 · “添加主机”入口只打开设置，不直接开始添加

**位置：** `Views.swift:serverContent` 的 plus 和 EmptyCard 只设置 `settingsTab="servers"` 并打开设置；首次 Agent 引导则会设置 `requestHostEditor=true`。

**影响：** 同样叫添加，用户还要在设置里再点一次添加；第一次使用时容易误以为按钮没有执行。

**优化：** 两个入口都复用请求 HostEditor 的路径，设置窗口作为承载层即可。**验收：** 从空服务器页点添加，一步看到新建主机表单；取消后回到合理来源位置。

### M10 · P2 · 唤醒成功反馈使用错误通道，旧状态可能留在新部署旁

**位置：** `WakeupsView.perform` 在 run 成功后设置 `error = "已启动一次唤醒…"`，该区域统一警告色；除 remove 外，其它部署、启停操作没有主动清理 statuses。

**影响：** 成功被画成警告；先查状态再停用后，旧的下次运行时间可能继续显示，直到手动查询。

**优化：** 分开 success / error；部署、启停、运行后更新对应任务状态，并对运行中的任务有限轮询。**验收：** 成功不使用失败色；停用后的“下次运行”立即变为“已暂停”，不能保留旧时间造成误解。

### M11 · P2 · 服务器收起后丢失 GPU 摘要，默认展开又太高

**位置：** `ServerCard` 默认 expanded=true；收起态 `compactMetric` 仅列 CPU 与内存，没有 GPU。`compact` 参数没有形成完整独立的面板摘要布局。

**影响：** GPU 训练主机在最需要紧凑展示时，核心指标消失。**优化：** 摘要按用户选定的监控指标显示；GPU 可以是“最高利用率 / 设备数”并支持切到指定卡。默认面板收起，详情可保持用户偏好。

**验收：** 只启用 GPU 的主机收起后仍有有意义的数值，不能变成只剩名称和状态的空行。

### M12 · P2 · 从服务器面板打开详情，页面上下文没有明确传递

**位置：** `RootView` 的 tab 是各实例独立 `@State`，默认 agent；`openDetail()` 没有传入当前页面。desktop `openDetail` 会传 `view.page`。

**影响：** 在服务器面板点打开详情，可能到 Agent 或详情窗口之前停留的页；共享过滤条件却不共享导航意图。**优化：** 打开详情时传入目标页面、账户 / 主机 ID、当前筛选；已有窗口保留合理滚动，定位目标对象。

**验收：** 从服务器 / 账户 / 估值入口进入详情，各自落到对应内容；不要通过把所有窗口 tab 改成一个全局值来强制互相跳页。

### M13 · P2 · mac 主窗工具区占用较大，未充分利用原生 toolbar

**位置：** `AieyesApp.swift` 创建原生标题栏；`RootView.header` 又在内容区放品牌、页面切换、刷新；SettingsView 同样使用内容区自绘标题与操作行。

**影响：** 小窗口中标题、工具区、提示条层层堆叠；系统窗口与应用内容像两个独立区域。**优化：** 详情窗口将页面切换和刷新整合到原生 toolbar；设置使用平台习惯的分类导航与明确保存状态。菜单栏面板仍保留自包含的紧凑 header。macOS 原生 toolbar 可以位于标题栏下或与标题栏整合。[Apple Toolbar 指南](https://developer.apple.com/design/human-interface-guidelines/toolbars)

**验收：** 760×480 详情的内容可见高度明显增加；窗口拖动、全屏、缩放、工具栏快捷键维持系统行为。

## 4. 整体 UI 美化改革方案

### 4.1 产品视觉方向

目标是**安静、清晰、适合长时间挂在桌面上的监控工具**。保留现有眼睛品牌图标与靛蓝强调色，把装饰集中于常驻入口和主操作；内容区以数字、名称、状态为主。

统一的内容规则：

1. 每个区域最多一个最突出的操作；刷新、排序、编辑属于次要动作。
2. 主指标与单位靠近，精确值和缩写值可以切换 / 复制；未知值、零值、过期值有不同表达。
3. 颜色只帮助识别，不独自决定状态。正常可保持中性，警告和错误只用在确实需要关注的地方。
4. 面板承担快速判断和轻操作；详情承担分析；设置承担配置；采样 / 部署承担有状态的长流程。
5. desktop 与 mac 共用信息结构、术语、数据口径和测试样本。材质、表单、菜单、窗口操作分别采用平台合适实现。

### 4.2 建议的视觉规范

以下为改版起点，颜色不是本轮已通过逐像素验证的最终值。

| 设计项 | 建议值 / 规则 | 相对当前的重点 |
| --- | --- | --- |
| 主强调色 | 继续使用浅色 `#5566D9`、深色 `#A3B3FF`，按平台映射 | 保留已建立的品牌识别 |
| 窗口背景 | 浅色候选 `#F7F8FB`，深色候选 `#151A23`；原生使用系统背景映射 | 降低全窗蓝紫 / 青色装饰渐变存在感 |
| 普通卡片 | 浅色候选 `#FFFFFF`，深色候选 `#202733`；mac 保留受控系统材质 | 由背景和留白分层，避免所有块同样厚重 |
| 装饰分隔线 | 浅色候选 `#DFE4ED`、深色候选 `#354052` | 只替换装饰线；控件边界、焦点、错误边界另设 token |
| 文字 | 主文字延续现有 ink；正文 15，辅助 13–14，说明至少易读且可放大 | 不把关键数字缩到辅助字号 |
| 数值 | 主窗 28–32，面板 24–28，次级数值 16–18，等宽数字 | 两端按实际字形光学调整，px 与 pt 不机械等同 |
| 标题 | 页标题 22，分区 16–18，卡内标签 13–14 | 避免每张卡都拥有同等强标题 |
| 间距 | 基础 4；控件内部 8–12；卡内 14–16；区域间 20–24 | 收敛零散 padding，面板不直接缩小整页 |
| 圆角 | 延续已建立的卡片 16、浮层 20、控件 9；进度条 pill | 当前已有，无需另起一套圆角语言 |
| 控件高度 | 普通 34–36；面板 28–32；图标操作默认命中区 32×32 | 视觉尺寸可小，命中区域保持清楚 |
| 阴影 | 普通卡无或极弱；浮层一档柔和阴影 | 禁止“卡＋按钮＋内部块”多层重影 |
| 动效 | hover 100–130ms，展开 160–220ms；数字更新不推动邻近控件 | 减少动态效果时直接完成状态转换 |

组件库优先整理 `StatusBadge`、`MetricCard`、`QuotaSummary`、`FilterBar`、`EditableRow`、`InlineError`、`EmptyState`、`SaveBar`、`TaskProgress` 九类。可以由两端各自实现，共用语义规格与相同样本，不必共享 UI 渲染代码。

### 4.3 页面结构改版

| 页面 | 建议布局 | 关键行为 |
| --- | --- | --- |
| 常驻 Agent 面板 | 紧凑顶部导航；会话一行；当前账户限额；今日双指标；缓存摘要；其它账户 / 趋势入口；状态底栏 | 固定首屏预算；账户可切换和置顶；估值入口不撑高每张卡 |
| Agent 详情 | 顶部上下文筛选；主指标；趋势与模型；账户状态区域；每日明细；年度热力图 | 完整分析，支持精确读数、图例交互与范围解释 |
| 服务器面板 | 总状态；主机摘要列表；点击展开单台；详情入口 | 每行时间与状态独立，优先展示用户选定指标 |
| 服务器详情 | 主机列表 / 筛选；选中主机概览；CPU / 内存 / GPU / 存储 / 网络分组 | 多主机比较与单机钻取分工，保留最近有效数据 |
| 数据源设置 | 账户分组；来源子行；接入状态和同步时间；添加入口 | 账户属性与来源位置分开编辑，关联影响就地可见 |
| 价格设置 | 顶部缺价修复摘要；待计价模型；映射草稿；可搜索价格目录 | 明确 USD / 百万 Token；重算作用域、待保存行明确 |
| 通用设置 | 桌面 / 菜单栏；网络与刷新；应用更新 | 立即生效偏好与需保存配置分组标注 |
| 唤醒任务 | 任务状态列表；下一次执行；编辑 / 主操作 / 更多 | 草稿、已部署版本、运行记录各自清楚；删除有影响说明 |
| 估值窗口 | 账户＋采样口径；采样状态；主结果；推算结果；计算依据 / 历史 | 窗口模式独立，后台任务可收起；输出值带周期 |

### 4.4 关键交互规则

| 操作 | 进行中 | 成功 | 失败 / 中断 |
| --- | --- | --- | --- |
| 切换筛选 | 保留旧数据并标“更新中”；记住已应用口径 | 一次性替换对应区域，不跳滚动 | 保留旧结果，提示其口径；提供重试 |
| 刷新记录 / 限额 | 当前分区显示忙碌；其它独立操作继续 | 更新对应来源时间；轻量成功反馈 | 按对象显示失败原因，旧数据标记时间 |
| 编辑配置 | 草稿持续保存于界面状态 | 就地反馈“已保存”；后续同步单独显示 | 原值、输入值和错误字段可见；不关闭编辑器 |
| 关闭编辑器 | 无改动直接关闭 | 有改动保留草稿或明确放弃 | Escape 逐层关闭，焦点返回发起入口 |
| 设备发现 | 显示当前目标；绑定请求快照 | 显示目标、时间、发现设备数 | 保留原选择，提示失败；目标变更则丢弃过期响应 |
| 删除 / 移除 | 确认内容包含名称、目标及影响 | 移除后就地反馈；可逆操作尽可能提供撤销 | 保留原行并提供重试，不虚报成功 |
| 开始采样 | 展示阶段与耗时，防重复提交 | 可收起到后台，列表可恢复 | 说明失败阶段，保留已选择来源 |
| 更新部署 | 显示目标和将应用的草稿版本 | 自动刷新系统任务状态 | 旧部署与新草稿同时保留并可区分 |
| 应用更新 | 展示版本、下载 / 校验 / 安装阶段 | 重启前保护草稿与任务记录 | 显示恢复路径；保留“稍后 / 取消下载”等适用动作 |

表单错误应就地显示，确认对话框用具体动词，不能将普通校验错误都升级为弹窗。这与 Microsoft 的对话框建议一致。[Microsoft Dialog controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/dialogs)

### 4.5 需要统一与需要保留差异的部分

| 必须统一 | 允许按平台实现 |
| --- | --- |
| 5h/7d/credits 数值口径、缓存分母、数据时间语义 | Swift Charts 与 Web canvas / SVG |
| 面板内容优先级、账户顺序、筛选作用域 | mac 菜单栏与 Windows / Linux 托盘 / 胶囊 |
| 动作名称、保存对象、错误恢复、危险操作影响 | mac 独立设置窗口、desktop 设置页面 |
| 主状态枚举、图表单位、空态分类、长流程状态 | SF Symbols 与 SVG 图标 |
| 每一操作的焦点与草稿保护结果 | mac 原生 toolbar / sheet，desktop 窗口内工具区 / dialog |

不要求两端按钮坐标完全一致；要求同一个用户目标有相同可预期结果。
