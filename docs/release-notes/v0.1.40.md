## 更新范围

本次更新覆盖上一公开版本 **v0.1.39 → v0.1.40** 的全部改动，新增五类 Agent 订阅接入、订阅额度重置提醒和 OpenCode 本机历史统计。

## 订阅接入与 API 余额

- 新增 ZCode、Qoder、Grok、Cursor、OpenCode 账户入口，支持查询已适配的订阅额度或独立 API 余额，并提供官方登录与用量页入口。
- ZCode 与 Qoder 按地区选择接口；Cursor 分别显示模型额度池，Grok 订阅与 xAI API 余额分别查询，OpenCode 支持 Go 三个周期及 Console/Zen 余额。
- 支持显式导入 Grok 订阅和 OpenCode Go 的本机登录。验证成功后才保存账户，凭据保存在系统凭据库；不会切换或改写客户端登录。
- 多个订阅账户可独立编辑查询来源；连接失败保留原有账户配置，不留下空账户。

## 订阅额度重置提醒

- 在“设置 → 常规 → 通知”配置提醒：非预期重置默认开启，自然重置默认关闭；每个账户可分别选择沿用全局、开启或关闭。
- 依据实时查询确认额度重置，合并同次刷新中的多个窗口，并避免重复通知。一直满额、历史日志回放及 API 余额充值不会触发订阅重置提醒。
- macOS、Windows、Linux 使用系统通知，设置页提供权限状态和测试通知。应用保留在菜单栏或托盘时继续检测；退出应用或电脑休眠时暂停。
- Windows/Linux 的额度轮询由原生后台执行，关闭或隐藏网页窗口后仍可按查询间隔检测重置。

## 历史统计与稳定性

- 新增 OpenCode v1/v2 SQLite 本机历史读取，只统计已完成消息的用量，不保存对话正文；重复导入不重复计数。远程历史继续使用标准 JSONL。
- 补充订阅表单、通知设置、账户独立覆盖、并发保存、事件去重与后台轮询回归；修复并发额度测试在慢速环境中的启动时序问题。

## 适用范围

订阅查询依赖各服务当前的用量接口；未知或不可识别的额度会明确报不可用。Qoder 新 qoder.cn 协议、跨 Grok/Cursor 共享额度池合并及其他闭源客户端原生历史库暂不支持。五类真实付费账户与各平台系统通知横幅尚未完成实机验收。
