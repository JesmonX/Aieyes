## Release scope

This release covers **v0.1.57 → v0.1.59**, improving macOS responsiveness during navigation, scrolling, and background refreshes.

## macOS interaction performance

- Keep visited pages and their local state in reusable native hosts, while attaching only the active page for layout. Preserve scroll positions, native text fields, focus, drafts, and expanded sections across page switches.
- Reduce repeated grid and flow measurements, and use one adaptive pair of analysis charts across wide and narrow windows.
- Limit refresh invalidation to the data each page displays. Publish analysis filter changes together, cache chart preparation, and move dashboard cache-size encoding off the main thread while retaining stale-response checks.
- Cache localization lookups and reuse date formatters, with language-change invalidation and concurrent access protection.

Paired local replay measurements on a Ryzen 5 5600H showed approximately 90–98% less UI-process CPU time in the main navigation and refresh scenarios. Panel scrolling during refresh improved from about 737 ms to 23 ms in the replay driver's median per-round step P95. These are diagnostic replay measurements, not physical input-to-display latency or frame-rate guarantees. Some filter and navigation feedback remains above 100 ms, and pure panel scrolling used more CPU in this comparison.

## Regression coverage

- Add native checks for retained controls, focus, scroll restoration, environment updates, layout invalidation, and adaptive chart breakpoints.
- Wait for an active key window and completed page attachment in the focus regression, and verify restoration over five page round trips with a bounded deadline instead of a fixed 50 ms delay.
- Cover localization concurrency, filter publication, unrelated host refreshes, and profiler isolation.
- Make the estimate-display test wait for the visibility-triggered refresh to finish before injecting its fixture; retain its data and display assertions and exercise a delayed response.
