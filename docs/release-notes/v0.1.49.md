## 更新范围

本次更新覆盖 **v0.1.48 → v0.1.49**，新增五类原生 Agent 接入，完善现有客户端的历史、API 配置、额度和会话状态，并减少日常刷新对已完成历史的重复读取。

## Agent 与原生 API

- 新增 Kimi Code、DeepSeek Harness、Pi、Oh My Pi 和 CodeBuddy，支持本机及 SSH 历史读取、实际模型与 Token 统计、工具调用和会话状态。
- Pi 与 Oh My Pi 分别适配官方配置和会话目录，支持 profile、原生环境变量、分叉去重与旧记录迁移；Oh My Pi 标题更新不会触发历史重读。
- Web 和 macOS 设置页提供 Claude、Qoder、ZCode、Grok、OpenCode、Kimi、Harness、CodeBuddy、Pi、Oh My Pi 的本机原生 API 配置入口。验证成功后保存，保留已有设置；多文件配置检查并发修改、备份并在失败时回滚，已保存密钥不回显。
- 完善 Qoder、Grok、OpenCode 和 ZCode 的原生记录与状态处理；ZCode 工具执行后的继续调用不会被过早标记为完成。Cursor 接入官方 Hooks，私有数据库中未支持的请求级 Token 不作为累计用量展示。
- Antigravity 会话观察器忽略摘要数据库，避免将统计摘要当作原始会话读取。

## 额度与计量

- 接入 Kimi 官方用量与钱包、DeepSeek 官方 API 余额，并完善 Qoder 和 CodeBuddy 的请求 Credits；账户余额与单次请求消耗分别展示。
- 修复钱包金额单位、零值、负值和缺失值的处理，避免将未知余额显示为可用额度；完善用量去重、来源关联和冻结价格的保留。
- Pi/Oh My Pi 的额度归属实际模型服务商。CodeBuddy 暂无已核实的公开账户剩余额度接口；Kimi 钱包、DeepSeek 官方余额和部分订阅仅完成协议回归，尚未使用有效付费凭据完成联网验收。

## 性能与恢复

- OpenCode/ZCode 使用 SQLite 增量游标，每轮额外检查最多 256 条待完成记录；停止写入后仍继续处理队列，覆盖迟到结算。
- Harness 从已校验的压缩文件边界读取新增帧，解压在数据库写锁外完成，并限制内存暂存；损坏、截断和并发写入不会推进失败游标。
- 本机和 SSH 状态复用未变化的结果，避免重复读取已完成请求。首次导入、目录发现及显式全量重扫仍与历史规模相关。
- 真实 SSH 链路中的合成性能场景从 10 条扩大到 10,000 条历史时，OpenCode/ZCode 的“新增请求加迟到完成”均只读取 2 条记录，Harness 只读取新增压缩帧。

## 验证

- 十二个客户端通过精简 PATH 下的启动检查；新增五类客户端完成本机及 Linux 的真实模型调用、工具执行、原生历史和会话状态核对，重复扫描与全量重放不重复计量。
- 本地 Rust 回归 411 项通过、4 项忽略；Clippy、共享检查、Web UI 与 Swift 原生检查通过。API 浏览器回归覆盖十类客户端、十一种场景。
- Qoder 与 Antigravity 已验证真实账户额度查询。Cursor 登录和依赖账号的模型调用按本次验收范围排除；浏览器中的 Windows/Linux 场景不替代对应系统的原生桌面实机验收。
