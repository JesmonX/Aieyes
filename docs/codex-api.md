# Codex API 接入

在「设置 → Agent 接入 → Codex → API 连接」选择**添加 API**，填写保存位置、连接名称、Base URL 和 API Key。支持本机及已配置的 SSH 设备，接口需兼容 Responses API。模型、推理强度和网络设置沿用 Codex 当前配置；连接表单不设置这些参数，也不设置价格。

API Key 仅保存在目标设备的私有文件中，不进入公开设置和界面返回值。编辑时留空保留已有密钥。保存只创建新的连接修订，不改变正在使用的登录方式；当前已启用的修订在再次切换前保持不变。测试连接仅查询服务的模型列表；部分服务不支持此接口，因此查询失败不等同于推理不可用。

点击**切换到此 API**或**切换到已保存账号**后，先检查目标配置、凭据及受影响进程，再展示确认窗口。只有确认后才会关闭列出的进程并切换。使用当前默认 API 的实例也参与检查；明确使用独立 API profile/provider 的实例及辅助进程会保留。切换前配置、密钥修订或进程有变化时，需要重新检查。切换完成后可重新打开 Codex 并恢复原对话。

API 与账号共用 Codex home 和对话历史。API 切换只选择原生 model provider，通过私有读钥匙助手提供凭据，不改写账号的 `auth.json`。账号切换恢复账号 provider 并使用所选账号档案。要求 Codex 使用文件凭据存储，且不受冲突的强制登录策略或默认 profile 限制；不兼容的配置会在预检时说明。新连接不部署计量网关或系统后台任务，关闭 Aieyes 后仍可使用。

移除连接前须切换到其他登录方式，并退出该目录的 Codex 会话。移除会清理对应密钥、旧连接私有文件及受管理 provider 配置，保留历史用量与旧计量账本。旧网关仅为原有显式 API 配置保留；移除最后一个旧连接时才取消其服务注册。

## 自动估值

- 自动估值仍需按来源开启，并确认所有影响额度的设备用量已纳入；无需选择“纯订阅”或“混用”模式。升级或切换登录后重新建立采样基线。
- 使用原生 JSONL 的请求增量、额度响应，以及 `logs_2.sqlite` 的实际推理路由。实际路由优先于登录标签和会话创建时的 provider。同一会话续聊时可以更换登录方式，不强行给整段历史贴上订阅/API 标签。
- 额度上升且 credits 不变的区间计入订阅限额；credits 下降且适用的额度已耗尽并保持不变的区间计入 credits。已确认的 API 用量排除；混合消耗、未知路由、跨边界累计量、缺价或缺失父历史等不可靠区间跳过，保留最后有效值。
- 任意正向消耗、价格完整且结果有限的可靠样本立即显示。5 个百分点/5 credits 仅作为小样本提示；手动采样使用相同规则。计算采用累计等价成本除以累计消耗，不平均各段比值。等价成本使用统一模型价格，不是 API 服务商账单。
- 5h、7d 和 credits 分别保留待配对用量。连续快照的计数暂未变化时，用量保留到首次正向变化；重置、充值、身份变化、不明确区间或数据缺口会打断配对。重置时间允许相对固定周期锚点最多 10 秒的抖动。
- 新鲜实时快照可立即推进估值，后台额度查询仍约每 30 秒进行一次。日志没有提供充分证据时只能跳过该区间，不能保证识别全部历史或所有第三方客户端。

## Fork 历史修正

「设置 → 常规 → 刷新与历史」中的「精确计数」默认关闭，新安装和升级用户均按各会话自身累计量计数，允许 fork 继承的父历史重复计入，不读取或校验父历史。开关同时控制本机和 SSH；切换后的下一次同步会重读已有 Codex 日志，之后恢复增量读取。

开启精确计数时，按 `session_meta.payload.history_base.thread_id` 与精确的 `end_byte_offset` 递归解析父记录，包括归档、跨日期与多级 fork。仅使用指定字节边界之前的父累计量；后续父会话增长不影响子会话。父记录缺失、循环或边界不完整时，暂不计首个不确定累计值，之后可确认的增量继续记录。父记录恢复或发生变化后会重新校验。相关诊断仅在该设置页查看，不作为同步失败，也不在其他页面告警。

会话 ID 以日志首行 `session_meta.payload.id`（或 `session_id`）为准，支持复制、迁移后附加 UUID 的文件名。本机与 SSH 来源使用相同规则；恢复父记录后，普通增量同步即可重新校验并补算。

首次修复已有 Codex 数据前创建数据库备份，保留原始日志、来源关系、冻结价格和修正审计。当前计数模式决定首段累计量，支持多次切换后的双向重算；重复同步不重复插入同一事件。受影响的历史估值按原区间和原价格生成独立修订的替代记录；无法可靠重算的旧值退出有效估值，原记录保留供审计。缺少原始日志时保留已有记录，日志恢复后继续重算。

## 接口兼容

`codexApi.save/list/status/probe/remove` 管理连接。切换统一使用 `codexAuth.switch.prepare` 与 `codexAuth.switch.commit`；prepare 接受 `target: {kind: "api", connectionId, revision}` 或 `target: {kind: "account", profileId}`，旧的顶层 `profileId` 继续支持。`codexApi.default` 和 `codexApi.command` 已拒绝使用；旧 `codexApi.deploy` 仅作为保存连接的兼容别名，不再部署服务。

## 验证

核心测试覆盖实际路由归因、小样本、零消耗配对、fork 下调、历史估值修复和切换冲突。`scripts/test-codex-api.py` 与 `scripts/test-codex-auth.py` 覆盖 SSH 直接连接和凭据写入失败回滚，同时保留旧账本回归。Web 回归覆盖精简表单、显式确认、失败草稿和切换成功后的刷新失败，Swift 构建覆盖同一接口。

`scripts/test-codex-api-cli.py <codex 路径>` 用实际安装的 CLI 连接本地模拟接口，验证同一对话的账号 → API → 账号 → API 续聊、原生凭据助手、设置保留及无网关运行。测试不调用真实收费接口，也不安装系统后台任务。实际服务需支持当前 Codex 选择的模型与 Responses API。
