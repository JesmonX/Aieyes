# CPU 优化实施与精简复测

依据：[排查报告](cpu-interaction-audit-2026-10-21.md)、[优化计划](cpu-optimization-plan-2026-10-21.md)。本轮实施 macOS 的滚动持久化、偏好通知和刷新发布优化，保留已有页面与编辑状态。未提交、推送或替换已安装应用。

## 实施内容

- `ScrollPositionStore` 在主线程按页面 key 保存最新位置，静默 250 ms 后合并写入旧格式偏好；切页、拆卸、窗口关闭和正常退出收尾。同值不写，旧延迟任务不能覆盖新位置。隐藏页面和未就绪内容的边界变化不记录，恢复仍按内容范围夹取。
- 桌宠仅在启用/缩放偏好真正变化时同步窗口，仅在可见性变化时发布 `petVisible`。菜单栏沿用去重后的状态投影，内容、计数显示、屏幕缩放或无障碍显示设置变化时才测量标签；tooltip、未保存标记继续独立更新。
- 刷新先组织完整结果，再按有效内容比较后发布。只忽略查询级 `generatedAt` 的重复变化，保留首次就绪、来源时间戳、真实用量与额度变化。未变化的缓存不再次 JSON 编码。请求编号、刷新合并和缓存失效规则保留。
- 页面根区域按可见内容快照更新；页头、页脚、刷新按钮、错误与失败详情弹层各自观察操作状态，忙碌反馈不再使整个页面失效。会话条不再跟随桌宠可见性发布。额度分组去掉全模型观察；账户卡片保留估值和账户状态更新所需的观察，通过输入比较复用未变化的内容。图表也比较实际输入。

CPU、内存卡片等高的修改同时保留，原生与 Web 的宽窄、深浅外观检查见排查报告。

## 复测方法

按用户要求缩减为 6 项关键操作、各 5 次；发现刷新仍有残余开销后，迭代中只补测两个受影响场景，各 5 次。未重跑 37 项矩阵，也未追加安装版与工作区版本差距测试。固定原生刷新图标的实验没有显示稳定收益，已撤回，保留现有图标和交互。

修改前后均使用优化编译（`-O`、whole-module）、相同驱动、实际偏好与固定回放：329 MiB 数据库快照、6 个账户、18 个来源、4 台主机、466 个模型；深色主题、主窗口 1307 × 900、面板宽 450、桌宠开启。快照及包含私人数据的输入仅保存在忽略目录 `.local/cpu-optimization-20261021/`，每次运行使用独立数据库副本和可写偏好域，结束后清理。

CPU 数字是单轮进程累计 CPU 时间，不是整机 CPU 百分比。滚动每轮 60 步，并包含停止后 350 ms 的保存观察；没有把延迟写入移出样本。步进 P95 包含没有位移的边界步骤，不用较低的“仅有位移步骤”指标替代。保留首次样本，以 5 次的中位数作小规模回归判断。

驱动使用生产处理函数、原生窗口和实际数据的只读回放。SwiftUI 忽略合成滚轮事件时，以原生 clip view 步进；这不是物理触控板/鼠标延迟或屏幕帧率。实际核心调用和首次解析成本见排查报告，不能把回放时间当成网络或扫描时间。

## 性能结果

首轮 6 项集成复测中，纯滚动已达到 P0 的 CPU 降幅和步进目标：

| 场景（各 5 次） | 修改前 CPU / 轮 | 集成版本 CPU / 轮 | CPU 降幅 | 步进 P95 中位数：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 分析页滚动 | 14,550 ms | 1,584 ms | 89.1% | 518.4 → 25.5 ms |
| 面板滚动 | 13,354 ms | 253 ms | 98.1% | 441.1 → 19.0 ms |

滚动位置持久化次数的中位数由 32 / 36 次降到 2 / 0 次；0 次表示回到已保存位置，无需重复写入。两种滚动的 `live` 发布中位数均为 0。停止后的保存观察 CPU 中位数约 21 ms，已包含在表内。滚动容器保留；分析页首次样本命中目标的变化在修改前后都存在，未被剔除。

同批集成复测中，进入分析页的 CPU 从 3,865 ms 降到 2,425 ms（37.3%），刷新切页连点从 4,887 ms 降到 3,346 ms（31.5%）。两者首反馈中位数仍约 601 / 566 ms，尚未达到原定 100 ms 目标；这是保留的限制，不能把这些数字描述为瞬时响应。

上述是 `.local/cpu-optimization-20261021/final/` 的集成版本结果。之后针对刷新做了局部观察修复，最终二进制只补测滚动中刷新与无变化刷新；没有将较早版本的 6 项结果冒充最终二进制的完整验收。

最终实现的针对性复测位于 `verified/`，输入哈希与基线一致，源码已核对为当前实现（仅附加相同的诊断控制）：

| 场景（各 5 次） | 修改前 CPU / 轮 | 最终 CPU / 轮 | CPU 降幅 | 完整步进 P95 中位数：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 面板滚动中刷新 | 13,415 ms | 1,237 ms | 90.8% | 402.8 → 84.4 ms |
| 无变化刷新分析页 | 1,781 ms | 794 ms | 55.4% | 不适用 |

面板滚动中刷新的每轮超 33 ms 步骤中位数由 45/60 降到 7/60，刷新完成中位数约 564 ms，悬停事件分发最大耗时的中位数约 0.006 ms。滚动容器与命中目标均保留。位置写入中位数为 2、`live` 发布为 0；停止后的收尾 CPU 约 277 ms，包含在 1,237 ms 中。该场景的 RSS 中位数约 151.7 MiB，基线约 153.8 MiB；无变化刷新约 138.5 MiB，基本持平。这是短测快照，不构成长期泄漏结论。

P1 的无变化 CPU 降幅和滚动中刷新先降至 100 ms 以内的目标达到；33 ms 的进一步目标尚未达到。面板滚动中刷新首反馈中位数约 3.7 ms，但 5 次中最慢首反馈约 109 ms、最慢单轮步进 P95 约 193 ms。无变化刷新首反馈中位数仍约 380 ms、P95 约 457 ms，广义操作反馈 100 ms 目标没有全部达到。没有为此降低门槛或继续扩大复测矩阵。

本轮保留 P0/P1 的已验证收益，不扩大到隐藏页容器重建或布局缓存改写；这些会影响几何和页面状态，后续应针对剩余首反馈成本单独评估。

## 状态与功能回归

`scripts/test-cpu-optimization.sh` 使用临时偏好、合成 IPC 和生产 Swift 对象验证：

- 60 次位置变化合并、旧任务防覆盖、不同 key、切页时保存、隐藏变化忽略、内容就绪后恢复、内容缩短夹取、关闭窗口收尾。
- 桌宠无关偏好不引发位置/可见性发布，启用、禁用和缩放仍生效；会话数据变化仍发布，会话条忽略桌宠变化。
- 查询时间戳去重不吞掉真实用量、模型名称、来源时间戳和首次就绪；无变化重载的数据投影发布为 0，加载反馈仍更新。仅估值数据变化、额度本身不变时，真实账户卡片也能显示新估值。
- 原生额度卡片可展开、刷新后仍保留展开状态、账户按钮能触发、可再次折叠；刷新指示器加载前后尺寸一致，局部额度按钮和页脚仍及时显示忙碌反馈。
- 延迟旧请求不覆盖最新筛选，失败后可以恢复；设置页刷新保留焦点，切页保留未保存输入。

上述回归通过。macOS Debug 构建通过；`git diff --check`、119 个 Core/Web/Swift RPC 契约检查、5 项诊断隔离测试通过；Web 主界面/面板 CPU 与内存卡片等高回归通过。

## 验证边界

这些证据证明本轮路径的优化和已覆盖状态回归，不能保证所有平台和真实输入条件下都没有副作用。物理触控板/鼠标手感、Windows/Linux 原生运行，以及 AppDelegate 的真实菜单尺寸测量计数未在此驱动中验收；菜单门控已有编译与代码审查证据。

未改动解析版本失效、历史事务、备份或游标。升级后的首次历史重读仍可能占用约 8.85 秒；它与本轮交互优化分开，首次扫描更细进度/取消仍是独立后续工作。强制杀进程可能丢失尚未提交的最后约 250 ms 滚动位置。
