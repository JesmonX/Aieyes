# 5h 采样和连接功能

## 额度估值

新采样优先使用账户的 5h 总池，Claude 使用 `five_hour` / `seven_day`，不把重叠的模型子池相加。只有 7d 总池的账户继续支持原有口径；既有 7d 采样和 credits 采样保留。以下金额均为当前模型组合的 API 等价价值。

| 显示值 | 计算口径 |
| --- | --- |
| 5h 价值 | 有效片段的成本合计 × 100 ÷ 5h 消耗百分点合计；至少消耗 5 个百分点 |
| 7d 同期换算 | 具有有效 7d 观测的片段成本 × 100 ÷ 对应 7d 消耗百分点；小于 5 个百分点标记样本较少 |
| 7d 近期倍率估算 | 5h 价值 × 同账户近期学习到的容量倍率；尚无倍率时显示空值 |

容量倍率利用现有实时限额刷新，被动采集同一周期内 5h 与 7d 的正向变化，不增加限额轮询。每个样本至少包含 5h 的 5 个百分点、7d 的 1 个百分点；使用最近 90 天的样本，按 7 天半衰期加权，倍率为加权 5h 变化之和除以加权 7d 变化之和。界面显示样本数、最近观测时间及样本较少/历史倍率提示。订阅方案变化后清除旧方案倍率。

正常 5h 或 7d 重置时，保存上一次有效检查点，跳过无法确认的边界间隙，从新快照接续。提前重置、额度异常回升、查询失败、超过 5h 未取得有效快照、来源或订阅方案变化会暂停并保留有效片段。已结束记录固定其价格和容量倍率；后续重算及学习不改写历史结果。

开始采样只同步一次所选用量来源，然后读取新限额。结束采样先同步记录、读取新限额，再补齐尾部记录，避免限额请求期间落盘的用量遗漏。远程读取最多三路并行；界面显示来源、读取限额、补齐记录、保存结果等阶段和已耗时。两个桌面窗口共享操作状态，采样边界处理期间暂停自动日志/限额刷新。

## SSH 与代理

服务器编辑器可选择 SSH 配置/密钥或账号密码。密码存入 macOS Keychain、Windows 凭据管理器或 Linux Secret Service；配置仅保存不透明引用。OpenSSH 的 askpass 辅助程序通过引用取密码，命令参数和环境变量不含密码。留空保留已保存密码，保存失败保留草稿，丢弃草稿或删除服务器时清理相应凭据。密码登录要求已验证的 SSH 主机密钥，未知或改变的密钥不会自动信任。

通用与本机来源的代理设置均可测试当前草稿，不必先保存。默认并行测试 GitHub 和 OpenRouter，可设置 1–5 个 HTTP/HTTPS 目标。延迟为请求到收到 HTTP 响应头的时间，显示成功目标的平均值；部分失败显示「连接不稳定」，全部失败显示「连接失败」，悬停查看各目标结果。手动点击立即重测，面板可见期间最多每五分钟自动测试一次。代理配置变化后旧结果失效。

## 界面与价格修复

两端悬浮面板底栏显示连接状态、延迟和检查更新；发现新版后保留感叹号，选择稍后不清除提示。固定按钮移入「更多」。缓存显示统一为数字后括号命中率。

模型映射区移到价格设置顶部。「一键映射」填入右侧 OpenRouter 模型 ID，并滚动和聚焦到编辑区，保留左侧日志模型名，由用户添加映射。删除映射后完整重算会清除找不到价格的旧成本、已计价 Token 与价格快照，重新同步也不会恢复它们。精确 ID 和唯一后缀仍可自动匹配；仍能匹配的模型不会列为缺失。

「保存并重算」也位于价格页顶部，先保存配置，再完整重算，完成后刷新概览。普通保存原先会读取并解析全部历史事件尝试补价，并等待概览读取结束；现在只有映射变化才按模型索引补计对应记录，其余设置保存不遍历历史。保存成功反馈不再等待概览，影响历史显示的配置按需后台刷新；无关的设置修改不重置限额轮询。macOS 的当日无筛选概览复用于菜单栏，避免重复读取，保存期间显示阶段与耗时。核心仍按顺序处理用量/限额与保存请求，因此正在进行的远程刷新会造成排队，界面明确显示「等待当前刷新完成」。

本机 10 万条模拟历史记录的核心 `settings.save` 对比（含进程启动）：优化前约 1.15 秒；优化后首次创建模型索引约 0.17 秒，连续五次的中位数约 0.02 秒。结果保存在 `.local/settings-save-benchmark/result.json`，不包含真实服务器刷新排队或界面渲染耗时。

## 验证范围

新增核心回归覆盖多轮正常重置、提前重置、缺失价格、方案变化、近期倍率权重、重复观测、已结束结果冻结、删除映射后重算和重新同步、采样边界同步次数及阶段通知。代理测试使用本机 HTTP 服务验证成功/部分失败/全部失败。凭据测试使用模拟系统凭据库。

浏览器回归覆盖两种桌面布局的三项估值和进度、账号密码读取设备与保存失败清理、草稿代理测试、映射输入与焦点、顶部保存并重算的请求顺序、慢概览不阻塞保存、底栏延迟和更新感叹号，以及小窗口布局。Swift 回归覆盖原生草稿、密码替换与重试、代理结果失效、阶段通知、普通设置不刷新历史、慢概览后台读取及当日概览复用；核心回归用拒绝写入的触发器验证普通保存不改动历史、映射只补计对应模型且保留事务回滚。原生浅深色截图使用模拟数据，位于 `.local/improvements/macos`。macOS 调试构建位于 `dist/Aieyes.app`。

本轮在 macOS 上执行验证。真实 SSH 密码登录、实际代理服务及真实订阅采样精度未进行端到端实测；Windows/Linux 原生凭据库、安装包和系统 WebView 仍需对应平台实测。

## v0.1.12 发布构建修复

v0.1.11 的 [Release 运行](https://github.com/JesmonX/Aieyes/actions/runs/37447273925) 中，Windows 和 Linux 构建成功，两个 macOS 架构在 Swift production 编译阶段失败。错误为类型推断超时，分别位于采样账户的组合查找表达式和采样结果的 SwiftUI 视图；本机先前的 debug 构建未发现该问题。

修复将账户查找拆成带明确类型的分支，并将结果标题、三项估值、容量说明、计算依据和价格依据拆成独立函数。原生回归增加按采样记录 ID 定位账户后仍能显示进度的检查，并以 `swiftc -O` 验证；本机完整 Swift release 编译、原生回归及 x64 DMG 打包通过，优化构建生成的浅深色 5h/7d 与 credits 截图显示正常。修复使用新标签 v0.1.12 和 macOS 构建号 13，保留原失败标签，重新执行多平台发布流水线。
