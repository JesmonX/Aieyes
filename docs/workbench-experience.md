# 工作台体验与系统集成（11-12）

本轮按界面、美观、动效、功能、体验五个方向改进三端，macOS 与 Windows/Linux 同时交付。不包含：菜单栏形状状态、导出（CSV／图片／诊断包）、通知动作按钮、全局热键与命令面板、单次任务成本与项目归因。

## 界面

### 会话页

主窗口侧栏新增“会话”页，位于服务器之后。

- 顶部三张汇总卡：进行中、等待输入、最近结束。
- 按 Agent 筛选的选项排成一行；列表分“进行中”“最近结束”两组，等待输入的会话排在最前。
- 只显示生命周期信息：Agent、机器、项目文件夹名、阶段、本轮时长、Token 与输出速度。不显示提示词、工具参数或回复，也不保存超出现有会话数据的历史。
- 没有会话时显示统一空态；有来源读取失败时列出失败来源。
- macOS 由 `sessionEngine` 唯一一处调用 `sessions.list`。Windows/Linux 没有引擎调用 `sessions.list`，会话列表由 `desktop.rs` 中唯一的会话读取线程持有。

### 设置治理

- 设置只有一个窗口，所有页面上方有一个搜索框，搜索结果来自同一份索引（macOS `SettingsIndex.swift`，Web `settings-index.js`）。回车打开第一个结果，Esc 清空；打开后滚动到对应分区并高亮一次。
- 常规设置的页面在两端相同：外观、面板、桌宠与会话（macOS 为桌面显示）、启动与系统、网络代理、刷新与历史、通知、Webhook、高级、更新与关于。某一页在当前平台没有内容时不显示。
- 原先的辅助窗口和对话框改为设置页内的分区：
  - 面板显示账户、账户顺序 → 面板页；
  - 后台采样管理 → 高级页。
- macOS 其余辅助窗口记住位置与大小（frame autosave）。

### 面板到主窗口

- 面板的账户卡新增“在主窗口中查看”。主窗口打开总览，清除会隐藏该账户的筛选、展开所在分组，滚动到账户卡，并用强调色描边一次（保持 1.6 秒后淡出）。总览中没有该卡片时不做处理。
- 面板宽度可选标准 450 或紧凑 360（设置 › 面板 › 面板宽度）。屏幕放不下时面板自动收窄。Windows/Linux 修改后，已打开的面板会以新尺寸重新打开。
- 来源编辑器中永久禁用的两个选择框改为只读行。

## 美观

- 浅色模式层级：主窗口的一级卡片为白色，带接触阴影和主阴影，嵌套卡片保持平面；深色模式保持原有层级；浅色面板卡片使用更亮的底色与轻阴影。令牌见 `ui-design-tokens.json` 的 `elevation-*`，`detail-card` 浅色由 `#f1f1f1` 改为 `#ffffff`。
- 空态统一使用同一组件：macOS `EmptyState`，Web `AieyesUI.emptyStateHTML`。服务器为空、筛选无匹配、额度、用量和会话空态都已迁移。macOS 的 `EmptyCard` 已移除。
- 颜色语义：
  - 状态色（`ok`／`warn`／`danger`）只表示状态；
  - 类别色表示数据系列；
  - 强调色只用于选择和交互。
  - 因此 DeepSeek 余额组成中的“赠送”部分改为中性色，静态的“余额”标签不再使用强调色，会话阶段文字使用正文颜色，旁边的图形标记带阶段色。

## 动效

所有动效使用 Motion 令牌（`motion-fast/base/slow/expand`）。系统开启“减少动态效果”后不播放动画，只有页面切换保留一次淡入。

- 额度环：弧长从旧值过渡到新值；刷新完成后亮起一次。首次显示不播放。菜单栏环形也随额度平滑过渡；减少动态效果时静止。
- 数字：标题数字、环心数值、服务器指标与网速在原位滚动到新值。
- 图表：切换日期范围时交叉淡入；同一范围内刷新或筛选时柱形缓动。
- 一次性反馈：
  - 刷新后的账户卡描边一次；
  - 额度刷新按钮显示“已更新” 1.6 秒，三种标签共用固定宽度；
  - 同步图标弹跳一次，跳过启动后的第一次成功；
  - 会话完成或确认的额度重置时，桌宠播放一次闪光。闪光叠加在核心选定的动作上，不改变桌宠状态，桌宠隐藏或暂停时不播放。
- 触控板反馈（macOS）：桌宠贴边、账户与 Agent 拖动排序每移动一格、缩放滑块每档与音量滑块每 10%。
- 页面切换：主窗口与面板 Agent／服务器切换使用淡入加轻微上移，减少动态效果时只淡入。

## 功能

### 登录时启动

- macOS：`SMAppService.mainApp`，需在已打包的应用中注册。设置 › 启动与系统可打开系统的登录项设置。
- Windows：HKCU `Software\Microsoft\Windows\CurrentVersion\Run` 下的 `Aieyes` 值，内容为 `"<exe>"`。
- Linux：`$XDG_CONFIG_HOME/autostart/aieyes.desktop`（默认 `~/.config/autostart/aieyes.desktop`），程序路径变化时在启动时更新。
- 没有引入 `tauri-plugin-autostart`。

### 应用链接

```
aieyes://[open/]panel|overview|analysis|servers|sessions|settings[/<name>]
```

- `<name>` 可为 `integrations` 或 `accounts`（接入与账户）、`machines`（机器与采集）、`prices`、`wakeups`，或常规设置的页面键。未知的 `<name>` 打开常规设置。
- 链接只用于导航：路径不在固定列表内即拒绝，查询参数和片段一律忽略。任何应用或网页都能触发 URL scheme，所以链接不能执行操作或修改设置。
- 注册方式：
  - macOS：`Info.plist` 的 `CFBundleURLTypes`；
  - Windows：HKCU `Software\Classes\aieyes`，命令 `"<exe>" "%1"`；
  - Linux：`~/.local/share/applications/aieyes-url-handler.desktop`（`x-scheme-handler/aieyes`）并执行 `xdg-mime default`，AppImage 使用 `$APPIMAGE`。
- Windows/Linux 每次启动都会注册，卸载后注册项保留。应用已运行时，链接经单实例插件交给运行中的进程。
- 设置 › 启动与系统列出可复制的链接。

### 等待输入数量

- macOS：打开窗口时 Dock 图标显示 Aieyes，徽标为等待输入的会话数，可在设置 › 启动与系统关闭。
- Windows/Linux：托盘提示原本就包含等待数量（多个会话时以“等待N”开头，单个会话显示“等待输入”），本轮没有修改。
- 小组件（WidgetKit）需要正式签名，当前 ad-hoc 签名无法提供，未实现。

### Webhook 通知

设置 › Webhook：

- 最多 8 个接收地址，每个可单独启用并发送测试；列表只显示主机名，因为地址可能含令牌。
- 格式：JSON、纯文本、Bark、Slack、企业微信、飞书。
- 可选事件：订阅额度重置、会话等待输入、会话完成、会话执行失败、服务器告警。额度重置发送每一次已确认的重置；服务器告警使用“通知”页的阈值与持续时间。
- 服务专用格式会校验响应正文中的业务成功码（Slack 为 `ok`）；HTTP 200 的业务拒绝仍进入退避重试，错误文本不回显响应正文。
- 消息只含身份字段：会话消息为 Agent、机器、阶段、轮次与项目文件夹名，额度消息为账户与额度窗口，服务器消息为主机与使用率。不含提示词、工具参数或回复。
- 投递由核心完成：事件先写入队列，已确认成功的地址不会再次投递；网络超时后重试可能重复送达。失败的地址按 60 s × 4ⁿ 退避，最多尝试 5 次，事件 24 小时后过期，队列上限 200 条；单次请求连接超时 5 秒、总超时 12 秒。
- 客户端在 `webhooks` 修订变化时调用 `webhooks.dispatch`，仍有失败或待发事件时每 60 秒重试。macOS 由 `OutboundEventService` 负责，Windows/Linux 由 `outbound.rs` 负责。
- Windows/Linux 的会话事件由会话读取线程调用核心的 `SessionObserver` 排队，规则与 `sessions.list` 相同：跳过后台会话，并检查事件开关。

### 服务器分钟历史与告警

- 核心在内存中按主机保留最近 180 分钟的分钟汇总（CPU 均值与峰值、内存均值、所有 GPU 中的最高利用率），通过 `hosts.history` 读取，核心重启后清空。
- 服务器卡片画最近 60 分钟的走势线，纵轴固定 0–100，与下方的资源条一致：
  - CPU、内存的走势位于卡片标题与数值之间，不增加行高；
  - 单 GPU 主机画在该 GPU 的标题行；多 GPU 主机在 GPU 列表上方固定一行“GPU 最高利用率走势”，不足两个相连读数时显示“—”；
  - 读数间隔超过 `max(150 s, 2.5 × 采样间隔)` 时断开，暂停显示为空缺，不画成 0；缺少读数的分钟跳过；孤立读数画成点；只有最新读数仍在间隔内时才标记圆点；
  - 悬停说明为“{0} 分钟走势 · 均值 {1}% · 峰值 {2}%”，CPU 峰值取分钟内最大值。
- 服务器告警（设置 › 通知）：CPU 与内存阈值 50–100%（步长 5），持续 1、3、5、10、15、30 分钟。采样中断超过 max(150 秒, 2.5 × 采样间隔)、失败、暂停或修改规则时重新计时。使用率高于阈值并持续所选时间后通知一次，回落后再次升高会重新通知。客户端每 15 秒调用 `hostAlerts.take`；系统通知只在开启服务器告警时发出，Webhook 的服务器告警使用同样的阈值。

## 体验

- 首次显示：
  - macOS 在首次读取完成前，今日用量与统计卡片以同样布局显示占位骨架，不再先闪出 0 Token 或空态。
  - Web 在首次结果前显示总览轮廓。同一筛选条件下，会先显示上一次的总览或面板结果（localStorage，≤ 1 MB，最多每 30 秒写入一次），并标注“正在更新，仍显示上一结果”。macOS 不跨启动缓存统计。
- 冷聚合：耗时查询按已处理日期发布进度；单日大批量数据每 256 条检查取消。两端显示进度与取消按钮，取消仅作用于当前查询标识，不影响其他窗口和采集任务；已显示结果保留，可重试。macOS 进度单独观察，Web 只更新进度条，避免每次进度触发整页重绘。
- 本次更新：
  - 应用启动时调用一次 `app.launch`，版本变化后在总览显示一次横幅；“查看本次更新”打开当前版本的 `docs/release-notes/v<version>.md`。
  - macOS 由 `scripts/build-macos.sh` 将该文件复制为 `ReleaseNotes.md` 资源，以表单显示；Windows/Linux 由 `build.rs` 内置，在设置 › 更新与关于显示。
  - “完整变更记录”只打开说明中的 https 链接。没有对应说明文件的版本不显示横幅。
