# 飞书个人会话控制

Aieyes 可通过飞书应用机器人，把已监测会话的问题和最终回复发到你的个人私聊。引用通知即可回答问题，或在会话中断、完成后继续下指令。本机和 SSH 共用同一套目标定位与指令状态。

功能默认关闭。启用后仍使用原来的终端、App、IDE 和启动方式；Aieyes 不创建替代会话，也不接管 Agent 的模型、权限或账户配置。

## 配置

1. 在飞书开放平台创建**企业自建应用**，添加机器人能力。
2. 开通接收机器人单聊消息的权限 `im:message.p2p_msg:readonly`，以及以应用身份发送消息的权限 `im:message:send_as_bot`。事件订阅添加 `im.message.receive_v1`，接收方式选择**长连接**。Aieyes 会主动连接飞书，无需公网回调地址或入站端口。
3. 在 Aieyes **设置 → 聊天渠道**填写 App ID、App Secret，启用并保存。App Secret 存在操作系统凭据库，配置数据库只保存引用。编辑时密钥留空会保留已存凭据。
4. 根据飞书后台要求完成应用版本发布和可用范围设置，使自己的账号可以私聊机器人。长连接显示已连接后，点击**创建配对码**，将完整 `/pair aieyes-…` 指令发送给机器人。
5. 收到配对成功回复后，发送 `/sessions` 查看会话。Aieyes 和相关来源须保持运行、启用；SSH 来源还需要可用的 SSH 连接和目标机器上的 Python 3。

配对码有效期为 10 分钟，最多尝试 5 次。一次只绑定一个 `open_id + chat_id + tenant_key`；群聊、其他应用、其他发送者、非文本消息均不进入指令队列。更换绑定账号须先在本机解除配对。更换 App ID 后需要重新配对。

macOS 的原生终端输入还需要开启**允许按终端适配输入**，并点击**授权终端自动化**。只有此按钮会请求系统自动化权限；后台收到指令不会弹出授权窗口。原生会话 API 不需要终端自动化权限。

## 私聊指令

| 输入 | 行为 |
| --- | --- |
| `/sessions` | 列出近期会话、状态、控制能力和 `s…` 编号 |
| `/use s…` | 选择后续未引用消息的目标会话 |
| `/send s… 内容` | 向指定会话发送指令，也可用来转发 Agent 的斜杠命令 |
| 引用会话通知后回复 | 使用被引用消息对应的会话和轮次；优先于 `/use` 的选择 |
| `/status` | 查看最近的指令状态及 `c…` 编号 |
| `/retry c…` | 仅重试尚未提交的待处理指令；原问题和轮次必须保持不变 |
| `/cancel c…` | 取消尚未提交的指令；不会终止已经执行的 Agent 任务 |
| `/help` | 查看用法 |

单个结构化问题可以直接回复答案，或回复选项数字。多个问题使用 `问题编号=答案`，每行一个。可核验的原生审批必须引用具体请求，使用 `/approve` 或 `/decline`；`/approve` 只允许本次操作，不授予整个会话的长期权限。`/cancel-request` 仅在原请求提供取消选项时生效。

未知或已过期的引用不会回退到其他会话。没有引用、没有 `/send`，也没有通过 `/use` 选择目标时，机器人会提示选择会话，不按“最近活跃”猜测。

## 支持范围

| 会话与环境 | 当前能力 |
| --- | --- |
| Codex / ChatGPT Work，已有兼容的 app-server 控制接口 | 验证原 thread、工作目录和最新 turn 后，回答可重放的结构化问题或单次审批，或在同一 thread 开启下一轮 |
| Codex，原生 socket 不可用，但已有 CLI 支持 `queue --thread … --message … --resume` | 核对当前原生记录后排队到同一 thread。只回执“已提交”，不能把 CLI 成功退出视为已执行；等待提问时不使用此回退 |
| 本机或 SSH Linux 的 tmux 会话 | 开启终端输入后，核对 PID、启动时间、TTY、父进程、唯一 pane 和已支持 Agent 的前台命令；提交文本并等待会话记录确认 |
| macOS 原生前端中的 Ghostty、iTerm2、Terminal | 开启并授权终端输入后，按 TTY 唯一定位原标签页或分屏，再检查桌面解锁状态、原进程及前台进程组；通过应用自己的 Apple Events 输入 |
| 其他 App、IDE、终端或 Agent | 发送可读取的问题、完成通知和最终回复；没有可靠控制接口时保留指令，说明不能提交的原因 |

Codex 原生控制入口为该来源目录下的 `app-server-control/app-server-control.sock`。不会连接其他来源的 home，也不会新启动 app-server 替代原应用。较旧版本、Windows 上没有此 Unix socket 的安装、未加载的提问、未向新客户端重放的问题，会按实际能力保留指令或退到已有 CLI 队列。

tmux 和 macOS 终端适配只在本轮结束或等待输入时提交。原 Agent 退出、PID 被复用、前台变成 shell、出现多个匹配分屏、桌面自动化缺少授权等情况会保留指令。SSH 上的图形化 App 自动化和非 Linux 远程终端控制不在第一版范围内。终端审批没有原生请求标识时，需要回原窗口处理。

问题和最终回复从原会话的受限尾部记录读取，不发送执行过程、工具结果或 reasoning。父、子会话会按来源和原生 ID 分开核对；不读取未完成写入的 JSONL 行，也不把上一轮或子 Agent 的回复当作当前结果。只有元数据、加密记录、没有最终文本或超出读取窗口时，会明确提示内容暂不可读取。

## 状态与恢复

| 状态 | 含义 |
| --- | --- |
| 等待提交 | 已持久化，等待核对原目标 |
| 正在提交 / 等待桌面操作 | 已开始一次提交，或等待原生前端领取终端操作 |
| 已提交，待确认 | 队列或终端已接受提交，但还没有原会话的确认 |
| 已确认 | 原生接口确认启动或接收回答，或原会话记录出现对应的新用户输入；不表示任务已经完成 |
| 待处理 | 没有提交，原会话、权限或接口不满足条件；可在条件恢复且轮次不变时重试 |
| 结果待核对 | 可能已经提交，但连接、应用重启或回执超时使结果无法确认；不会自动或手动重放这条指令 |
| 已取消 | 尚未提交的指令已取消 |

提交前先写入状态；应用在提交期间退出，重启后将该指令标为“结果待核对”。相同入站消息只处理一次；同数据目录只运行一个后台消费者。飞书发送重试复用持久化 UUID，最多 5 次，且只在消息产生后的 55 分钟内自动重试。设置页显示未送达数量和最近错误。

确认检查优先处理最早的指令。已提交超过 60 秒仍无法确认时，会在检查后转为“结果待核对”；来源被暂停、移除或目标不可用时，也会按此规则处理。

修改渠道配置会取消旧配置中尚未提交的指令，已可能提交的结果保留供本机核对。旧通知的引用不会被重新绑定到新的配对或轮次。

Aieyes 退出、电脑休眠或 SSH 不可达时，控制能力会暂停。**已被 Aieyes 接收**的指令保存在本机；未接收的飞书消息不能保证补收，超过 5 分钟的入站消息会被忽略。恢复后先用 `/status` 核对，避免重新发送可能已执行的操作。界面锁定只阻止需要桌面自动化的操作，原生 API 和 tmux 按各自能力继续工作。

消息、指令、通知引用和会话控制缓存按 24 小时清理；退出期间未清理的记录在下次运行时处理。Aieyes 不删除飞书服务端已经送达的消息。

## 验证边界

离线测试覆盖配对与鉴权、重复事件、引用路由、旧轮次拒绝、密钥隔离、崩溃恢复、分片与 ACK、同 UUID 发送重试、原生协议模拟、SSH 适配和两端设置页。macOS 通过安装的 Ghostty、Terminal 字典编译自动化脚本；测试不向真实会话输入。

真实飞书账号、企业权限与发布流程、实际 app-server 对未决请求的重放，以及真实终端提交仍需按 [手动验证](manual-verification.md)完成验收。第一版没有将这些模拟测试描述为真实私聊已接通。
