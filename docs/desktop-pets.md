# 桌面宠物

内置原创橘猫根据本机 Codex 会话状态变化。只读取已启用的本地 Codex 来源生命周期元数据，不显示提示词或工具参数，不需要登录额外服务。远程来源及其他 Agent 的运行状态尚未接入；没有受支持的活跃会话时显示空闲。

## 开关与操作

- Windows：「设置 → 通用 → 桌面显示」的自动模式默认显示宠物；选择悬浮胶囊可恢复旧入口，选择状态栏可关闭悬浮入口（无托盘时仍保留入口）。已手动保存胶囊模式的用户保留原选择。
- Linux：默认使用状态栏；在相同设置选择桌面宠物后启用。
- macOS：「设置 → 通用 → 桌面宠物」打开；默认关闭，原菜单栏继续保留。右键可以隐藏宠物，设置中可恢复。
- 点击打开面板，拖动调整位置。Windows/Linux 沿用贴边和屏幕范围约束；macOS 保存位置，并在屏幕变化后限制到可见工作区域。
- 系统减少动画时显示当前动作的静态首帧。普通模式活动动作播放三轮后回到安静待机；状态标签始终保留，不把待机动作当作任务完成。相同状态轮询不会重启动画。

## 状态映射

核心统一选择状态，客户端只渲染同一张 8 列、9 行精灵图。多会话优先级为等待输入、失败、完成、运行；同优先级选择最近更新的会话。监控不完整时明确显示状态不全。

| 会话状态 | 小猫动作 | 图集行（从 0 开始） |
| --- | --- | --- |
| 空闲 | 呼吸、眨眼 | 0 |
| 进行中 | 奔跑 | 1 |
| 等待输入 | 挥爪提醒 | 3 |
| 已完成 | 跳跃 | 4 |
| 执行失败 / 已中断 | 低落 / 休息 | 5 |
| 状态待确认 / 状态不全 | 等待 | 6 |
| 执行工具 | 敲键盘 | 7 |
| 思考中 | 思考 | 8 |

等待输入来自 `request_user_input` 工具调用，关联 `call_id` 的返回后解除等待；并行工具调用和返回不会误解除。失败来自明确的 `error` 生命周期事件。没有明确错误事件时不推断失败。沿用原监控时效：运行超过 180 秒无更新视为待确认，完成/中断/失败保留 90 秒，发现范围为最近一小时。

## 参考与资产

行为优先级、三轮后平静待机及减少动画参考 [OpenAI Pets 文档](https://learn.chatgpt.com/docs/pets)。图集布局参考 [公开 Codex pet model](https://github.com/openai/codex/blob/main/codex-rs/tui/src/pets/model.rs) 和 [asset pack](https://github.com/openai/codex/blob/main/codex-rs/tui/src/pets/asset_pack.rs)。这是 Aieyes 自己的实现；小猫为本仓库原创 SVG 图集，不复制 OpenAI 宠物资产。`apps/desktop/web/pet-cat.svg` 是可编辑源图，PNG 是各客户端共享的运行资源。

Windows 保留原生无激活入口，使用带预乘 Alpha 的位图合成；Linux 使用透明 Tauri WebView；macOS 使用非激活 NSPanel。模式、位置等是本机偏好。

## 自动验证

- Rust 核心：状态优先级、并行等待关联、错误事件、动画边界与减少动画；完整核心回归。
- Windows：原生 PNG/Alpha/DPI 测试，真实桌面点击、焦点、穿透、固定、菜单和面板重建；`scripts/test-windows-panel.ps1 -LegacyCapsule` 验证旧入口。
- Windows/Linux 浏览器：八种行为截图、动作推进、重复轮询、减少动画、高对比、点击、键盘、拖动及模式切换；完整 UI 回归。
- macOS：Swift 客户端构建及原生契约测试，`verify-pets.swift` 验证动画帧与减少动画。
- CI：`core-native.yml` 在三种 OS 上运行核心测试和 macOS 原生测试，`desktop.yml` 在 Windows/Linux 上运行共享检查、UI、Tauri 测试与安装包构建。无可用输入桌面时 Windows 交互脚本明确报告 `not-run`，不当作交互通过。

macOS 手工拖动、多显示器实际切换、Linux 不同桌面合成器尚需发布前人工验收；浏览器模拟不等同于这些桌面环境的实机测试。
