# Qoder 与 Linux 桌面近期提交审查（2026-10-21）

审查范围：`008dade` 至 `f640e1a` 的 Qoder 身份识别、环境配置、历史状态恢复、Windows 编译修正，以及 Linux 原生桌宠、StatusNotifier 托盘、面板与安装包改动。以 `f640e1a` 为修复基线；此前 main 的核心与桌面 GitHub Actions 均已成功。

## 发现与修复

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| shell 配置读取失败被当成空文件 | 本地遇到非 UTF-8 内容、远端遇到权限等读取错误时，可能覆盖用户原配置 | 只有文件不存在时才创建；其他读取错误保留文件。补充内容、权限和幂等性回归。 |
| 临时文件名只含 PID 与秒级时间 | 同进程同秒写入可能碰撞；手写重命名也没有复用项目现有的跨平台替换实现 | 使用 `NamedTempFile`，保留目标权限并原子替换，失败时自动清理临时文件。 |
| 状态密钥绑定压缩变量名 `zMt` | Fedora 已安装的 qodercli 1.1.74 使用 `Zjt`，真实历史状态无法恢复 | 从 32 字节 Buffer 字面量提取候选密钥，通过 AES-GCM 认证确定匹配项；本地和 SSH 收集器保持一致。 |
| 密钥数组跨读取分块时丢失 | 标记本身没有跨块、数组内容跨块时漏读密钥 | 保留完整数组所需的尾部，覆盖标记、数字与结束符跨块的回归。 |
| 密钥缓存没有区分二进制 | 切换来源目录或升级 CLI 后可能继续使用旧密钥 | 缓存同时检查候选路径、大小和修改时间；补充不同二进制与升级回归。 |
| 状态写入没有复查当前来源 | 读取/解密期间暂停、删除或重绑定来源后，旧扫描仍可能写入状态或补偿记录 | 在写事务内复查来源与主机配置，读取同一事务中的已采集用量；覆盖本地及远程暂停后的拒写行为。 |
| 相同补偿记录每次扫描都更新 | 不变的历史反复触发每日用量修订和缓存失效 | UPSERT 仅在有效数据或计价发生变化时更新；验证重复扫描不增加用量修订号。 |
| 远程合法 JSON 的错误结构未隔离 | 单个数组形态的 state.json 可以中断整个历史收集器 | 验证对象结构、隔离错误文件并继续其他会话；补充同时存在有效/无效状态的回归。 |
| Linux D-Bus 托盘仍要求 AppIndicator | 无此动态库时错误回退；Tauri 全平台 tray-icon 特性还会重新注入安装包依赖 | 移除库探测与显式运行依赖，通过平台配置显式启用 Windows/macOS 的 native-tray，Linux 保留 ksni；不使用默认托盘特性，避免 Tauri CLI 打包阶段重新注入依赖；同步清理 CI 开发依赖。 |
| Linux 面板导航继承侧栏收起内边距 | “服务器”在真实截图中折成两行，顶部高度增加 | 限定面板按钮内边距、居中与单行显示；补充 450px 面板、侧栏收起及较大字宽下的布局回归。 |
| XWayland 自动选择限定 GNOME | KDE 等 Wayland 环境也需要绝对定位，却未启用兼容后端 | 可连接 XWayland 时选择 X11；显式 GDK_BACKEND 仍优先。测试脚本增加桌面环境标识参数。 |

密钥只用于内存中的认证解密；没有写入测试报告或日志。实机历史测试使用独立临时数据库，原始会话文件保持只读。

## 验证

- macOS：完整核心测试 460 项通过、4 项原有忽略；核心严格 Clippy、共享检查、Qoder 浏览器身份/表单回归通过。
- macOS Tauri：29 项测试通过，严格 Clippy 通过。
- Fedora 44 x86_64：完整核心、共享检查、Qoder 定向回归、Linux Tauri 测试与严格 Clippy通过。
- 真实 Qoder 历史：本地恢复 4 份状态并生成 4 条补偿记录，无问题报告；重复扫描的每日用量修订号不变。SSH Python 收集器另验证相同机器的真实状态。
- 原生窗口：缺少 AppIndicator 库的进程夹具下完成 100 次托盘开关、600 秒动画与桌宠区域录屏，2320 帧采样，无黑帧或透明角闪烁；最终去除 Tauri Linux 托盘特性后另完成 100 次交互和 60 秒录屏。Xvfb/KDE 环境标识下完成 100 次桌宠点击、外部点击与 Esc，及 60 秒动画。
- 最终 release 二进制另完成 100 次原生托盘开关；DEB/RPM 依赖检查确认无 AppIndicator，两个 ELF 无符号表且没有内嵌 Windows 字体。AppImage 打包时 Fedora 到 GitHub 的运行时下载超时，改由宿主从同一官方 AppImage type2-runtime 地址下载并通过 `LDAI_RUNTIME_FILE` 提供；没有改动系统代理。
- 最终三个安装包通过检查：DEB 21.18 MiB、RPM 15.24 MiB、AppImage 126.69 MiB。依赖检查已纳入 `check-linux-package-size.py`，会拒绝重新引入 AppIndicator 的 DEB/RPM。
- 最终安装包验证结果见本次 `.local/review-20261021/` 证据目录；构建在 Fedora 的隔离源码目录完成，复用已有编译缓存。

非 GNOME 测试使用 Xvfb/Openbox 加 KDE 环境标识，验证后端选择与交互；不等同于 KDE 实机验收。Qoder 在线身份/额度请求仍由已有模拟控制协议与浏览器回归覆盖，本次实机 Qoder 验证针对历史读取和解密。Fedora 生成的安装包用于验证，不作为 Ubuntu 22.04 通用 glibc 兼容基线。
