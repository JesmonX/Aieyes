# 限额体验与整周价值估算 · 2026-10-05

## 本轮行为

- macOS 的 agy 卡片按模型组排列，5h / 7d 并列，默认紧凑摘要。展开显示更新时间、各窗口重置时间和说明。错误不随折叠隐藏；Windows/Linux 使用同样分组。
- 限额区“调整账户顺序”支持拖动和上下移动，保存后同步面板和详情。排序单独持久化，不覆盖设置草稿；账户改名、查询失败和筛选不会改变已保存顺序，新账户追加。
- 应用内、macOS 菜单栏、Windows/Linux 标题栏、托盘和悬浮球复用 `render-icon.swift` 生成的图形。菜单栏使用无底色模板版本，实时状态用独立标记，品牌绿点不表示运行状态。
- 保留透明材质，增加折叠弹簧过渡、限额条数值过渡和排序位移动画；仅响应用户主动设置的系统减少动态效果偏好。

## 使用整周估值

在支持的账户卡片中点击“估算整周价值”，选择 7d 窗口和用量来源，确认采样期间这些来源只使用该订阅，且其他设备用量也已纳入，然后开始。建议开始后新建会话。结束按钮会同步用量、刷新限额并保存结果。

**整周 API 等价价值（USD） = 样本 API 等价成本 × 100 ÷ 消耗额度百分点。**

仅显示整周价值；至少消耗 5 个百分点，所有纳入 Token 有价格且区间可匹配时才输出数值。使用现有模型映射和输入、输出、缓存读取、缓存写入价格，推理 Token 不重复计价。结果代表本次模型组合，不代表可兑换余额或保证可使用的 API 金额。结束后的价格依据固定；计算依据包含区间、来源、额度消耗、成本、计价覆盖和价格快照。

自动历史统计仍照常运行。功能默认没有活动采样，须明确开始；关闭窗口不结束。应用重启后恢复状态，在下一次实时查询中核验额度周期。查询或用量采集失败、来源配置变更、额度回升、重置时间变化及正常周期结束会进入待确认状态，保留最后有效区间。确认后开始新一段，各段不拼接；也可以直接结束并保存有效段，即使原来源已删除。

### 归因与支持边界

- 数据源关联账户、当前登录方式、`model_provider`、会话创建账户以及日志附带限额，均不是逐次订阅计费证明。Codex 的模型提供方只作为证据保存；不凭 `openai` 判定订阅。
- 标准化导入记录可附带 `billing: {"category":"api"}` 或 `subscription`；明确的 API 用量不计入估值。其余历史默认未知，仅在明确确认的手动采样范围内纳入。
- Codex 首次累计用量需已知会话起点；后续累计差值保存前一事件时间。跨起始边界或没有可确定起点的累计值不输出有效估值，不将整段历史计入新采样。
- 当前支持具有可采集用量、独立 7d 窗口的账户，以及 Claude 的总体 7d 窗口。重叠子额度池没有模型映射时不估算。agy 查询仅提供限额，当前没有可供估值的 Token 历史与组归属，因此保留紧凑额度展示，不放置无效估值入口。
- 若用户混用中转或有未采集设备，无法可靠拆分的用量仍可能影响结果。两次采样之间发生且未留下可观测变化的重置无法保证识别；界面要求用户确认采样条件，不宣称自动精确归因。

## 接口与兼容

共享 Rust 核心提供 `quotas.order.set({keys})` 和 `quotaEstimates.start/stop/get/list/restart`。开始参数为 `accountKey`、`windowId`、`sourceIds`、`confirmed:true`；结束/读取使用 `id`；重开使用 `id`、`confirmed:true`，可覆盖来源选择。返回记录包含状态、区间、计算值与依据。dashboard 增加 `quotaOrder`、`quotaEstimates`。

SQLite 增加限额历史与采样表，保留现有事件、配置、去重和价格表。旧事件的归因和区间默认未知，旧窗口没有 ID 时继续用名称识别；开始采样时可匹配旧名称并升级到实时窗口 ID。来源配置只保存比较用摘要，不在采样记录中复制命令或凭据。
