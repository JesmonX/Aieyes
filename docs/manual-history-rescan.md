# 手动全量重扫历史记录

2026-10-11，应用版本 0.1.29。

在 macOS 和 Windows/Linux 的「设置 → 通用 → 历史记录」点击「全量重扫」，确认「开始重扫」后执行。启动、定时刷新和普通「同步记录」继续增量读取，不会自动触发全量重扫。

重扫从头读取所有已启用、所在服务器也已启用的数据源，包含本机 JSONL、Codex 归档日志、Antigravity 会话数据库和 SSH 历史。DeepSeek 余额来源不参与历史重扫。暂停或已删除的数据源不会被重新启用。

已有历史、冻结价格和来源归属会保留。重读得到稳定身份后，同一归属范围内可确认的重复哈希会原子合并，历史总量和成本随之纠正；重复执行不会再次累计。日志缺失时保留旧记录，无法证明是否重复的记录不猜测合并。

执行中显示状态并阻止重复启动；完成后刷新概览并显示结果。来源不可读取或记录损坏时显示具体失败信息，已成功导入的部分保留。点击状态图标可查看失败来源并手动重试；重试仍使用完整重读。

核心提供独立手动方法 `sources.rescan`，接受与 `sources.scan` 相同的 `sourceId` / `sourceIds` 可选筛选。普通方法不接受全量开关。全量重扫绕过当前读取位置，成功批次按原有事务方式更新读取位置；不预先删除游标、事件、价格或历史来源关系。

SSH 历史传输按等待下一批统计的时间判断超时：连续 45 秒没有下一批数据时停止，并保留已提交进度。持续收到数据的重扫可以超过 45 秒；本地批次入库耗时不占用远端等待时间。大历史的完整重扫可能需要数分钟。

开发版构建：

```sh
AIEYES_OFFLINE=1 sh scripts/build-macos.sh debug
```

输出为 `dist/Aieyes.app`，调试数据仍使用项目 `.local/app/`。构建不会替用户执行全量重扫。
