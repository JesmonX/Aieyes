Reviewed the current 0.1.1 desktop frontend, Windows configuration, native window handling, and settings persistence. The light and dark browser previews have a consistent visual hierarchy, readable primary values, and working navigation. The main usability concerns are settings failure recovery, dialogs, and automatic refresh. This is a source and Chromium review with mocked IPC data; Windows/WebView2, Mica, installation, and real account/SSH integrations were not exercised.

Findings are ordered by impact. P1 means address before relying on the affected flow; P2 means a reproducible usability defect.

1. **[P1] A rejected settings save changes the running configuration and can block unrelated saves.** In Settings → General, enter an Agent interval of `1` second and save. Core validation rejects it, but `state.settings.refreshSeconds` remains `1` while persisted settings remain `300`. Then disable a host: the request includes the same invalid interval, fails again, and the checkbox remains unchecked even though the host is still enabled on disk. Connection, toggle, removal, and mapping handlers also mutate shared state before persistence. Build a draft, validate and save it, then replace committed state only after success; restore controls on failure. Sources: [general form and toggle handlers](../apps/desktop/web/app.js#L151), [interval validation](../crates/core/src/store.rs#L160). Reproduced with the core's interval rejection modeled in the browser fixture.

2. **[P1] Removing an account can delete its imported history without explaining that consequence.** The account removal button immediately removes the account and sets linked sources' account IDs to empty. Saving this reassignment deletes those sources' event associations, imported events without another source association, file-import markers, and source status. Records can be recovered by rescanning only if the original logs are still available; archived-only history can be lost. Explain the effect before committing removal and provide a way to retain history or undo the operation. Sources: [account removal](../apps/desktop/web/app.js#L146), [source reassignment cleanup](../crates/core/src/store.rs#L178). Established from source; no real account was removed.

3. **[P2] Dialog validation errors appear behind the dialog.** Open Add Account, leave its name blank, and save. The dialog remains open while `Error: 请输入账户名称` is written into the page-level message under the blurred backdrop. That message is outside the modal's accessible, interactive content. The same catch path handles host, data-source, and price errors. Put an error status inside the dialog, associate field errors with their inputs, and focus the invalid field. Sources: [editor error handler](../apps/desktop/web/app.js#L172), [message and dialog markup](../apps/desktop/web/index.html#L18). Reproduced; [screenshot](../.local/ui-previews/review-modal-validation.png).

4. **[P2] Open dialogs block the custom Windows title-bar controls.** The title bar is outside the HTML dialog. `showModal()` makes that area inert, and pointer hit-testing at the minimize button reaches `#editor` instead. Users must dismiss the editor before clicking minimize, maximize, or the main-window close button. Retain usable native window controls during editing through native chrome or an accessible modal design that leaves window controls interactive. Sources: [title bar placement](../apps/desktop/web/index.html#L6), [modal opening](../apps/desktop/web/app.js#L172), [window controls](../apps/desktop/web/desktop.js#L29). Reproduced in Chromium; verify the resulting fix in WebView2.

5. **[P2] Live quota polling never starts until the user manually refreshes.** `lastQuota` starts at zero; startup loads the dashboard and scans history but never calls `quotas.refresh`. The timer requires a nonzero `lastQuota`, so restarting the app resets polling to inactive. This especially affects agy and DeepSeek, whose live values are not imported by the history scan. Start an initial quota refresh for configured, enabled accounts and track quota scheduling independently of manual actions. Sources: [initial state](../apps/desktop/web/app.js#L14), [startup and timer](../apps/desktop/web/app.js#L258), [history exclusions](../crates/core/src/lib.rs#L101). Three controlled scheduler ticks with a configured quota account produced zero quota refresh calls.

6. **[P2] Dashboard refresh collapses expanded daily details.** Expand the daily table and a day, then click Sync Records or allow automatic synchronization. `loadDashboard()` recreates the entire Agent content; both expanded sections close. The probe measured two expanded sections before reload and zero afterwards. Preserve expansion and focus across refreshes, as the server page already preserves its metric expansion. Sources: [dashboard reload](../apps/desktop/web/app.js#L24), [Agent rendering](../apps/desktop/web/app.js#L68), [server expansion preservation](../apps/desktop/web/app.js#L104).

7. **[P2] Canceling quick setup leaves a persistent empty account.** Click Settings → Accounts → Connect agy, then cancel the data-source editor. The account is saved before the editor opens, so cancel leaves one account and zero sources. DeepSeek uses the same handler. Save the account and source together when setup is submitted, or explicitly explain that the account has already been created. Source: [quick setup](../apps/desktop/web/app.js#L143). Reproduced for agy.

The current usage flow is:

- Click the floating ball to open Agent Overview; drag it to move it; use right-click or Shift+F10 for its menu. The ball reports enabled local Codex log state, not every provider or remote session. Closing the main window keeps the app running; use Exit Aieyes to terminate it. Display mode and position reset are under Settings → General.
- For Codex or Claude, create an account when quota tracking is needed, then add and associate a data source. A history-only source can use No Account / API. Sync Records imports history; Refresh Quotas starts live querying. Today is the initial summary range, with a separate seven-day trend.
- For a remote data source, first add a server under Settings → Servers and then select it as the source's location. Server monitoring uses SSH; the remote server needs Python 3. In the host editor, Read Devices populates grouped selectors. Search limits All, Clear, and Invert to matching devices.
- API-equivalent cost is an estimate using configured prices, rather than subscription billing. Missing prices have an explicit repair entry. Live quotas and history statistics are separate.
- The Windows connection label “System Proxy” needs clarification: the code explicitly reads macOS system settings, while the Windows path leaves proxy selection to the client/environment. For a configured local proxy, use Custom and enter its address. Source: [proxy handling](../crates/core/src/network.rs#L5).

Further interface improvements: provide direct Add Data Source / Add Server actions in empty states; explain the account/source relationship during setup; increase small helper text where feasible; and indicate that closing sends the window to the background. The installer offers Chinese and English, while the current application strings are Chinese. These are design observations, not runtime failures.
