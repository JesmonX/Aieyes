# 当前 Release 配置下的 CPU 与交互性能排查

本次以 macOS 的可见界面、点击处理、切页、刷新和滚动为重点。性能诊断使用独立脚本和驱动；产品代码仅按追加要求调整 CPU、内存卡片等高，尚未应用性能修复。原有未提交修改保留。

## 数据与测量边界

- 安装版本为 0.1.52，构建号 53，核心 `hello` 确认版本与 v0.1.52 契约一致。当前工作区为 `7132858` 加本次开始前已有的未提交工作。
- SQLite 在线备份包含 74,818 条用量、125,078 条来源关联、1,753 条文件游标、126,552 条额度历史、61 条估值和 2,324 条价格历史，数据库约 329 MiB。
- 查询失效微基准仅在副本的一条事件上累计增加 0.00002 USD；回放响应在该基准之后录制，数据条数与配置保持不变。原始数据库没有接受该测试写入。
- 使用 6 个账户、18 个来源（15 个启用）、4 台主机（2 台启用）、466 个价格模型和原有筛选、展开、桌宠偏好。主窗口恢复为保存的 1307×900，主题按实际配置为深色。
- 每个驱动使用独立、可写的偏好域和独立数据库。网络、额度、SSH、授权和定时任务执行使用回放；真实核心模式只放行本地查询。副本及含私人配置的原始响应保留在被 Git 忽略、权限受限的 `.local/release-interactions-20261021/`。
- 初期使用覆盖域的预检会阻止偏好正常更新，相关 `pilot-*`、`scroll-preflight`、`smoke-workspace` 结果不作为最终界面结论。修正前的浅色对照和被主动终止的 `workspace-default` 也不混入正式矩阵。
- 菜单摘要最初误录为完整估值历史，复核后改为生产请求使用的 `estimateHistory: "display"`：菜单显示 3 条额度估值、1 条点数估值，完整详情历史仍在单独响应中保留。相关旧 UI 结果已移入 `excluded-full-estimate-menu/`，不作为最终量化依据；后续复用样本必须匹配当前 fixture 的 SHA-256。
- 原生驱动使用生产视图与处理函数，以 `-O` 编译。版本对照来自 v0.1.52 源码和当前工作区，不声称它们与已安装可执行文件逐字节相同。另有复制并重新签名的实际安装包入口探测。
- 交互驱动挂载生产主窗口、菜单标签、桌宠和面板视图；菜单项尺寸固定，未复刻完整生产菜单控制器的尺寸更新。会话与外部刷新使用固定回放，不等同于真实活动会话、网络波动及远端变化；实际安装包入口与原始进程采样另列证据。
- UI CPU 使用 `getrusage(RUSAGE_SELF)`，仅计驱动进程，不含 WindowServer 和核心子进程。响应测量先让出主线程约 1 ms，再显式执行布局与显示；另有 5 ms 心跳观察主线程延迟。驱动本身会增加开销，表中耗时是同一驱动下的诊断指标，不能直接当作真实鼠标到屏幕延迟或发布版绝对 CPU。
- 滚动向原生滚动视图发送连续像素事件；SwiftUI 忽略事件时，以每帧 48 px 的原生 clip-view 位移回退，并记录回退次数、实际位移和容器是否保留。间隔是主线程步进响应，包含每帧约 16.7 ms 等待，不是屏幕实际刷新率或硬件触控板延迟。
- 主机数和采样间隔保持实际配置，指标响应按本机核心数合成；远端硬件细节、实时网络和真实 SSH 性能没有复刻。服务器滚动另行展开 CPU 明细以产生可滚动内容。

## 已定位的调用链

### 滚动位置持久化触发无关界面更新

`ScrollMemory.Coordinator` 在每次 `NSView.boundsDidChangeNotification` 中立即调用 `UserDefaults.standard.set`。连续滚动会把原本的几何变化变成持续的全局偏好通知。

`PetWindowController` 订阅所有偏好变化并执行 `sync()`，其中无条件赋值 `live.petVisible`；该字段属于 `@Published`，同值赋值也发布。`SessionStrip` 等视图直接观察整个 `LiveSessionState`，菜单栏控制器也订阅该对象和偏好通知。调用栈以 SwiftUI/AttributeGraph 布局、原生视图测量为主，既有全局观察链路会放大本应只影响滚动位置的更新。

诊断控制仅在独立进程中拦截 `view.scroll.v2.*` 的写入，其他偏好、数据、刷新和生产视图保持原行为。报告记录实际拦截次数，避免把没有触发控制的样本当成因果证据。

### 隐藏页和重复发布是进一步的放大路径

`MainWindowView` 在同一个 `ZStack` 保留所有监测页，用透明度、命中测试和可访问性控制隐藏。隐藏页的模型观察有门控，但视图仍在布局树中；布局采样能看到 `RootView`、`BalancedGridLayout` 和 `FlowLayout`。只挂载当前页的 20 次独立对照将分析页切换 CPU 中位数从约 2,414 ms 降到 2,053 ms，仍然存在秒级开销；这支持将其列为放大因素，而不是唯一根因。该小幅差异来自串行测量，不作为严格的整应用性能提升保证。

无变化 `reload()` 仍会发布加载状态、错误清空、多个 dashboard 字段等状态。它与后台真实变更需要分开看；请求命中缓存不等于界面没有更新。

### 日期格式化存在可量化的次要开销

`Format.date` 每次创建并配置 `DateFormatter`。以副本完整估值历史中的 158 个真实时间戳做 20 次同输出对照，逐次创建约消耗 20 ms CPU，复用配置后的格式器约 0.3 ms。完整历史用于构造负载，当前菜单显示投影的条数更少，不能把这 20 ms 当作每次切页的实际成本。该实验说明存在可优化开销，不把微基准倍率当成整应用收益，也不把它当作数百毫秒滚动停顿的唯一解释。

### 真实本地历史扫描

从登记的本地文件中复制了 891 个唯一文件，来源统计合计约 613 MiB；保留 6 个可用启用来源，远端来源、额度和 API 账本关闭。使用相同文件副本、路径与游标重映射后的数据库，两版本各执行 20 次 `sources.scan`。

| 扫描 | 安装核心 0.1.52 (ms) | 工作区核心 (ms) |
| --- | ---: | ---: |
| 首次 | 1,210 | 8,853 |
| 后续中位数 | 68 | 50 |
| 后续 P95 | 405 | 62 |

来源错误与部分失败均为 0。单独重建副本、逐来源复核显示，工作区首次 Codex 扫描约 8.87 秒，读取约 505.5 MB；安装版约 0.34 秒，读取约 6.4 MB。快照中的 Codex 游标解析版本为 6，工作区为 7；`import::scan_file` 在版本不匹配时从头重读，解释了这次升级扫描的一次性成本。Qoder 同样存在解析版本变化，首次约 0.33 秒并读取约 7.6 MB。这些是后端真实工作，应与回放刷新下的 UI 开销分开。

文件内容取自数据库快照之后，确认时两版本均新增 274 条 Codex 事件；不能称作完全无变化的首次扫描。此实验仅涵盖仍存在的登记本地文件，不复刻新文件发现、未登记的附属状态、丢失历史、远端扫描或真实网络；原生数据库在线备份也可能改变文件指纹。来源级复核位于 `cold-scan-breakdown-confirm/report.json`。

## 修复优先级与验收建议

1. **滚动持久化**：滚动中只更新内存坐标，结束滚动或短暂静默后合并写入；分离恢复位置与用户滚动，关闭/退出时保存最后位置。保持现有滚动位置记忆，不以移除该功能作为产品修复。
2. **偏好观察与同值发布**：桌宠仅响应它使用的偏好变化；写入 `live.petVisible` 前比较值。会话栏使用自身所需的状态投影，菜单栏尺寸计算只在显示内容变化时进行。
3. **刷新与隐藏页**：减少逻辑上未变化的 dashboard 发布，保留编辑和滚动状态的同时让非活动页退出昂贵布局。当前页控制是诊断实验，不能直接当作保留所有编辑状态的完整实现。
4. **格式化与布局缓存**：复用配置后的格式器，明确时区/区域变化时的失效；评估自定义布局重复测量的缓存，优先处理有栈和对照支持的开销。

修复验收应重新运行相同副本和场景，检查滚动中的 CPU、超过 33 ms 的步进间隔、刷新到达时的停顿、容器和位置保留、焦点及未保存输入。持续高负载与操作瞬时峰值分开报告。真实硬件滚轮/触控板、肉眼可见的合成效果和 Windows/Linux 原生验收仍需分别验证。

复现入口：

```sh
python3.14 scripts/profile-release-interactions.py prepare --output .local/my-interaction-audit
python3.14 scripts/profile-release-interactions.py build --output .local/my-interaction-audit --ref v0.1.52
python3.14 scripts/profile-release-interactions.py build --output .local/my-interaction-audit --ref workspace
python3.14 scripts/profile-release-interactions.py run --output .local/my-interaction-audit --ref workspace --run-name workspace --repetitions 20
python3.14 scripts/profile-release-interactions.py run --output .local/my-interaction-audit --ref workspace --run-name no-scroll-writes --repetitions 20 --only scroll --no-scroll-persistence
python3.14 scripts/profile-release-interactions.py summarize --output .local/my-interaction-audit
```

需 macOS、可连接的 WindowServer、Swift 工具链和已有的 Sparkle 缓存；准备前先构建当前 `target/release/aieyes-core`。测试偏好域在退出时清理；会话中断后的完整结果可由矩阵入口恢复登记，未完成的额外版本场景已标记为用户取消。隔离性回归为 `scripts/test-profile-release-interactions.py`。

## CPU 与内存卡片等高

macOS 的资源摘要改用同一 `GridRow`，卡片背景填满行高，并将整行约束在内容所需高度；内存的容量说明换行时，CPU 卡片随该行增高。Web 移除卡片的顶部自对齐，改为拉伸且内容保持顶部排列，并统一隐式行高，窄屏纵向排列时也保持等高。

macOS 增量构建通过，320/640 pt、深浅外观的生产摘要截图已核对；Web 既有 `test-server-summary.cjs` 增加同一行 CPU/内存高度相等断言，主界面和浮动面板的宽窄、深浅主题测试通过。卡片改动没有混入已固定的性能对照源码与二进制。

后续实施顺序与验收门槛见 [CPU 优化计划](cpu-optimization-plan-2026-10-21.md)。
