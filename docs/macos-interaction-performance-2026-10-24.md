# macOS 点击与滚动性能优化（2026-10-24）

本轮针对主窗口、菜单栏面板及刷新到达时的交互；保留原有功能、外观、桌宠动画、草稿、展开项与滚动记忆。安装版仍为 0.1.57（58），没有替换 `/Applications/Aieyes.app`。

## 定位与改动

- **隐藏页面布局**：原主窗口把所有监测页及已访问的价格页留在同一布局树中。现在按稳定页面 key 懒创建并保留独立宿主，仅挂载活动页；切页前保存滚动位置，重新进入复用 SwiftUI 状态、原生输入框和可恢复的焦点。正常退出继续收尾。
- **布局重复测量**：网格与流式布局使用有界测量缓存，在放置阶段复用测量结果；子项、字体、宽度与布局参数改变时失效。分析页的两个图表不再分别创建横、竖两份，改为单份自适应布局，保留 818 pt 的排列临界宽度。
- **刷新范围**：页面投影只比较本页的 dashboard、筛选、主机或模型选项；服务器采样不会使分析页失效。分析筛选改为一次完整值发布与一次偏好保存，保留请求合并、独立查询通道和旧响应丢弃。刷新 worker 退出统一清理加载态。
- **主线程计算**：dashboard 缓存体积检查的 JSON 编码移到后台，返回后重新核验请求与修订。图表的模型集合、坐标标签与每日分组使用有界不可变缓存，悬停仅在日期实际变化时更新。
- **本地化与格式化**：有效语言缓存并响应偏好通知，用修订避免并发旧通知覆盖；每次文案查询不再重新读取整个进程环境。翻译结果缓存有界，包含未匹配结果；无参数文案跳过占位符处理。复用日期格式器，维护时区、区域变化与并发安全。主机默认字段键与翻译标签分离，保存格式不变。

宿主之间只传递公开的外观与布局环境；系统辅助功能值由各原生宿主继承。整份复制 SwiftUI 环境会把私有渲染上下文带入另一个图，开发中的控件渲染回归已被测试发现并修正。最终验证包含实际按钮、输入框与布局，不能以空白界面的低开销作为收益。

Rust/Web RPC、配置版本和业务数据库格式没有本轮新增变更；119 项契约检查通过。原有未提交估值功能修改保留，测试包包含当前完整工作区。

## 对照方法

当前机器为用户报告的 Ryzen 5 5600H / Renoir 核显，macOS 26.7.1，x86_64。本机识别到 Metal 支持；真实安装进程的短时采样出现 SwiftUI 布局、界面提交、网格测量和本地化调用。它们是调查依据，不证明显卡或驱动完全没有影响。本机 SwiftUI Instruments 记录没有获得 SwiftUI 事件，不将此当作正常证据。

SQLite 在线副本为 423,321,600 字节，含 79,492 条用量、149,409 条额度历史；7 个账户、18 个来源、4 台配置主机、496 个价格模型。修改前后均以 `-O`、whole-module 编译生产对象，并用相同驱动、固定响应与偏好回放；每项 5 轮，首次样本保留。数据库及含私人配置的原始产物留在忽略目录 `.local/macos-performance-20261024/`。

回放对照暂停无关周期任务，保留实际原生视图、菜单、桌宠与显式刷新。它测量 UI 工作，不包含真实 SSH、网络额度耗时。CPU 为单轮 UI 进程累计 CPU 时间，非整机百分比，也不包含核心子进程或 WindowServer。

首反馈是现有驱动在约 1 ms 主循环让出后强制布局、显示的诊断指标；滚动发送连续像素事件，必要时使用原生 clip view 步进。步进 P95 包含每步约 16.7 ms 的等待及边界步骤；停止后另等待 350 ms，将延迟保存及后续渲染计入 CPU。两者均不是物理输入到屏幕的延迟或实测刷新率。

服务器滚动明确切到全部主机并展开已启用主机，完成后恢复原筛选。旧驱动在保存的单主机筛选不溢出时可能选择隐藏页；相关早期场景不作最终对照。最终使用同一修正驱动重新测量两版，并验证实际位移、滚动容器及命中目标保持。

## 性能结果

下表均为各轮指标的中位数；步进 P95 先逐轮计算，再取五轮中位数。

| 场景（各 5 轮） | CPU 前 → 后（ms/轮） | CPU 降幅 | 首反馈前 → 后（ms） | 步进 P95 前 → 后（ms） |
|---|---:|---:|---:|---:|
| 进入分析页 | 4169.6 → 293.5 | 93.0% | 413.8 → 152.7 | — |
| 进入价格页 | 4213.5 → 220.8 | 94.8% | 1348.7 → 63.3 | — |
| 打开面板 | 2698.8 → 209.4 | 92.2% | 780.1 → 17.3 | — |
| 切换全部 Agent | 4029.7 → 395.4 | 90.2% | 2054.9 → 303.8 | — |
| 无变化刷新分析页 | 1677.6 → 35.6 | 97.9% | 738.9 → 15.1 | — |
| 分析页滚动 | 524.4 → 487.5 | 7.0% | 21.4 → 11.6 | 18.1 → 17.7 |
| 服务器滚动 | 2171.5 → 316.6 | 85.4% | 32.9 → 6.3 | 58.2 → 17.9 |
| 面板纯滚动 | 203.3 → 256.2 | -26.0% | 4.4 → 3.9 | 17.9 → 17.7 |
| 面板滚动中刷新 | 5648.8 → 346.3 | 93.9% | 4.7 → 3.2 | 737.4 → 23.2 |
| 刷新与切页连点 | 6318.6 → 410.2 | 93.5% | 883.7 → 171.5 | — |

主要点击、切页与刷新场景的 UI CPU 降幅约 90%–98%；滚动中刷新由每轮约 5.65 秒 CPU 降到 346 ms。该场景五轮步进 P95 为 31.9 / 19.2 / 22.4 / 23.2 / 25.7 ms，均小于 33 ms；超过 33 ms 的步骤分别为 3 / 1 / 2 / 0 / 0，容器与命中目标全部保留。首次该轮心跳仍记录到约 194 ms 的最大主循环延迟，不能解释成完全没有停顿。

100 ms 首反馈目标没有全部达到：分析页中位约 153 ms、筛选约 304 ms、刷新切页连点约 172 ms；面板首次打开约 293 ms，热切换中位约 17 ms。没有丢弃首次样本或改变门槛。纯面板滚动 CPU 从约 203 ms 增至 256 ms（约 +53 ms / +26%），虽然步进 P95 仍约 18 ms，也不能声称所有场景 CPU 都下降。这里保留这项残余开销及后续实机验收边界。

- 本机较早的完整原生套件通过。最终干净检出的模型、会话、配置、价格、唤醒、更新及状态回归通过；动画窗口可见性因本机锁屏中止（已只读确认系统锁屏标志），没有放宽或跳过该检查。GitHub macOS 原生任务的最终结果作为提交后的独立验收。
- 性能对照保留了原有未提交估值修改；提交前另在干净检出只应用本轮补丁验证，不把那些原有改动混入本轮提交。

优化编译包为 `dist/Aieyes Performance.app`，应用标识 `app.aieyes.performance`，数据目录 `.local/macos-performance-20261024/app-data`。原有 `dist/Aieyes.app` 与安装版均未替换；没有推送或发布。完整源码哈希、驱动哈希与输入哈希记录于本地报告，可核验性能驱动除诊断控制外与最终生产源码一致。
