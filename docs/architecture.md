# 技术设计

## 建议架构

2026-10-03 实现进度：共享核心先集中在 `crates/core` 内按模块分层。macOS 外壳已实现；Windows/Linux Tauri 外壳已通过原生 CI 编译与安装包生成。下述多 crate 目录为后续拆分目标。当前能力与未完成项以 [README](../README.md) 为准。

macOS：SwiftUI + AppKit，原生状态栏、弹出面板、设置与详情窗口。菜单栏用 AppKit 精细管理锚点、焦点和固定窗口行为；统计页面使用原生图表与视图。

跨平台核心：Rust，负责采集、归一化、去重、存储、限额刷新、价格计算、SSH 调度和更新元数据获取。数据库使用 SQLite。

Windows/Linux：Tauri 桌面界面，共享同一个核心协议、配置模型与测试样例。Windows 默认使用透明置顶悬浮球，Linux 检测 AppIndicator / StatusNotifierHost 后优先使用动态托盘，不可用时回退悬浮球。显示方式与悬浮球位置保存在本机 `desktop.json`。Rust 独立线程每约 5 秒读取本机会话生命周期元数据并向两个窗口发出状态事件，关闭详情不影响监测。Windows NSIS 和 Linux deb/AppImage 已通过原生 CI 构建，目标系统图形交互与安装卸载验证尚待完成，详见 [平台说明](windows-linux.md)。

macOS 原生界面与核心使用随应用分发的子进程，通过带协议版本的 JSON-RPC/stdin/stdout 通信，不监听本机网络端口。Tauri 外壳直接调用同一个 Rust 引擎，使用相同的方法名、输入和输出模型。原始命令标准错误不进入 UI，连接故障映射为简洁的状态文案。

macOS 安装包包含核心可执行文件，Tauri 应用直接链接 Rust 核心；用户不需要预先安装 Rust、Node 或开发工具（查询已有 CLI 时仍需对应 CLI）。

## 核心实体

- `Provider`：Agent 类型、适配器版本、能力集合。
- `Account`：逻辑账号与凭据引用；凭据内容不进入普通配置与统计库。
- `Host`：本机或 SSH 主机、连接配置、监控选择。
- `Source`：某个主机上的某个 Agent 数据目录、关联账号及查询方式。
- `UsageEvent`：来源标识、原生事件标识、会话、模型、UTC 时间、归一化 Token、原始计数语义。
- `QuotaSnapshot`：账号、模型池、窗口长度、已用比例、重置时间、采集时间、查询来源。
- `BankResetSnapshot`：账号与来源明确提供的状态字段；字段未验证前保持接口扩展点。
- `PriceSnapshot`：模型 ID、价格维度、单位、币种、抓取时间、适用时间、来源。
- `MetricSample`：主机、设备/网卡/挂载点、UTC 时间、单调采样间隔、数值与单位。

用能力集合分别表示 `usageHistory`、`quotaWindows`、`bankResetStatus` 等功能。不能因为一个 Provider 支持历史导入，就假定它也能查实时限额。

## 历史导入与去重

日志文件增量读取，持久化文件标识、偏移与末尾未完成记录。识别轮转、截断、重复导入和一行尚未写完的情况。

优先使用来源的稳定请求/事件 ID 去重。没有稳定 ID 时，在明确作用域内使用会话、消息标识、事件类型和原始计数建立可追踪指纹；不可仅凭时间与 Token 数跨主机合并。

对于累计计数源，使用同一会话有序快照的差值；首次只有累计值时标记为汇总来源，不伪造逐次请求时间。计数回退、模型切换和缺少前序快照均需专门处理。

只有经过确认的账号关联与事件身份，才允许跨来源去重。同一会话的拷贝与真正的独立会话必须区分。

保存 Token 明细与价格快照引用。每日、模型、账号、主机聚合由基础事件生成，便于修正适配器后重建。

## 限额刷新

账号是轮询单位。多个页面与多个来源共用账号状态，合并并发请求。来源选择支持本机查询或通过指定 SSH 主机查询。

采用来源返回的重试提示、失败退避、超时与取消；前台手动刷新可以触发立即查询，同一账号的进行中请求仍复用。应用休眠后恢复时重新计算过期任务，不补跑所有错过的轮询。

历史日志读取权限与账号限额凭据分别管理。只为用户选择的来源读取相应数据，不枚举无关会话内容。

## SSH 执行

优先调用系统 OpenSSH，沿用已有身份、跳板与主机信任记录。主机首次信任流程展示实际指纹并由用户选择，不自动关闭校验。

连接参数作为进程参数传递；远端固定采集脚本通过标准输入发送。环境变量与路径按目标 shell 编码，不把用户配置拼接到本地 shell。用户前置命令本身是有意允许执行的脚本，单独管理与展示。

远程查询可选择临时帮助程序或内置脚本，按目标架构选择；部署可执行文件需在首次设置该数据源时明确展示具体路径与用途。首选能够利用现有 Agent 与系统工具的读取方式。

SSH 监控通过 `/proc/stat`、`/proc/meminfo`、`/proc/diskstats`、`/proc/net/dev` 等接口与文件系统统计采集，NVIDIA 使用可用的 `nvidia-smi`。具体格式通过样例与 Linux 实机验证，不假设所有命令始终存在。

CPU、磁盘和网络速率由两次有效采样的计数差计算。重启、休眠、连接中断、设备消失、计数回退后丢弃旧基线。

## 存储与资源

SQLite 保存配置引用、基础用量、价格、限额快照与聚合历史。凭据保存在 macOS Keychain、Windows Credential Manager、Linux Secret Service 对应的系统存储中；核心通过统一凭据接口访问。

建议服务器原始采样保存 24 小时，分钟聚合保存 30 天，小时聚合保存 1 年；用户可调整。Agent 日聚合长期保留，原始记录保留策略另设。

文件监视与增量游标减少重复扫描。主机任务设置并发上限；界面关闭时降低轮询频率，避免菜单栏工具持续占用 CPU。
