# 三端视觉审阅：Windows 为主（2026-10-28）

接续 Claude 会话 `5fe8ac4d-e8cf-4a8d-bb01-b03bb66c979d`。本次整理已有截图、实机读数和代码证据，范围是材质、配色、布局、卡片空间及控件质感；未修改产品代码。

## 结论

Windows 主窗口的基础视觉体系已经成立：背景、侧栏、内容卡片和控件有基本层次，浅色与深色都能维持统一的强调色和分类色。最需要先处理的是弹出层可读性，以及主窗口操作按钮偏小、折叠分组偏松造成的密度不协调。

建议保留当前主窗口的 Mica 取色、轻卡片、细描边和分类色。第一轮集中改善菜单与对话框，再整理操作行和分组间距。深色悬浮面板的灰度差异、焦点描边和 Agent 选择器属于后续视觉优化。

### V-01：弹出层可读性

最直接的证据是 [浅色下拉菜单](../.local/ui-review-2026-10-28/win/l-select-open.png)、[浅色 SSH 编辑器](../.local/ui-review-2026-10-28/win/l-dialog-host.png) 和 [深色 SSH 编辑器](../.local/ui-review-2026-10-28/win/d-dialog-host.png)。局部证据见 [菜单放大图](../.local/ui-review-2026-10-28/win/zoom/select-open.png) 和 [对话框透字放大图](../.local/ui-review-2026-10-28/win/zoom/dialog-ghost.png)。

基线中 `--overlay-fill-opacity` 为 `0.64`；Windows 的对话框、菜单等共用这一填充及 `blur(16px)`。页面遮罩另用 20% 暗色和 `blur(3px)`。本轮实时读取也得到对话框 `rgba(250, 250, 252, 0.64)` 和 `blur(16px)`。这些规则与实机透字现象相符；没有必要把问题归咎于整个 Mica 背景。

代码位置：[tokens.css](../.local/ui-review-2026-10-28/windows-baseline/tokens.css) 第 228 行；[windows.css](../.local/ui-review-2026-10-28/windows-baseline/windows.css) 第 37、40、103–111 行。

建议先用不透明或高遮蔽底色验证菜单文字能够独立阅读，再逐步恢复需要的透明感。菜单和大表单可以使用不同的填充强度；“提高模糊半径”是否有效必须用同一底层内容实测。验收场景至少包括浅深色、展开菜单覆盖文字、表单覆盖开关，以及关闭透明效果后的降级。

### V-02 至 V-06：尺寸、空间和控件质感

对照 [接入与账户](../.local/ui-review-2026-10-28/win/l-settings-integrations.png)、[机器与采集](../.local/ui-review-2026-10-28/win/l-settings-hosts.png)、[模型价格](../.local/ui-review-2026-10-28/win/l-settings-prices.png) 和 [定时唤醒](../.local/ui-review-2026-10-28/win/l-settings-wakeups.png)，问题集中在操作角色和密度，而不是缺少阴影或高光。

建议采用下列局部规格，再逐页检查：

| 元素角色 | 主窗口 | 悬浮面板 |
| --- | --- | --- |
| 页头、分区工具栏、新增操作 | 常规 32px | 按空间选择紧凑 28px |
| 行内编辑、低频辅助动作 | 紧凑 24px | 紧凑 24px |
| 对话框保存 / 取消 | 常规 32px | 编辑器沿用对话框规格 |
| 折叠标题 | 保持整行可点，压缩外层空白 | 保持紧凑分组 |

这里的高度是设计建议，并不表示所有 24px 按钮都存在命中故障。当前实心“保存”与次要“取消”已经有清楚的层级，应保留；不应把此前“主按钮不突出”的旧结论重复算作当前缺陷。

焦点证据见 [输入框放大图](../.local/ui-review-2026-10-28/win/zoom/dialog-focus.png)。基线 [controls.css](../.local/ui-review-2026-10-28/windows-baseline/controls.css) 第 35 行设置外轮廓和强调色边框，Windows 层又增加输入焦点阴影。SSH 操作分组见基线 [app.js](../.local/ui-review-2026-10-28/windows-baseline/app.js) 第 1530–1559 行；Agent 自动换行见基线 [workspace.css](../.local/ui-review-2026-10-28/windows-baseline/workspace.css) 第 208 行。

### V-07：主窗口与面板

对照 [深色主窗口](../.local/ui-review-2026-10-28/win/d-overview2.png)、[深色面板](../.local/ui-review-2026-10-28/win/d-panel.png) 和 [浅色面板](../.local/ui-review-2026-10-28/win/l-panel.png)。原截图已记录主窗口 Mica、面板 Acrylic；它们并不是相同的系统表面，不能要求像素完全相同。

视觉建议是减轻深色面板的大面积中灰底，使内容卡与窗口之间保持容易理解的层次。是否调整网页底色或原生回退仍需区分原因。本轮不宣称发现了 Acrylic 调用失败。

## 配色和材质中应保留的部分

- 浅色主窗口取样壁纸后略偏暖，当前截图中的偏粉、偏米色本身不构成主题颜色错误。
- 强调色用于选中、操作、额度；分类色用于 Provider 与 CPU / 内存 / GPU 等资源，角色基本可辨。
- 总览中只有一个账户时保留半行卡片和空白是合理的，无须为了铺满窗口拉伸卡片。
- 服务器摘要的资源分组、4px 进度条、细描边和较轻阴影已经形成一套样式，适合继续保留。
- 当前页头按钮基本对齐，主按钮已有实心层级，外观选择器列宽也已统一；不重复列入旧版审计的问题。

## macOS 对照

当前 SwiftUI 构建成功，随后使用隔离的合成数据生成原生布局快照。代表画面：[总览浅色](../.local/ui-review-2026-10-28/macos/workspace-agent-light.png)、[接入设置浅色](../.local/ui-review-2026-10-28/macos/workspace-settings-light.png)、[窄主窗口深色](../.local/ui-review-2026-10-28/macos/workspace-agent-small-dark.png)、[低高度面板深色](../.local/ui-review-2026-10-28/macos/workspace-panel-440-dark.png)。

macOS 的分组表面更平，额度卡染色更明显，使用系统字体和原生选择器。三端可以共享字号层次、间距和操作角色，保留各自的原生材质与控件机制。

接入页的多行 Agent 入口同样占据较多垂直空间，V-06 可以在两套实现中一起设计。macOS 把账户与折叠小节放在更连续的分组中，可作为 Windows 精简外层卡片的布局参考。现有快照不足以证明系统菜单、工作表材质和真实输入焦点已通过交互验收。

## Linux 对照与重构期间的证据限制

[浅色接入页](../.local/ui-review-2026-10-28/linux/linux-light-integrations.png) 中，设置卡仍使用比窗口更深的灰底；通用卡片与设置卡片的底色来自不同变量。如果目标是“浅灰窗口配白色抬升卡片”，还需同步设置卡的 `--settings-card-fill`，仅修改 `--detail-card` 不会覆盖全部页面。这是表面一致性的设计选择，应先确定目标。

[深色 SSH 编辑器预览](../.local/ui-review-2026-10-28/linux/linux-dark-host-dialog.png) 的表面较稳定，没有出现 Windows 截图中相同程度的透字；该证据来自 Chromium，不能推导为 WebKitGTK 也已通过。

本轮另保存了 [760px 窄窗口总览](../.local/ui-review-2026-10-28/linux/linux-small-long-overview.png) 和 [窄窗口接入页](../.local/ui-review-2026-10-28/linux/linux-small-integrations.png)：采集时出现“导航文字隐藏但侧栏仍宽”和“Agent 入口内容不可见”。由于截图发生于 CSS 拆分及层叠顺序调整期间，这两项列为**重构完成后待复核的现象**，不计为原 Windows 构建已确认的问题，也不直接宣称是 Linux 原生缺陷。

当时的工作区 Web 文件已保留于 [web-refactor-snapshot](../.local/ui-review-2026-10-28/web-refactor-snapshot/)，便于以后定位。按用户最新要求，本轮停止补拍，没有继续追踪或修改这一并行重构。

## 建议处理顺序

1. 先处理 V-01：下拉与对话框遮蔽底层内容，分别验收浅深色。
2. 整理 V-02 / V-03 / V-04：主窗口操作尺寸、折叠分组、SSH 表单动作的位置。
3. 细化 V-05 / V-06 / V-07：焦点效果、Agent 选择器、深色面板灰度。
4. CSS 重构完成后复核窄窗口与三端一致性；系统 DPI 和 Linux 原生表现另行实测。

以上为审阅结果与候选改进，未实施修复，也未把构建成功或浏览器预览计作三端实机验收。
