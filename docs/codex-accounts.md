# Codex 多账号管理

## 使用方式

在「设置 → Agents」启用 Codex 并选择机器，再进入「账户 → Codex 右侧的添加账户」或已有账户的「设置 → 设备」。首次添加登录会建立托管来源；建立前，同一个 Codex home 只能保留一个历史来源，已有唤醒部署需要先移除。

- 「读取当前登录并添加」验证现有登录；「授权登录」在独立目录完成授权。添加入口直接打开登录页，无需先创建账户或填写名称；授权成功后才添加实际账号，以邮箱命名，之后可修改，手动名称不会被重新授权覆盖。取消或失败不产生空账户。同一账号自动识别，不需要手动选择关联账户；授权不切换设备当前账户。本机使用浏览器，SSH 使用设备码；提供打开登录页、复制链接与复制设备码。远端凭据不会下载到本机。
- 同一账户可以连接多个机器上的档案。已验证的用户与工作区相同时自动复用账户，在已有账号的设备设置中登录时，必须使用同一身份；身份不符时拒绝连接。一个档案只属于一个账户。已归档账户不会因重新登录而自动恢复。
- 「切换」先检查凭据版本和相关进程，明确提醒将关闭所选设备上当前用户使用登录账号的 Codex 和 ChatGPT 进程及应用，包括其他 Codex home 的登录实例。已确认使用独立 API 凭据的实例及其辅助进程会保留，确认框显示保留数量。用户先保存工作，再选择「关闭并切换」，也可取消。按父子层级先向应用发送正常退出信号，再关闭辅助进程；无法确认、拒绝退出或重新启动均会阻止切换。Windows 当前要求手动关闭。切换后按需手动重新打开 Codex 或 ChatGPT；不会调用 logout。
- 切换检查会打开独立确认框，显示当前账号、目标账号、运行位置和进程列表。按钮保持可见；无法切换时显示具体原因，可手动处理后「重新检查」。检查完成不代表账号已经切换。提交成功后重新读取当前身份并刷新该位置所有账号的设备状态；状态读取失败时「重试读取」不会重复提交切换。
- 若选中的已保存凭据尚未关联到当前 Aieyes 配置，切换成功后按已验证身份自动关联或添加账户，使设备状态能显示目标账号；已有账户的归档和额度开关仍按原配置处理。
- 「重新登录」仅接受原用户和工作区，可恢复续期冲突。当前日常账号需要先关闭 Codex；授权期间凭据被外部修改会中止覆盖。
- 账户页同时显示已登录与使用中的设备计数，轻量检查不会启动 CLI。服务器前置命令按账户和设备保存。归档账户删除及强制清理见 [设置说明](agents-and-accounts-settings.md)。
- 非当前档案可以移除。引用它的唤醒任务必须先移除；操作会停用对应额度账户，保留历史。

启用后，历史由共享来源统计，不按当前登录账号归属。既有事件和导入去重标识保留；账户筛选排除共享记录，「无账户」和来源筛选可以查看这些记录。额度账户仍按档案分别展示。共享历史不能作为单账号额度或 credit 估值的采样来源。

## 存储和协调

```text
CODEX_HOME/
  auth.json                         # 日常 Codex 的当前凭据
  sessions/、archived_sessions/      # 原会话历史
  .aieyes/
    accounts/<profileId>/
      auth.json                     # 非当前账号的权威凭据
      metadata.json                 # 用户/工作区指纹与显示信息
    codex/<profileId>/
      query/                        # 只通过 stdin 注入 access token
      managed/                      # 持有独占租约时用于续期/唤醒
    state/
      home.json
      coordinator.lock
      refresh.json                  # 崩溃恢复记录
      <operationId>.json            # 登录/切换状态
```

当前档案始终优先读取根目录 auth.json；非当前档案读取 accounts 中的 auth.json，不用文件修改时间判断新旧。查询通过 `chatgptAuthTokens` 注入内存凭据，query 不复制 refresh token。日常 Codex 运行时，由它负责当前账号续期；查询仅在凭据改变后重读一次，否则保留上次额度并报告失败。非当前账号或日常 Codex 已退出时，允许在独占租约下续期。

跨应用实例、SSH 助手、定时任务共用 home 文件锁。凭据替换采用临时文件、同步和原子重命名；续期日志先于网络请求写入，即使 RPC 响应丢失也会回收已轮换的凭据。恢复时验证身份和原凭据内容哈希，有冲突保留结果并要求重新登录。Unix 管理目录为 0700，凭据/状态文件为 0600；Windows 设置用户专属 ACL。文件未加密。路径中的符号链接和上级目录跳转被拒绝。

所有历史扫描器排除 `.aieyes`，管理目录内的模型测试和唤醒日志不会混入日常会话统计。新唤醒任务必须绑定明确档案；执行期间保有同一租约，失败也回写轮换凭据。当前账号有日常 Codex 进程时跳过唤醒。

## 兼容边界

- 使用 Codex CLI 的实验性 app-server 认证接口，要求可识别的 **0.99.0 或更新版本**，并在实际调用时确认接口可用；本机研究使用了 0.161.0 协议。实验接口仍可能变化。
- 旧 CLI 的额度查询仅在允许取得托管凭据租约时退回文件认证。新账号验证、切换前校验及模型探测需要内存认证接口。
- 直接管理仅支持 `cli_auth_credentials_store = "file"`（包括默认值）。`keyring`、`auto`、默认配置 profile 会明确阻止管理；不迁移系统钥匙串。home 中强制登录方式和工作区限制会在保存/切换前检查，Codex 自身仍执行系统级策略。
- SSH 助手面向 Linux；读取 `config.toml` 需要 Python 3.11+ 的 `tomllib`。凭据全程留在授权机器，各机器分别授权。
- 后台登录最多等待 10 分钟，可取消并在返回设置页时继续查看操作状态。失去协调进程的登录会报告失败；登录暂存凭据在流程结束时清理。
- 进程归属无法确认时阻止写入，要求手动关闭。不能阻止用户在检查与原子替换之间自行启动第三方程序；写入前重复检查进程和凭据可缩小竞争窗口。
- 额度查询、登录和唤醒仍通过进程环境确认实际 `CODEX_HOME`；账号切换使用独立的整机当前用户进程范围，不依赖进程的 home。macOS 识别 Codex、ChatGPT 应用及其包内辅助程序、Codex CLI、`codex-code-mode-host` 和完整子进程树；Linux/SSH 识别同名进程及其子进程。切换关闭期间保留已确认后被重新托管的子进程身份，每次发送信号前核对 PID、启动时间和可执行文件；正常退出无需再次关闭，未知辅助程序需手动关闭。只识别明确名称、应用包路径或已确认的父子关系，不按路径中的任意关键词关闭其他程序。
- Unix 切换检查解析进程的 `--profile` / `-p`，按系统、用户和 profile 配置层合并，再应用 `--config` / `-c` 覆盖。优先读取 `$CODEX_HOME/<profile>.config.toml`，也兼容旧 `[profiles.<name>]`；两种格式同时存在且认证结论不同则要求手动处理。只有选中的自定义 provider 明确配置有效地址、独立 token 或实际存在的密钥环境变量，且不要求 OpenAI 登录认证时才保留。单独出现 profile、模型选项、base URL、未选中的 provider 或未被使用的环境变量都不构成排除依据。基础配置按当前可读值合并，避免信任目录等无关设置的自动更新导致误判；基础配置无法读取时，仅完整的更高优先级认证覆盖可用于确认。选中的 profile 文件在进程启动后改变或无法确认认证方式时阻止自动关闭。包含独立 API 子实例的共享父进程也会阻止自动关闭，避免连带终止。进程参数、地址和密钥不写入操作记录、不传给界面，也不执行凭据获取命令。配置含义依据 [OpenAI Docs 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 和 [profile 配置](https://learn.chatgpt.com/docs/config-file/config-advanced)。

## 协议入口

核心提供 `codexAuth.homes.list`、`enable`、`inspect`、`adopt`、`login.start/status/cancel`、`profiles.bind/remove`、`switch.prepare/commit`。有状态操作使用 sourceId 和 operationId；UI 不接收凭据内容。`openUrl` 只允许受支持的 HTTPS 登录域名。来源通过 `codexHomeId` 标识共享 home；账户使用 `connections[{sourceId,profileId}]` 连接多个来源，保留旧 `quotaProfileId` 作为兼容主连接；唤醒任务继续通过 `codexProfileId` 的 `homeId:profileId` 引用明确档案。

## 验证

自动化验证使用虚构凭据和模拟 app-server，不读取真实账号：

- Rust：身份/工作区区分、目录权限与锁、符号链接拒绝、查询不复制 refresh token、双向 RPC 与请求 ID 冲突、错误脱敏、陈旧切换阻断、续期响应丢失恢复、共享历史总量与额度展示。
- Python：当前权威凭据选择、续期冲突、唤醒失败回写、幂等切换、会话保留、未知进程不发送信号、遗留操作状态、重新登录恢复与错误用户拒绝。
- 浏览器：切换确认/取消、未知进程阻断、重新授权参数、打开登录 URL、状态轮询、即时保存和失败输入保留。
- 切换回归补充：ChatGPT 应用、跨 home 的 Codex、完整父子层级关闭、孤立辅助程序、自然退出、进程替换与重启；额度查询的 home 隔离；离线双账号双向切换及缓存失效；小窗口中的关闭范围提醒和确认按钮可见、重新检查、提交后身份核对、旧状态响应不覆盖新账号，以及刷新失败只重试读取。原生生命周期回归覆盖面板与窗口交接、多窗口、最小化、取消关闭和恢复菜单栏状态。
- macOS 原生 Swift 构建、Tauri Rust 检查及既有核心/UI 回归。

真实双账号授权、长时间 token 轮换、Windows ACL/进程识别以及 SSH Linux 真机联调仍需在授权环境完成，不将模拟测试视作这些验收已通过。建议在生产账号启用前，依次验证：两个账号独立额度 → 保持 Codex 运行时刷新 → 关闭并切换并恢复原会话 → 非当前账号唤醒 → 重新登录恢复。
