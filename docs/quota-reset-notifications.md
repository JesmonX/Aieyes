# 订阅额度重置提醒

在“设置 → 常规 → 通知”配置全局默认值：非预期重置提醒默认开启，自然重置提醒默认关闭。账户设置中的两个选项分别支持沿用全局、开启和关闭。设置页提供系统通知状态和测试通知按钮。

只有 Aieyes 运行时才检测，包括留在菜单栏或托盘的状态。检测沿用额度查询间隔；到达预计重置时间时会查询确认。退出、休眠和断网期间不能实时检测，恢复后以新的查询结果判断。Windows/Linux 的查询由原生后台执行，不依赖网页计时器。

## 判断规则

- 一直满额（已用 0%）不会因为接口不断更新重置时间而通知。
- 原定重置时间尚未到，但新的重置时间向后推进超过 60 秒，并且已用额度下降至少 1 个百分点，判断为非预期重置。这允许刷新时已经再次消耗一部分额度。
- 已用额度下降至少 1 个百分点并恢复至不超过 1%，也构成重置证据，不要求接口同时更新重置时间。
- 原定时间前后使用 60 秒容差；已经到达该边界时，接口确认新周期或满额恢复才发自然重置提醒。此前没有至少 1 个百分点消耗的窗口保持安静。
- 时间不变且仅部分恢复（例如已用 80% 变为 5%）不提醒。缺少可靠旧重置时间也不推断类型。若重置后消耗已追平旧值，在原定时间之前可能无法确认重置。
- 离线间隔跨过原定时间时，不推断提前重置；确认发生重置后仅适用自然重置开关。
- API 余额、credit 增加和充值不参与检测。

## 数据与交付

检测接在通过账户身份、配置版本校验的实时额度提交路径中。实时接口与用户配置的实时查询命令均可提供证据；日志回放、错误、无效读数、重复及乱序结果不推进检测基线。窗口需有稳定且唯一的 ID。身份、套餐、来源或窗口定义变化后重新建立可比较的基线。

`Settings.quotaResetNotifications` 含 `unexpected`、`natural` 布尔值。账户同名对象的各字段允许为空，表示继承。旧配置默认启用非预期提醒、禁用自然提醒。

SQLite 新增 `quota_reset_baselines` 和 `quota_reset_notifications`。基线、事件和额度快照在同一事务提交；首次观察只建基线，不回放历史。事件按账户、类型合并同一快照内的窗口。

`quotaResetNotifications.take({ since: <Unix 秒> })` 在事务中领取并消费待发送事件，过滤启动前的事件及当前已停用的提醒。通知采用至多一次投递：系统拒绝或发送失败后显示状态，不重发旧通知。应用重启保留检测基线。重复刷新和多个消费者不会重复领取；原预计时间相同的两次独立重置仍可产生两个事件。

macOS 使用 UserNotifications；Windows/Linux 使用 Tauri 通知插件。Windows/Linux 插件返回的权限状态仅代表通知接口可用，系统通知设置、勿扰模式和桌面环境仍可影响展示，应使用测试通知在安装后的应用中确认。

## 验证入口

- Rust：`cargo test --workspace --locked`；通知专项为 `cargo test -p aieyes-core quota_notifications --lib`，包含真实查询提交、事务回滚、并发消费、重启、套餐变更和原生轮询场景。
- 桌面宿主：`cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --locked --bin aieyes-desktop`。
- Web：`scripts/test-notifications-ui.cjs`、`scripts/test-agent-settings-ui.cjs`、设置导航、刷新和性能回归；已加入 `npm run test:ui`。
- macOS：`scripts/test-native.sh` 验证真实核心的设置往返与自动保存；原生截图覆盖新增通知页的浅色、深色布局。快照和模型测试实例不访问用户通知中心。

实际系统横幅仍需在各平台安装后的应用中通过“发送测试通知”验收；模拟传输测试和编译检查不等同于操作系统展示验收。
