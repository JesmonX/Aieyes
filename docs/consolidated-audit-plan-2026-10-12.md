## 发现的合并风险

1. **credit 测试传错类型。** 多份补丁将 `sampling_repair.rs` 的 credit 记录改为 `estimate_for(id, false)`；应传 `true`。采用第一阶段已通过的类型划分，保留同 ID 的 quota/credit 隔离覆盖。
2. **Web 清理误删有效状态。** 删除 `sourceError` 的补丁同时删掉 `settingsForms`、`generalSaveTimer` 和 `generalSaveVersion` 声明，它们仍被设置页和自动保存使用。只删不可达来源分支，保留这些声明；浏览器检查须实际打开并保存设置。
3. **测试仍可驱动废弃路径。** 原生旧测试直接写 `pendingAPIKeys` / `pendingHostPasswords`，并要求移除操作停留在草稿，实际编辑器早已即时提交。删除旧路径后，测试必须调用编辑器使用的保存动作，核对持久化结果、失败重试和凭据清理。来源/账户已经走专门 RPC，不为了保留旧断言新增第二套删除实现；截图确认文案仍保留。
4. **提取代码不等于修正并发。** 仅搬出 `persistConfiguration` 仍会用保存时的配置作为基线，旧编辑器可能覆盖期间更新。合并另一份补丁中的基线传递，保存后的刷新依据使用后端返回的合并结果。
5. **前置命令仅展开路径仍不完整。** Windows 原包装使用 `1>&2`，且 Antigravity 有的调用跳过前置命令、有的调用强制 `/bin/bash`。需统一构造器并验证真实目标平台行为，不能以 macOS 编译通过代替 Windows 执行。
6. **报告线索并非全部已实施。** 各报告提到的唤醒 DST/时区问题并无对应完整补丁；另有“保留当前秒数”的描述与当前 Python 已清零秒数的代码不符。实际问题是按本地墙钟递增，而非秒数；根据当前代码重新修复并建立边界用例。
7. **原始配置与加载后的配置有区别。** 真实 RPC 回归确认：完全相同的重复 Agent 配置会被加载迁移去重，有冲突的重复配置才阻止采集。共享夹具分别列出原始判断与规范化后预期，避免把合法迁移行为当作故障。

Windows PowerShell 只允许把其他流合并到成功流，不能使用 Unix 的 `1>&2` 写法。本轮通过管道把初始化的普通、警告和信息输出写到 stderr，并检查初始化的原生命令退出码；CLI 名称在初始化后解析，使修改后的 PATH 生效。[Microsoft PowerShell 重定向文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_redirection?view=powershell-5.1)。

## 已实施的整合

- **来源和会话：** Rust、Web、Swift 共用来源夹具，dashboard 的 `enabled` 也返回实际启用状态。会话缓存随有效来源集合变化，暂停 Agent 或取消本机选择后不再返回该来源的活动会话；原始历史记录仍参与统计。
- **配置事务：** 生产动作集中于 `ConfigurationActions.swift`，主机编辑器保留打开时基线，保存后采用核心返回的合并结果。新建密码引用在失败后释放，重试重新建立引用，切换密钥登录不提交隐藏密码。Web 浏览器用真实核心处理配置并模拟凭据边界；原生新增真实核心回归，分别验证并发不同字段合并和同字段冲突拒绝。
- **测试清理：** 移除未被生产写入的凭据暂存、旧草稿删除及不可达 Web 来源渲染；保留表单自动保存状态、截图确认文案和正在使用的唤醒初始来源选择。旧“重试复用失败凭据”断言改为验证引用生命周期。来源过滤的客户端 mock 不再重写核心过滤算法，真实 `accounts.targets` RPC 单独覆盖启停、机器、主机和归档状态。
- **CLI：** Antigravity 登录、身份和限额调用共用平台命令构造器；在隔离 HOME/USERPROFILE 的子进程中核验非 ASCII/空格路径、前置环境、PATH 修改、参数、stdin、初始化输出和失败。没有真实登录或推理调用。
- **唤醒：** Web/Swift 严格接受 HH:mm，支持 IANA 和带明确偏移的实际核心标签；不将模糊的 CST 缩写当成确定时区。当前偏移结果标明估算。本机/远端状态结合运行记录跳过已执行的本地日期与时刻，符合调度器既有去重规则；预览尚未部署的任务时不假设某个时刻已经执行。
- **入口：** 系统 Python 3.9 兼容方案保留，`PYTHON` 可覆盖解释器，错误参数在运行检查前拒绝。原生检查编译实际提取的配置代码；Windows/Linux 默认执行 Tauri 测试和严格 Clippy。

## 后续维护方向

- 持续以跨语言共享业务夹具约束语义；系统窗口、托盘、安装器和调度器仍按平台分别验收。
- 配置写入继续使用核心的按字段合并和专用账户/来源 RPC；减少客户端的重复事务实现。
- 凭据清理失败目前依赖既有错误处理。若需要自动清理长期孤立凭据，应另行设计以引用关系为依据的回收机制，不能仅凭文件年龄删除。
- 仅带当前 UTC 偏移的远端标签无法推断未来 DST。预览应明确是当前偏移估算，实际执行以目标机器调度状态为准；将来可在协议中增加 IANA 时区标识。
