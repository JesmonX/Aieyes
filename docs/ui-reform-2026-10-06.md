# 桌面端与 macOS UI 改革方案 · 2026-10-06

本轮基于当前工作区源码（Tauri Web 界面、Win32 原生胶囊、SwiftUI 界面）与 `.local/` 下两端浅深色截图，做一次完整的 UI 设计与交互评审，输出：两端共有问题、桌面端专属问题、macOS 专属问题，以及一份整体改革方案与逐项优化清单。

评审对象与证据：

- 桌面 Web：`apps/desktop/web/`（tokens.css、style.css、panel.css、floating.css、index.html、floating.html、app.js、floating.js、sessions.js、wakeups.js、updates.js、multiselect.js、tooltip.js、desktop.js、webview-guards.js）。
- 桌面外壳：`apps/desktop/src-tauri/`（desktop.rs 窗口/托盘/面板管理、capsule.rs Windows 原生胶囊、三份 tauri 配置）。
- macOS：`apps/macos/Sources/Aieyes/` 全部 Swift 文件与 Info.plist。
- 截图：`.local/ui-previews/`（主窗、面板、设置、编辑器、缩放）、`.local/quota-review/native/`、`.local/wakeup-review/native/`（macOS 原生浅深色、面板、设置、估值窗口）。
- 既有评审：`docs/cross-platform-ui-review-2026-10-05.md`、`docs/windows-ui-refresh.md`、`docs/native-capsule-and-ui-sync.md`、`docs/quota-value-and-macos-review.md`、`docs/windows-ui-review.md`、`docs/product-spec.md`。

本轮为源码与静态截图评审，未在真实 Windows WebView2、真实多屏、VoiceOver 下操作，涉及原生行为的部分标注了验证范围。

## 一、两端共有问题

### 1.1 信息架构与导航

**A1. 三层模型没有在两端显式对齐。**
桌面是"主窗三页导航（Agent 概览/服务器/设置）+ 面板两页 + 对话框"，macOS 是"面板两页 + 详情窗口两页 + 独立设置窗口"。层级本身合理（面板速览、详情分析、设置配置），但两端的入口分布不同：桌面把设置做成主导航第三项，macOS 设置只从 footer 齿轮、菜单栏右键和 ⌘, 进入。结果：桌面用户"设置是页面"，macOS 用户"设置是窗口"，文档与帮助文案难以共用。
建议：保留各平台惯例，但在两端统一"面板 footer = 固定/详情/设置/更多"四件套（现状已接近）与面板页签集合（Agent、服务器），把设置明确为"从任意界面可达的独立层"。

**A2. 刷新入口的集合与命名不一致。**
- 桌面主窗 header 只有"同步记录""刷新限额"（index.html:17），"同步价格"埋在设置页，"刷新服务器"只在服务器页（app.js:341）。
- 桌面面板刷新菜单有 4 项（floating.html:19-23），macOS 面板与详情 header 的刷新菜单也是同样 4 项（Views.swift:95-103）。
- macOS 限额区按钮叫"刷新"（Views.swift:273），桌面叫"刷新限额"（app.js:115）。
建议：统一为单一"刷新"入口 + 分组菜单（同步记录 / 刷新限额 / 同步价格 / 刷新服务器），两端、两载体（主窗与面板）完全同构；单项命名统一为"刷新限额"。

**A3. 筛选栏形态与可见性不一致。**
桌面主窗 4 个原生 `<select>`（app.js:238），面板 2 个下拉 + 隐藏筛选 chips（app.js:262、757-765）；macOS 详情 4 个 Picker，面板 2 个 + chips（Views.swift:123-141、206-215）。筛选状态在面板与详情之间共享（桌面经 `desktop_detail` 传递，macOS 经同一 AppModel），面板里"数据源/模型"筛选只能看到 chip，看不到来源。两端逻辑已对齐，但控件视觉（select vs Picker）、chips 样式（蓝底圆角 vs 系统胶囊）与"清除全部"入口缺失仍是差异。
建议：抽出统一"筛选栏"规范：主窗 4 项 + 有效筛选 chips；面板 2 项 + chips；chips 一律带"清除"与"清除全部"。

**A4. 空态与首次引导的位置、按钮形态不同。**
桌面引导卡在筛选栏之前（app.js:96-99、238），macOS 引导卡在会话条之后（Views.swift:121-122、192-200）；macOS 引导按钮带 SF Symbol，桌面无图标。空态时两端都仍然渲染统计卡（0 / — / —）与图表占位（桌面 `shortenEmptyUsage` 只替换图表区，app.js:279-286；macOS `hasUsageData` 只控制图表区，Views.swift:163-167）。
建议：空态时首屏只保留"引导卡 + 会话条"，隐藏统计与筛选（或折叠为一行说明），两端同一顺序：会话条 → 引导卡 → 筛选 → 限额 → 概览。

### 1.2 状态与反馈

**B1. "时间"语义不统一（重点）。**
桌面 footer 显示最近一次操作结果（"更新于 14:32""操作失败 · 上次成功 14:20"，app.js:121-133），macOS footer 显示 `dashboard.generatedAt` 数据生成时间（Views.swift:108）。两者都合理，但同一产品里"14:32"含义不同；且桌面用 24 小时制（app.js:28），macOS 用系统 12 小时制（截图"下午6:06"）。
建议：统一为"数据时间 + 状态点"：`数据 14:32 · 正常`、`同步失败 · 数据 14:20`；格式跟随系统区域设置，两端一致；状态点复用同一组颜色 token。

**B2. 错误呈现是长字符串拼接。**
桌面 `batchError` 把多个来源失败拼成一句（app.js:149-155），macOS `quotaError` 用 ` · ` 拼接（EngineClient.swift `refreshQuotas`）。长错误在横幅里换行难读，且没有逐项重试。
建议：错误列表化（每项：来源名 + 原因 + 重试），横幅限高滚动；两端共用同一结构。

**B3. "不确定"状态缺少统一语言。**
产品里有四类不确定：数据延迟（>10s，两端已一致）、会话待确认（3 分钟，两端一致）、限额待确认（pending）、计价覆盖不足。目前分别用：橙色文字、橙色圆点、橙色徽标、"!"圆圈按钮（app.js:241、Views.swift:346-351），颜色接近但形态各异。
建议：定义统一"注意"组件（橙色 1px 描边 + 图标 + 一句原因 + 一个动作），四处复用；文案统一为"待确认/数据已延迟/计价未完成"。

**B4. 忙碌反馈碎片化。**
桌面用禁用 header 按钮 + footer 文本（app.js:121-133），刷新菜单项点击后立即关闭且无进行中提示；macOS 用 ProgressView 塞进菜单 label（Views.swift:101）与各按钮"读取中…"。
建议：所有刷新动作在 footer 状态点处统一显示进行中（旋转点或文字），菜单项加勾选/禁用状态；避免把 ProgressView 塞进 18px 的菜单图标位。

### 1.3 保存与破坏性操作

**C1. 保存模型有意的平台差异需要"可见性"补偿。**
macOS 是"编辑器更新草稿、顶部保存全部"（SettingsView.swift:21-31、302），桌面是"编辑器保存即生效 + 每个卡片独立保存按钮"（app.js:451-452、556-580）。差异可保留，但目前可见性不对等：macOS 有窗口脏标记与关闭确认（AieyesApp.swift:92、169-192），桌面保存后只有一句"已保存"横幅（app.js:199），失败回滚依赖 `job()`。
建议：桌面在每个保存动作后提供轻量"已保存 · 14:32"的原地反馈（按钮旁或卡片角），失败时保留旧值并标红；macOS 保持现状。

**C2. 破坏性操作确认不对等（P1）。**
桌面移除数据源/主机有确认对话框、列出关联来源影响、提交按钮变红（app.js:437-449）；归档账户有确认（app.js:415-422）。macOS 的 List 行内 minus 直接改草稿（SettingsView.swift:103、139），归档是行内按钮（SettingsView.swift:123-129），没有确认与影响说明。草稿模型下可"放弃更改"撤回，但用户很可能不知道删除主机会连带停用关联来源。
建议：macOS 与桌面对齐，弹确认 sheet 说明"以下 N 个数据源将暂停并需重新选择服务器"；或行内展开影响提示 + 提供撤销。

**C3. 复合按钮命名需要收敛。**
macOS 有"保存并同步记录""保存并测试采样""保存配置并重算"（SettingsView.swift:114、142、182），桌面没有对应物（需分别点击）。动作重载容易让用户担心"点一下做了两件事"。
建议：保留但统一命名模式"保存并…"，并在两端都提供；或在保存成功后自动触发对应刷新（少一个按钮）。

### 1.4 视觉系统

**D1. 卡片语言两端分歧（P1 视觉）。**
桌面：中性描边 + 阴影 + 顶部高光，统计卡统一底色（style.css:110-126）。macOS：`Surface` 每张卡都有 accent→teal→purple 的彩色渐变描边（Views.swift:32），统计卡各自带蓝/青/紫/橙渐变底（Views.swift:337-360，`dashboard-dark.png` 中四张彩卡在深色下浑浊）。
建议：确立"卡片中性、颜色归数据"原则：卡片底与描边统一中性（材质差异允许：macOS 材质、Mica、不透明）；颜色只出现在图标、数值、进度条、状态点。macOS 的 Token 明细卡可保留一个低饱和区分色，其余三张统一 accent 系或中性。

**D2. 圆角、间距、阴影没有语义化 token。**
桌面有 7/10/13/17/21/26 阶梯（tokens.css:42-48），但组件各自取值：卡片 21、面板卡片 16、对话框 26、设置 tabs 13；macOS 混用 12（唤醒卡、估值结果）、16（统计卡、会话条）、18（Surface）。阴影桌面三档 + macOS 单档。
建议：定义组件级 token：卡片 16、浮层 18-20、控件 8-10、胶囊 pill；阴影两档（卡片、浮层）。两端按语义映射同一套值。

**D3. 图标与符号体系不统一（P2）。**
桌面混用内联 SVG 与字符符号：`⌄`（面板页签、quota-chevron）、`›`（disclosure）、`☰`（排序手柄）、`＋`/`−`（添加/删除）、`×`、`░ ▒ ▓`（热力图图例，style.css:158、app.js:245）。字符符号在不同字体下基线、粗细不一致，热力图图例在缺字字体下会显示豆腐块。macOS 全部用 SF Symbols，一致性好。
建议：桌面把交互性字符符号替换为内联 SVG（chevron、plus、minus、x、grip），热力图图例改为 5 个色块（与 macOS 相同）。

**D4. 统计卡信息密度与语义不一致。**
桌面主窗 4 卡：总 Token / API 等价成本 / 缓存命中率 / Token 明细（app.js:241）；面板 2 卡 + 缓存卡（app.js:265-266）；macOS 详情 4 卡同桌面，面板 2 卡 + 内联 TokenBreakdown（Views.swift:152-162）。数值字号：桌面 30px（主窗）/24px（面板）；macOS 24px。基本对齐，但 macOS 的"缓存命中率"卡与"Token 明细"卡颜色区分度强而桌面没有，且桌面面板把"缓存命中率"和三项明细合并成一张卡（好设计），macOS 紧凑面板是两张统计卡加一段内联三列明细，缓存命中率并入明细标签，没有独立缓存卡（Views.swift:160-162）。
建议：把桌面面板的"缓存 + 明细合并卡"作为标准组件推广到 macOS 面板与两端详情。

**D5. 深浅色一致性。**
桌面有完整 dark token 与 reduced-transparency / forced-colors 分支（tokens.css:70-107、style.css:387-401），覆盖好；macOS 依赖系统材质，彩色卡在深色下对比偏弱。两端的"浅色面板"截图对比：桌面面板卡片白色不透明感更强，macOS 材质通透。
建议：macOS 降低彩色底不透明度并加深色专用值；以"浅色/深色各一张对照截图"纳入回归。

### 1.5 交互细节

**E1. 会话行信息不一致。**
桌面显示会话 id 前 8 位 + 更新时间（sessions.js:19）；macOS 显示文件名后 8 字符、无时间（Views.swift:246）。建议统一为"来源 + 短 id + 相对时间"。

**E2. 限额区标题样式不一致。**
桌面用 accent 胶囊计数徽标（style.css:104、app.js:115）；macOS 用灰色数字（Views.swift:273）；排序入口桌面是"排序"文字按钮，macOS 是 ↑↓ 图标按钮（Views.swift:273）。
建议：统一"标题 + 灰色计数 + 图标按钮（排序、刷新）"。

**E3. 键盘与快捷键不对等。**
macOS：⌘, 设置、⌘Q 退出、Esc 关闭 sheet（Views.swift:115-116、302）。桌面：Esc 分层关闭、编辑器焦点循环（app.js:494-506）、设置 tabs 方向键（app.js:408-412），但没有打开设置/详情的快捷键，面板也没有。建议：桌面补 `Ctrl+,` 打开设置、`Ctrl+Shift+D` 打开详情（与 macOS 语义对应），并在提示气泡中标注。

**E4. 提示气泡两套机制。**
桌面自绘 hint（520ms 延迟，替换原生 title，tooltip.js），macOS 用系统 `.help`。平台惯例允许差异；但桌面自绘气泡在 450px 面板里容易遮住内容，且 520ms 对键盘用户偏慢。建议：键盘聚焦即时显示、指针悬停保留延迟，气泡最大宽度与面板宽度联动。

## 二、桌面端（Windows / Linux）专属问题

**F1. 刷新入口覆盖不全（P1）。** 见 A2。主窗 header 仅两项，服务器/价格刷新要切页；建议改为与面板一致的四项刷新菜单。

**F2. 全局覆盖误伤按压反馈（P1）。** `style.css:452` 的 `button:hover,button:active { transform:none; }` 同时禁用了 style.css:38 的 hover 上移与 `:active` 的 `scale(.985)`，所有按钮失去按压反馈，只剩阴影变化。建议改为只对静态卡（`.card`、`.stat`）禁用位移，按钮保留按压缩放或改为背景加深。

**F3. 面板页签像输入框（P1）。** panel.css:16 的选中态是 `--surface-strong` 白色胶囊 + 阴影 + 边框，浅色下与相邻 `<select>` 同形（见 `floating-panel-fixed-light.png` 顶部）。建议改为分段控件：选中=accent 底白字或深色底+加粗文字；页签高度降到 26-28px、等宽分布（已 `flex:1`）。

**F4. 面板宽度与信息密度。** 面板固定 450×720（desktop.rs `PANEL_WIDTH/HEIGHT`），内容区在 450 宽度下配额卡、图表、每日明细纵向堆叠，滚动长。建议面板首屏顺序固定为：会话条 → 限额（折叠摘要）→ 今日概览两卡 → 缓存合并卡；趋势图与每日明细折叠或移入详情；这已部分实现（renderAgentPanel），建议进一步把"近 N 天用量"默认折叠为一行摘要。

**F5. 原生胶囊与 Web 胶囊的视觉一致性风险。** Windows 用 GDI+ 自绘 144×44 胶囊（capsule.rs），Linux 用 WebView + floating.css 的同尺寸胶囊。字体渲染、圆角、阴影、高对比模式（forced-colors 只覆盖 Web 侧）都不同。建议：在 Windows 实机截图对照两者；给原生胶囊补高对比主题分支与 reduced-motion 等价处理（悬停/呼吸动效的静态替代）。

**F6. 标题栏与窗口控制。** Windows 自绘 titlebar 40px，控制按钮 34×26（style.css:278-287），关闭按钮 hover 变红（好）；最小化/最大化/关闭在编辑器打开时保持可用（`.shell` inert，已修复）。Linux 保留系统装饰。建议：最大化/还原图标已切换（desktop.js:36-41），补"双击标题栏最大化"行为（Tauri 默认可能已支持，需实机验证），并让标题栏在 Mica 下不叠加第二层渐变（当前 `#titlebar` 有 `linear-gradient` 背景，Mica 下会显得比正文区更亮）。

**F7. 编辑器对话框。** 660px 宽、`overflow: visible`、内部滚动（style.css:292-419），Windows 下避开标题栏（`top: var(--titlebar-h)`）。多选弹层用 top-layer popover（multiselect.js:38）避免裁剪（好）。问题：数据源编辑器的"账户"区块用 `--surface-sunken` 底（style.css:213），与表单行叠在一起层级偏弱；确认删除时提交按钮变红（app.js:447）但取消按钮未聚焦（`$('#cancel-editor').focus()` 已做，app.js:448，好）。建议：危险操作默认焦点落在"取消"（已做），并给账户区块加标题行与分隔。

**F8. 设置页导航。** 桌面设置 tabs 是文字分段控件（style.css:193-196），macOS 带图标。桌面五个 tab 在 640px 最小宽度下可能换行。建议：tabs 允许横向滚动或图标化；与 macOS 使用同一图标（数据源、服务器、价格、唤醒、通用）。

## 三、macOS 专属问题

**G1. 移除/归档缺少确认与影响说明（P1）。** SettingsView.swift:103、139 行内 minus 直接删除草稿项；归档是行内切换（SettingsView.swift:123-129）。桌面同类操作已有确认与影响列表。建议见 C2。

**G2. 菜单栏指标口径不可见（P1）。** `menuText` 用 `dashboard.summary.total`（EngineClient.swift `menuText`），而 `dashboard` 是按详情/面板筛选 `reload` 的结果。用户在详情里筛了某模型，菜单栏 Token 数字随之变化且无任何提示。建议：菜单栏固定"全部"口径（用不带筛选的请求），或设置项注明"跟随筛选"并在菜单栏 tooltip 中标注当前筛选。

**G3. 彩色卡片体系（P1 视觉）。** 见 D1。`dashboard-dark.png` 中四张统计卡（蓝/青/紫/橙）与 agy 卡的彩色描边在深色下显得浑浊；浅色下多卡同屏偏"彩虹"。建议：卡片底改中性或单一 accent 低饱和；描边统一 `separator` 色；保留进度条与数值用色。

**G4. 设置页四种列表风格并存。** 数据源/服务器用 `List(.inset)`（SettingsView.swift:95、134），价格用 ScrollView + GroupBox + List（SettingsView.swift:150-183），通用用 `Form(.grouped)`（SettingsView.swift:186-196），定时唤醒用自绘 ScrollView 卡片（WakeupsView.swift:28-37）。同一窗口不同 tab 的行高、分隔线、底色都不同。建议：统一为 grouped Form 或统一卡片列表（推荐前者，贴近系统设置）。

**G5. 唤醒页按钮层级。** 任务卡里"编辑/更新部署/停用/立即运行/状态与记录"五个同级按钮 + 右下"移除自动任务"（WakeupsView.swift:51-56），危险操作未着色（截图 `settings-wakeups.png`）。建议：主操作（更新部署）用 prominent，其余次要；"移除自动任务"用红色文字并加确认。

**G6. 估值窗口与面板的重复。** QuotaEstimateView 是独立窗口（AieyesApp.swift:136-147），桌面是模态对话框。内容结构一致（好）。问题：macOS 每个账户一个窗口（`estimateWindows`），可同时打开多个；标题随 `creditEstimateMode` 变化。建议：窗口标题固定"账户名 · 额度估值"，口径（7d/credits）在窗口内切换（已有 segmented，标题变化可去掉）。

**G7. 面板顶部无品牌文字。** 菜单栏本身提供品牌，popover 内只有 34px 图标（Views.swift:90）。桌面面板有品牌图 + 页签 + 刷新（floating.html:11-26）。一致性可接受；建议 macOS 面板在图标右侧留出页签宽度（现状已 `maxWidth: .infinity`），保持与桌面相同布局节奏。

**G8. 时间格式。** macOS 用 `.formatted(.dateTime.month(.twoDigits).day(.twoDigits).hour().minute())`（Models.swift `Format.date`），中文区域下输出"10/06 下午6:06"；桌面 `toLocaleString('zh-CN', ...)` 输出 24 小时制。建议统一（见 B1）。

**G9. 详情窗口与设置窗口的标题栏。** 详情 `titlebarAppearsTransparent`（AieyesApp.swift:99），设置是普通标题栏；两窗口风格不统一。建议：设置也透明标题栏或详情恢复普通标题栏，二选一。

**G10. 会话条展开内容。** 展开后每行显示来源 + 文件名后 8 字符（等宽 14px），无更新时间（Views.swift:244-247）；底部固定一行"本机 Codex · 日志状态"。建议补相对时间（与桌面一致），并把说明行移到 summary 的 tooltip。

**G11. 无障碍待实测。** 动画均有 reduceMotion 分支（Views.swift:76、358、546、633），ActivityIndicator 有 symbolEffect 分支（好）；但 VoiceOver 全流程、增大对比度、降低透明度尚未实机验收（README 已注明）。建议纳入本轮改革验收清单。

## 四、整体 UI 改革方案

### 4.1 设计原则（三条主线）

1. **一层信息架构，三种载体。** 面板=速览（会话、限额摘要、今日指标）、详情=分析（趋势、明细、热力图、服务器）、设置=配置。两端同一层级承载同一内容、同一命名、同一刷新与时间语义；平台只决定载体的"壳"（popover / 独立窗口 / 悬浮面板）。
2. **一套视觉语法，两种材质。** Token 层（颜色、圆角、间距、字级、状态色）两端语义同名同值；材质层允许平台差异（macOS 材质、Windows Mica、Linux 不透明）。卡片中性化，颜色只给数据（数值、进度、状态点、图标）。
3. **一致的动作结果模型。** 每个动作有 进行中 → 成功（时间）/ 失败（原因 + 重试）三态；保存模型按平台惯例（macOS 草稿、桌面即时），但脏标记、已保存提示、影响说明、破坏性确认两端对等。

### 4.2 信息架构与导航统一

- 刷新：单一入口 + 四项菜单（同步记录 / 刷新限额 / 同步价格 / 刷新服务器），主窗、面板、macOS 详情与面板四处同构；菜单项显示各自最近成功时间与进行中状态。
- 筛选：统一"筛选栏 + 有效筛选 chips + 清除全部"；主窗四项，面板两项（数据源、模型 走 chips）。
- 空态：会话条 → 引导卡 → 隐藏统计与筛选；有数据后再显示筛选。
- 设置：五个分区（数据源、服务器、价格、定时唤醒、通用）两端同名同图标；macOS 保持独立窗口，桌面保持页面但视觉上独立于 Agent/服务器导航。

### 4.3 视觉系统

- 颜色：定义状态色 token（正常=绿、注意=橙、错误=红、强调=accent），两端同一色值；卡片底与描边中性；进度条/圆环按 70%/90% 阈值着色（两端已一致，保留）。
- 圆角：卡片 16、浮层 18-20、控件 8-10、胶囊 pill；两端按语义映射。
- 阴影：两档（卡片、浮层）；去掉逐卡高光与多层阴影。
- 字体：正文 15、辅助 14、节标题 16 semibold、页标题 22（面板 20）；数值一律 tabular/monospacedDigit；桌面面板最小字号从 12px 提升到 13px。
- 图标：桌面把字符符号全部替换为内联 SVG；热力图图例改 5 色块；两端同一语义同一图形（品牌图已共享）。
- 深色：以对照截图回归；macOS 彩色卡改中性后重点核对卡片/背景对比 ≥ 3:1、正文 ≥ 4.5:1。

### 4.4 组件规范

| 组件 | 规范要点 |
| --- | --- |
| 状态点 + 时间 | 统一"数据 HH:mm · 状态"；颜色随状态；点击可触发刷新 |
| 注意组件 | 橙色描边 + 图标 + 原因 + 动作；用于计价不足、数据延迟、待确认 |
| 限额卡 | 标题 + 计划 + 更新时间；窗口条（5h/7d）剩余百分比；折叠时隐藏重置时间与余额明细（两端已基本一致，统一 macOS 的折叠行为到桌面） |
| 估值入口 | 行内按钮"7d 整周估值 · $xx USD · 待确认"（两端已一致，保留） |
| 错误列表 | 每项：来源 + 原因 + 重试；限高滚动 |
| 危险确认 | 说明影响（关联项列表）+ 默认焦点取消 + 红色确认；macOS 补齐 |
| 会话条 | 相位图标 + 摘要 + 计数 + 展开列表（来源、短 id、相对时间） |
| 刷新菜单 | 四项 + 最近成功时间；进行中禁用并显示状态 |

### 4.5 实施路线

- **阶段 0（P1 修复）**：摘要表 1-8 项。macOS 删除确认、桌面刷新入口、菜单栏口径、按压反馈、面板页签、空态、时间语义、macOS 卡片中性化。
- **阶段 1（一致性）**：筛选栏组件、错误列表、注意组件、会话行、限额标题、圆角/阴影 token、图标替换、价格页说明、快捷键。
- **阶段 2（视觉精修）**：macOS 设置列表统一、唤醒页按钮层级、面板密度与折叠策略、Mica 标题栏、原生胶囊高对比分支。
- **阶段 3（验收）**：扩展截图矩阵（空态、失败、长名称、多账户、25+ 映射、深浅色、1.5/2 DPI、450×540 低屏高、640×440 最小窗）；键盘全程走查（打开编辑器→保存/取消、面板菜单、设置 tabs）；macOS VoiceOver 与增大对比度；Windows 实机 Mica/Snap/混合 DPI/胶囊拖动。

### 4.6 验收清单（回归基线）

1. 空态、单账户、多账户、长名称、连接失败五种数据状态的两端浅深色截图。
2. 键盘：Tab 全程可达、Esc 分层关闭、焦点在重渲染后恢复（两端已有部分实现，纳入自动回归）。
3. 刷新语义：四个刷新动作都有进行中/成功时间/失败原因。
4. 保存语义：桌面即时保存有反馈、macOS 草稿有脏标记与关闭确认。
5. 破坏性操作：两端都有影响说明与取消优先焦点。
6. 对比度：正文 ≥ 4.5:1、大字与图形 ≥ 3:1（浅深色、材质背景上分别核对）。
7. 原生：Windows 实机（WebView2、Mica、Snap、DPI、胶囊）、macOS 实机（VoiceOver、多屏、低屏高）。
