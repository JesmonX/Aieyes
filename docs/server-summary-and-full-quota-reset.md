# 服务器摘要与满额窗口重置时间

按 Codex 会话 `01a11be4-89d7-7341-822c-1231cf52a1f0` 的最终计划实施，日期：2026-10-09。

## 服务器卡片

- macOS 原生主窗口、菜单栏面板和 Windows/Linux 共用桌面网页界面均保留一份常驻摘要。CPU 显示总利用率，内存显示已用／总量及占比，每张已选 GPU 单独显示编号、型号、利用率和显存已用／总量及占比。
- CPU、内存保留圆环；GPU 利用率和显存使用并排细进度条，指标区约为原高度的一半。折叠摘要显示已选文件系统的挂载点、容量及进度条。零值保留为零，缺失读数显示 `—`，零容量不计算百分比；多卡在窄窗口逐卡排列。
- 展开区移除重复的 CPU、内存、GPU 总览及其进度条，保留各核、CPU 时间分布、缓存、Swap、温度功耗、文件系统、磁盘和网络速率等明细。
- `Host.details` 新增 `uptime`，在“显示细分项”中控制连续运行时间。它独立于采集项目，使用已有 uptime 采样值，按天／小时／分钟显示。新主机默认开启，旧配置中显式的细分项列表原样保留；缺省列表沿用全部显示语义。
- `networkTotals` 控制摘要中的每张已选网卡累计收发量，`gpuMemory` 控制显存展示。设备筛选也作用于刷新失败时保留的旧采样。

## 重置时间（2026-10-09 修正）

- 各窗口按接口返回的有效未来 `resetsAt` 显示倒计时和本地日期，不再根据 `usedPercent` 或窗口长度推算重置时间。已用比例为 0 不能证明窗口尚未开始计时。
- 本机实测：2026-10-09 11:56:51（北京时间），5h 已用 0%，接口重置时间为 13:00:06。应显示“1 小时 4 分后重置 · 10/09 13:00”，而非按当前时间加 5 小时显示 16:56。
- 到达接口时间但尚未收到新重置时间时显示“确认重置中”。时间缺失或无效且已用比例为 0 时，5h / 7d 窗口分别只显示“5h” / “7d”；其余情况显示“重置时间未知”。这些状态均不推算新周期日期，收到新的有效时间后恢复倒计时。
- 网页初次渲染、30 秒定时重绘和原生时间刷新使用相同规则，不改写 `resetsAt`，也不改变查询调度、采样或存储。

修正回归覆盖本机实测快照、满额和少量使用、5h/7d 独立时间、定时重绘时日期固定、过期／未知状态，以及收到新时间后恢复。对应脚本为 `scripts/test-reset-display.cjs`、`scripts/verify-reset-format.swift` 和双界面浏览器测试 `scripts/test-quota-ui.cjs`。
