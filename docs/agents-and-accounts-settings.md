# Agent 接入、账户与设备设置

## 使用流程

首次启动或清空应用数据后，只发现已有的本机数据目录，不读取登录凭据来自动创建账户。发现目录、读取设置和刷新面板均不会添加账户；请主动添加账户、登录或导入当前登录。目录可显示「Codex · 本机」等位置名称，这不是账户名称。Codex 和 Antigravity 在确认身份后默认使用邮箱命名，手动名称保留；没有可靠邮箱时使用默认名称。已有账户及旧配置迁移保留。

1. 在「设置 → Agent 接入」选择并启用 Agent，在「机器与目录」勾选本机及 SSH 服务器。停用只暂停应用采集／额度查询，保留历史和配置；独立部署的唤醒任务仍在任务页管理。
2. 所选 Agent 的账户区域提供“添加账户”，直接添加该 Agent 的账户；Codex 的 API 连接也在同一页管理。账户即实际登录账号；同一账号在多台机器登录时只显示一条。账户行显示「已登录设备x/y」「使用中设备x/y」，组下方显示各设备当前账户。`y` 是该 Agent 选择且启用的设备数，同机多个目录只计一次。离线或尚不能识别的状态明确标记待确认，不当作未登录。
3. 进入账户设置，顶部配置额度显示与优先查询位置，下方管理各设备。添加时无需填写名称。Codex 的“添加账户”直接打开登录页，登录或读取当前账号成功后才添加账号并以邮箱命名；取消或失败不创建空账户。已添加的同一账号会自动识别，不需要选择“连接到账户”。账户名称仍可修改，手动名称不会被后续登录覆盖。无法取得邮箱的 Agent 使用默认名称。进入登录页自动读取账号状态；“登录新账号”保存凭证，“读取当前登录账号”连接机器现有登录。设备已有凭证时隐藏“登录”，无凭证时隐藏“切换账户”；正在使用的账户显示“正在使用”。两个入口均不切换当前账号；“切换到此账户”直接进入进程检查和确认。界面隐藏工作区编号，身份隔离校验保留。Claude／Antigravity 沿用已有登录；不能可靠识别的身份显示待确认。DeepSeek 使用本机 API Key。
4. 数据目录、CLI 和本机来源代理位于 Agent 各机器开关旁的“目录设置”，支持添加和移除多目录配置；Shell 在服务器高级设置。远程前置命令只在「账户 → 设备 → 前置命令」编辑，按账户 × 机器保存，同机相关目录共享，新关联目录继承；用于授权、切换、额度／余额查询和定时唤醒。远程旧代理值停用，不自动转成命令；本机代理继续生效。历史同步、设备发现、服务器监控、部署卸载不执行账户命令。
5. 账户开关和选择项即时保存，名称、查询间隔和设备前置命令失焦保存；失败保留输入并支持重试。目录和服务器编辑器保留独立保存。配置通道与远程操作分离；保存完成即结束保存提示，刷新和部署同步在后台进行。修改命令后已部署任务后台更新，保持原启停状态；失败或同步期间再次修改时显示「部署待同步」，支持重试。

同一账户可连接多台机器，额度只显示一份。优先位置失败后尝试其他可用连接。额度卡片“切换为此账号”右侧同步显示两行相同设备计数；首次展示先读取缓存，再在后台进行轻量检查，登录、切换和重新检查后更新。已登录表示机器已保存该账号的登录凭证，使用中表示机器当前选用了该账号；状态来自最近一次检查，并不保证联网授权仍有效。Codex 检查只读取身份及档案元数据，不为状态展示启动 CLI 或查询额度，凭证内容不返回界面。

面板自动模式选择每种 Agent 排序前五个可显示账户；手动模式不限数量，可滚动查看，也可为空。所有 Agent 新增账户默认加入面板，即使已有手动选择或已选满五个；用户仍可取消显示。旧账户的手动隐藏保留，原选择全部失效时不会补入其他旧账户；可随时恢复自动模式。已归档账户需要明确恢复。

登录、切换、额度与估值使用同一可用性判断：Agent 已启用、机器被选择、机器 Agent 采集开启，且目录已绑定并启用。无可用目标时显示原因和设置入口；同名目录补充路径便于区分。其他页面的设置或模型映射草稿不阻止 Codex 登录、切换和 API 操作，操作后的配置刷新会保留这些未保存草稿。

## 删除归档账户

- 删除前列出关联任务。普通删除先移除自动唤醒部署及任务配置，再移除账户；部分失败时保留账户和未完成任务，可重试。停止部署意味着停止后续自动触发，不向用户的日常 Agent 进程发送退出信号。
- 对无法连接或已弃用的设备，可在确认框勾选强制删除。此操作无法保证远端任务停止，只解除本地管理，不再自动重试。账户页保留未清理任务名称、设备和部署位置供查看。
- 账户历史、导入去重标识和机器凭证保留，不执行 logout。已删除账户默认不出现在账户筛选及当前／归档账户列表。“常规 → 刷新与历史 → 在筛选中显示已删除账户”可显示有历史记录的旧账户，名称标记为“已删除”；空账户不会返回筛选菜单。隐藏不影响总用量统计。主动重新添加是新账户，不自动恢复已删除配置。
- 任务部署与删除使用独立文件锁协调，不在 SSH 等待期间持有配置数据库事务。强制删除本地任务、账户和未清理记录以一个事务提交。

## 服务器开关

服务器设置为本机和每台 SSH 主机提供独立的「资源监控」「Agent 采集」开关。关闭 Agent 采集不影响 CPU、内存等资源监控；关闭资源监控不影响 Agent 采集。保存失败恢复已保存状态。

Agent 采集关闭的机器从 Agent 接入的「机器与目录」隐藏；目录、机器选择、账户关联和历史保留，重新开启后恢复显示。隐藏期间修改其他机器的选择不会移除原选择。机器未绑定的条目保留修复入口。

## 配置和接口

- 配置版本 11，增加只包含定位和非敏感元数据的原生连接引用；版本 10 统一远程账户设备前置命令并标记需要同步的旧部署。沿用版本 9 的独立资源监控与 Agent 采集开关，升级不会启动此前暂停的资源监控。版本 6 移除未使用的 `githubRepository`，版本 5 拆分刷新间隔；`agents[{provider,enabled,machineIds}]` 与 `connections[{sourceId,profileId?}]` 沿用版本 3。
- `Account.deviceSettings[{machineId,preCommand,preCommandResetRequired}]`：尚未授权也可保存；显式空命令不继承旧值。迁移将无冲突的旧命令复制到对应账户设备；同账户同机器的历史目录命令冲突时清空冲突命令，并提示重新设置，不自动选取其中一项。
- `settings.patch({base,settings})` 按字段和记录标识合并，设备设置按 `machineId` 合并；同字段冲突整次回滚。`deletedAccounts` / `accountAliases` 是系统管理的只读字段，修改会明确报错；未改动的旧值可用于乐观合并。macOS 独立核心通道、Tauri 独立 Engine 执行配置读写，避免排在额度／SSH 后面。
- `accounts.create({provider,name?})` 保留为旧配置的兼容入口，新界面的添加账号流程不调用它。旧的未命名 Codex 配置可用 `pendingName` 在后续登录时补齐邮箱名称，手动改名清除此标记。
- `accounts.status.get` 返回缓存；`accounts.status.refresh({accountKey,sourceId})` 检查一个目录，返回 `current`、`credential`、检查时间及错误。无法确认使用 null；失败保留上次确认结果，配置变化则丢弃旧观察结果。
- `accounts.deletion.preview({accountKey})` 返回清理清单；`accounts.delete({accountKey,force?})` 返回删除结果、失败任务或规范化配置。已成功删除的重复请求幂等。
- `accounts.cleanup.list` 返回强制删除留下的未清理位置；`accounts.deployments.sync({taskId?})` 后台更新全部或单个待同步部署，返回 `failedTasks` 和 `syncedTasks`。沿用已部署任务而不是尚未部署的草稿，保留原启停状态；失败继续保留待同步标记。
- `accounts.targets({includeUnavailable:true})` 可包含暂停、离线待确认或失去绑定的目标；`canDraft` 与 `draftReason` 表示是否能保存草稿，`available`、`canWake`、`canSwitch` 表示执行条件。默认仍只返回有效启用的目标。
- `Settings.deletedAccounts` 从有用量记录的历史标签生成，仅用于历史展示；不会重新成为实时额度账户。`historyShowDeletedAccounts` 默认 false，两端共用。关闭时清除已删除账户的当前筛选；macOS 历史查询与范围提示使用完整历史账户身份。

## 验证边界

历史来源曾被替换、日志曾被复制到其他设备时，可用 `scripts/repair-legacy-account-history.py` 审计旧账户重复。默认只读；`--apply` 先生成独立 SQLite 备份，再在单个事务内修复。备份在 Unix 使用权限 0600，在 Windows 继承所在目录的 ACL。`--source-alias 旧来源=当前来源` 必须明确指定；已经确认复制过会话的来源可额外使用 `--copied-source 旧来源=副本来源`。仅合并可由稳定导入标识重算出旧记录哈希，且会话、时间、模型、Token 和归因一致的记录；保留冻结价格、来源关联和重导入所需的历史命名空间，不合并有效账户、不按相似用量猜测去重。

2026-10-11 本机开发数据库修复了 49,072 条旧 Codex 重复记录。修复后再次审计无可合并重复，数据库完整性、外键及来源计数一致；备份中的独有历史全部保留。验证包括核心回归、真实核心浏览器历史开关及旧账户筛选、macOS 历史账户查询身份，以及维护脚本的隔离、冻结价格和幂等用例。

核心测试覆盖命令迁移与隔离、显式清空、轻量状态、陈旧缓存失效、删除保留历史／凭证、强制清理记录、任务互斥和部署待同步。原生通道测试模拟主通道阻塞 20 秒，配置请求须在 500 毫秒内返回；Tauri 测试持有主 Engine 锁验证独立配置写入。

浏览器使用真实核心及临时数据库，验证分组页面、命令保存、登录成功才添加账号、失败及取消不留空条目、删除失败重试及强制删除；OAuth、远端不可达和部分设备状态通过模拟验证。macOS 明暗主题渲染、原生测试和跨平台界面回归继续覆盖现有功能。真实 OAuth／SSH 及远端长期任务运行不作为模拟测试已完成的项目。

## 目录修改和账户查询间隔

- `sources.configure({source,baseSource?})` 与 `sources.remove({sourceId})` 走独立配置通道，在本地事务内校验和更新。编辑使用原始 `baseSource` 防止覆盖其他窗口的修改；机器与 Agent 固定。普通目录保持 ID，受管理 Codex 改址创建新来源并解除旧登录关联，不移动文件或凭证。
- 目录被唤醒任务草稿或部署引用时，操作返回具体任务名称。移除最后一个目录同时取消该机器选择；保留账户和导入历史，清理无效优先查询位置及连接。
- 账户可选 `quotaRefreshSeconds`，自定义为 30–86400 秒；缺省沿用 `Settings.refreshSeconds`。历史同步和服务器监控间隔不受单账户设置影响。
- `quotas.refresh({dueOnly:true,accountKey?})` 仅查询到期且连接可用的账户；省略 `dueOnly` 为手动立即刷新。按完整账户标识持久化尝试时间，失败同样节流；跨引擎文件锁避免重复查询，进程结束自动释放。间隔变更按上次尝试时间重算。
- 两端主界面每 5 秒检查到期账户，面板不另启轮询。存储的配置、凭证和调度元数据不含新的外部服务依赖。
- 交互强调色统一使用主题变量，余额跟随强调色；成功、警告和错误使用统一语义色，图表分类色保持独立。

Antigravity 的“登录 / 检查”会显示当前邮箱和订阅。首次识别可为默认账户补全邮箱名称，手动名称保留；再次检查发现身份不一致时会提示实际邮箱并停止将该设备额度归入原账号。订阅暂不可用时显示未知或带待更新标记的上次订阅，额度仍可刷新。此功能不创建多账户凭据档案，也不自动合并账户。

## Agent 展示与可用配置

DeepSeek 余额查询与 DeepSeek Harness 共用一个 DeepSeek 入口，账户、总览、分析、会话与面板分组统一展示。余额账户和 Harness 日志目录仍使用各自原有来源与账户键；合并不改写凭据或历史归属，同名账户 ID 不会串号。新余额账户使用 `deepseek` 的官方 API 余额连接；旧 API Key 文件及 `deepseek-harness` 账户仍可管理。Agent 总开关一次保存两个适配器，机器与目录只控制 Harness 采集。

设置项由 `docs/core-contracts.json` 的能力表统一生成到两端。未接入原生 API 表单的 Agent 隐藏 API 分组；没有可估值订阅窗口的 Agent 隐藏估值与采样；没有统一额度接口的 Agent 隐藏账户额度与重置配置。显式配置额度查询命令时保留对应自定义能力。隐藏选项不删除已有配置。

订阅表单仅在 Grok API 模式显示 Team ID、OpenCode Console 模式显示 Workspace ID；读取本机登录仅在 Grok 订阅 / OpenCode Go 模式出现。只有一种连接模式时隐藏模式选择器。图标来源及视觉大小约定见 [Agent identity icons](provider-icons.md)。


## 一键扫描已有登录与原生连接

新用户首次初始化默认启用全部具名内置 Agent，保留 `custom` 的原有默认值。既有用户的启用状态不会因升级改变；新 SSH 主机不会自动加入各 Agent 的机器选择。首次启动与普通刷新仍不读取凭据建账。

- 「机器与采集」在开启 Agent 采集的机器行提供「一键扫描账户与凭据」。只扫描全局已启用的 Agent，但不要求预先为 Agent 勾选该机器；发现可识别的账户或连接后自动选择该机器。
- 「接入与账户」的账户栏提供「扫描已启用机器」，只处理当前 Agent 已选择且机器采集开启的本机与 SSH 主机。
- 扫描已配置目录、原生环境变量目录及已知默认位置。Codex 包含当前登录和 `.aieyes/accounts` 已存档案；已有自洽的 home 标记、档案元数据和凭据身份可直接关联到原有档案管理。不会执行登录、切换、取密配置脚本或模型请求。
- 同一 Agent 的稳定身份按既有账户身份规则合并，不以邮箱或目录名称猜测。无法确认身份时保留可见的待验证凭据引用；过期、离线和部分失败不丢弃已登记的项目。原账户手动名称和归档状态保留。
- 原生 API 连接枚举配置中的已有 Provider，并非只读取 `aieyes-managed`。API Key 保留在原机器的客户端文件中，Aieyes 设置只保存文件/条目定位、端点、模型和状态。扫描不修改原生默认模型、端点或凭据。配置读取仅在核心内存中解析；远端通过 SSH 的私有核心输入传输，不进入界面、进度、日志或持久配置。
- 扫描凭据默认折叠，可展开查看单条信息或在组标题处「一键取消引用」。取消引用只移除 Aieyes 管理的定位，不删除客户端文件、账户或历史。后续检查发现身份或凭据变化会要求重新扫描，不将新身份的额度写入旧账户。
- `accounts.scan({scope:"machine",machineId})` / `accounts.scan({scope:"agent",provider})` 返回规范化设置、添加数量及逐项结果；`accounts.native.remove({connectionId})` 或 `accounts.native.remove({connectionIds:[...]})` 单条／原子批量取消引用。`Settings.nativeConnections` 是扫描操作管理的只读设置字段，普通配置更新不能伪造或替换引用。

扫描不重分配历史来源的 `accountId`，不复制原生日志。已实现的 Codex、Claude、Antigravity 和 Qoder 登录查询可通过原生引用继续读取；没有可确认身份的凭据和未接入统一额度协议的 API 连接保持待验证，不伪造有效登录或额度。Cursor GUI 私有凭据、无法解锁的系统存储、未知/动态配置会报告未识别或不可读，需在原生客户端处理。

验证使用隔离目录和临时 Aieyes 数据库，覆盖核心、原生配置样本和模拟 SSH 传输；模拟 SSH 不等于真实远端登录验收。真实 OAuth、各厂商付费账户及长周期令牌轮换需要对应凭据单独验收。

服务器面板与主窗口顶部提供“全部 / 各主机名称”切换栏，包含本机监控与 SSH 主机；与异常、已暂停状态筛选组合使用。两种窗口分别记住所选主机，删除所选主机后回到全部。

CPU、内存摘要使用标题与百分比同排的紧凑卡片，保留进度条、内存占用容量和高负载提示。


## 智能引用模型价格与估值展示

模型价格页的「智能引用」使用已同步的 OpenRouter 目录，为历史模型和自定义价格条目生成可编辑、可移除的模型映射；待计价模型也可单独引用。按 ID、显示名称、版本和日期匹配，兼容大小写、分隔符及 Claude 等模型的版本位置差异。未知供应商可按模型家族优先引用官方供应商；没有版本信息时允许 latest。未明确标注 batch 的模型不引用 batch，明确版本／日期不降级为其他版本或 latest。

引用仅用于 API 等价成本估值，不覆盖已有手动映射；补齐未计价历史，已有冻结成本沿用原值。如需更新全部历史成本，使用「保存并重算」。首次同步前可使用已有本地官方供应商价格，后续同步将目录与手动价格分别保存。

各 Agent 面板只展示已计算的 credits、5h 和 7d 估值片段；部分估值缺失时不显示占位横线，全部缺失时保留「额度估值／credits 估值」采样入口。有效零值和可用历史估值正常显示。
